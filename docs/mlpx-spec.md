# `.mlpx` 포맷 명세

`CLAUDE.md` §1.3의 상세 문서. 프로젝트 파일 포맷과 무결성 확인을 건드릴 때 읽는다.

> **정식 타입 정의는 `frontend/src/project/schema.ts`다.** 아래 JSON은 읽기 위한 예시이고,
> 어긋나면 코드를 믿어라. 크기 상한의 실제 값은 `frontend/src/limits.ts`에 있다.
> 확장자와 엔트리 경로는 `frontend/src/project/format.ts`의 상수 하나로 관리한다.

---

## 0. 이 도구가 무엇인가

> **학생이 데이터를 올려 여러 기계학습 모델을 만들어보고, 결과를 비교하고,
> 새 값으로 시험해보는 플레이그라운드.**
> 여기에 동기와 소감을 덧붙이면 결과적으로 교사가 채점에도 쓸 수 있는 정리물이 된다.

모델을 만들고 결과를 보는 것이 본체이고, 글은 부가다.
글쓰기를 강제하는 방향(체크리스트, 긴 서술 문항)은 배제한다.

```
① 데이터 업로드          CSV / 엑셀 → (V5) 이미지셋, 음성
② 데이터 타입 판정        tabular / image / audio / text   (자동)
③ 과제 유형 선택          분류 / 회귀 / 군집               (학생이 고른다)
④ 선택 가능한 모델 결정    ② ✕ ③ ✕ 실행 가능 위치
⑤ 공통 조건 설정 + 모델 여러 개 체크
⑥ [학습] 한 번           브라우저에서 될 것은 로컬, 나머지는 서버로
⑦ 비교표                 같은 분할로 학습됐으므로 공정한 비교
⑧ 예측 시험              저장된 모델 여러 개에 같은 값을 동시 입력. 항상 브라우저
⑨ 저장                   .mlpx 하나
```

**예측 결과는 파일에 기록하지 않는다.** 여기는 플레이그라운드지 보고서가 아니다.

### 0.1 선택 가능한 모델은 세 축으로 결정된다

| 축 | 어디서 오나 | 효과 |
|---|---|---|
| `dataTypes` | 업로드한 데이터 | CSV면 표 데이터용, 이미지셋이면 이미지용만 |
| `taskTypes` | **학생이 고른다** | 분류를 고르면 분류 모델만 |
| `locations` | 서버 연결 상태 | 서버가 없으면 브라우저에서 되는 것만 |

**과제 유형을 자동으로 판정하지 않는다.** 로지스틱 회귀는 수치 입력을 범주로 분류한다.
타깃 컬럼의 자료형은 학생이 무엇을 하려는지 알려주지 않는다.

`if dataType === 'image'` 같은 분기를 만들지 않는다. 등록부에 항목을 추가하면 화면이 따라온다.
**비활성화하되 숨기지 않고**, 왜 못 쓰는지 이유를 함께 보여준다.
이유의 우선순위는 데이터 타입 > 과제 유형 > 실행 위치다.

### 0.2 학습과 실행은 부담이 다르다

```
학습   브라우저가 기본, 서버는 예외      무겁다
실행   항상 브라우저 (순수 JS)          가볍다. 서버 불필요
검증   브라우저 (해시 + 재실행)          서버 불필요
```

예측은 밀리초 단위다. 서버에서 학습한 모델이라도 **실행은 브라우저에서 한다.**
그래서 파일만 있으면 서버 없이도 시연이 된다.

**서버가 있어야만 되는 일은 두지 않는다.** 공식 배포에는 서버가 없다(CLAUDE.md §1.1).

### 0.3 서버로 가는 것

```
보낸다:  데이터셋 + 공통 설정 + 알고리즘/하이퍼파라미터 + 분할 인덱스
받는다:  지표 + 모델
```

**`manifest`는 절대 보내지 않는다.** 학번·이름이 서버로 갈 경로 자체를 만들지 않는다(§7).

**분할 인덱스를 클라이언트가 계산해서 함께 보낸다.** 브라우저와 서버가 각자 분할을 계산하면
라이브러리 버전 차이로 테스트셋이 갈릴 수 있고, 그러면 같은 묶음인데 비교가 무의미해진다.

진행 표시는 **모델 단위**다. 3개를 보내면 3개가 각각 보고하고, 묶음 전체 진행률은
클라이언트가 센다.

## 1. 파일 구조

`.mlpx`는 zip 아카이브다. 확장자만 다르다.

```
10203_홍길동_붓꽃품종분류.mlpx
├── manifest.json      누가 · 언제 · 무엇을
├── settings.json      현재 편집 중인 설정
├── runs.json          학습 묶음과 결과들
├── portfolio.json     "나의 AI 모델 정리" 원본
├── portfolio.md       사람이 읽는 렌더링
├── hashes.json        엔트리별 해시와 contentHash (§7.2.1). 옛 파일에는 없다
├── model/
│   ├── preprocessor-batch-2.json
│   ├── run-1.json
│   └── run-2.json
└── dataset/
    └── data.csv       원본 그대로 (해시 재계산 때문에 손대지 않는다)
```

**없으면 열 수 없는 것은 앞의 JSON 넷과 `dataset/`의 본체다.** `portfolio.md`는 파생물이라
없어도 열리고, `model/` 아래가 없는 것은 지표만 남은 정상적인 파일이다. `hashes.json`도
필수가 아니다 — 없으면 무결성을 "확인할 수 없음"일 뿐이다(§7.2.1).

**모르는 엔트리는 저장할 때 버린다.** 상위 버전 파일은 §9에서 이미 거부되므로 여기 남는
모르는 엔트리는 미래의 파일이 아니라 `__MACOSX/` 같은 쓰레기이거나, 아무도 가리키지 않는
고아 모델이다. 실어 나를 이유가 없다.

### 1.1 `dataset/` 레이아웃

**표 데이터의 `data.csv`는 언제나 UTF-8 CSV(BOM 포함)다.** 업로드가 xlsx였든 CP949
CSV였든 가져오기 시점에 한 번 정규화된다(`open-decisions.md` "정본 데이터셋은 언제나
UTF-8 CSV다"). 정규화는 정본이 되기 **전에** 끝나므로 아래 §7의 "바이트를 가공하지
않는다"와 충돌하지 않는다 — 확정된 뒤로는 누구도 손대지 않는다.

| 데이터 타입 | 구조 |
|---|---|
| 표 | `dataset/data.csv` |
| 이미지 | `dataset/{라벨}/{파일}.jpg` |
| 음성 | `dataset/{라벨}/{파일}.wav` |
| 텍스트 | `dataset/data.csv` 또는 `dataset/{라벨}/` |

**이미지·음성의 포함 정책은 미확정이다 (V5 착수 전 결정 → `open-decisions.md`).**
원본을 그대로 담으면 IndexedDB 할당량과 파일 크기가 모두 감당이 안 된다.
유력한 방향은 썸네일과 해시·통계만 남기는 것인데, 그러면 **`datasetHash` 재계산이
불가능해져 무결성 검증도 무력해진다.**

## 3. `settings.json` — 현재 편집 상태

화면에서 만지고 있는 값이다. 학습 시점의 값은 각 묶음이 따로 들고 있다.

```jsonc
{
  "dataset": {
    "path": "dataset/data.csv",
    "originalFileName": "iris_data_final(1).csv",
    "hasHeader": true,
    "encoding": "utf-8"
  },
  "features": ["sepal_length", "sepal_width", "petal_length", "petal_width"],
  "target": "species",          // 군집화에는 없다. 과제 유형에 따라 선택 항목
  "preprocessing": { "missing": "drop", "scaling": "standard", "categoricalEncoding": "onehot" },
  "split": { "method": "holdout", "testSize": 0.2, "stratify": true, "randomState": 42 },
  "selectedAlgorithms": ["decision_tree", "svm", "logistic_regression"],
  "hyperparameters": { "decision_tree": { "max_depth": null }, "svm": { "C": 1.0 } }
}
```

하이퍼파라미터는 **기본값으로 일괄 학습**하고, 고급 설정은 접어 둔다.
학생이 안 건드려도 **실제 쓰인 값은 전부 기록**한다. 그래야 재현된다.

`randomState`는 항상 저장한다.

## 4. `runs.json` — 묶음과 결과

[학습]을 한 번 누르면 **묶음 하나**가 생기고, 체크한 모델 수만큼 `runs`가 들어간다.
같은 묶음은 같은 데이터·전처리·분할을 쓰므로 **공정한 비교가 구조적으로 보장된다.**

```jsonc
{
  "batches": [
    {
      "id": "batch-2",
      "startedAt": "2026-08-04T10:30:00Z",
      "changed": ["preprocessing.scaling"],      // 직전 묶음 대비

      "settings": {                              // 학습 시점 스냅샷
        "features": ["sepal_length", "…"],
        "target": "species",
        "preprocessing": { … },
        "split": { "method": "holdout", "testSize": 0.2, "stratify": true, "randomState": 42 },
        "trainIndices": [0, 3, 5, …],            // 환경 무관하게 같은 분할을 보장
        "testIndices": [1, 2, 4, …]
      },

      "preprocessor": {                          // 학습된 전처리 파라미터
        "format": "mlpx-preprocess-v1",
        "path": "model/preprocessor-batch-2.json"
      },

      "runs": [
        {
          "id": "run-3",
          "algorithm": "logistic_regression",
          "hyperparameters": { "C": 1.0, "max_iter": 100 },
          "computedBy": "browser",
          "trainedAt": "2026-08-04T10:30:04Z",
          "status": "done",                      // done | failed

          "metrics": { "accuracy": 0.9333, "f1Macro": 0.9310 },
          "perClass": [ … ],
          "confusionMatrix": { … },
          "featureImportance": [ … ],
          "engine": { "kind": "…", "version": "…" },  // 재실행 대조는 엔진을 넘지 않는다

          "model": {                             // 없으면 지표만 남은 것
            "format": "mlpx-linear-v1",
            "path": "model/run-3.json",
            "includesPreprocessing": false,
            "sizeBytes": 1284
          }
        }
      ]
    }
  ]
}
```

### 4.1 묶음 안에서 일부만 실패할 수 있다

SVM이 시간 초과로 죽어도 나머지 두 개의 결과는 나와야 한다.
**묶음 하나가 통째로 실패하는 일은 없다.**

```jsonc
{ "id": "run-4", "algorithm": "svm", "status": "failed",
  "failure": { "code": "JOB_TIMEOUT", "params": { "limitSeconds": 120 } } }
```

실패한 run은 지표도 모델도 없고 **사유는 반드시 있다**(스키마가 강제).
학생이 무엇이 왜 안 됐는지 알아야 다음 선택을 할 수 있다.

**"최종 모델"을 하나 고르는 개념은 두지 않는다.** 모델들을 나란히 보는 것 자체가 결과물이고,
하나를 고르라고 하면 "정확도 높은 게 정답"이라는 인상을 준다.

### 4.2 모델 보관 규칙 — 크기 예산

묶음 단위가 아니라 **모델 하나하나의 크기**로 정한다. 값은 `limits.ts`에 있다.

```
1. 최신 묶음의 모델을 먼저 담는다
2. 남은 예산으로 과거 묶음의 모델을 최신순으로 채운다
3. 개별 상한을 넘는 모델은 담지 않는다 (경고 후 지표만)
```

| 알고리즘 | 대략 크기 | 결과 |
|---|---|---|
| Logistic Regression, Naive Bayes | 1KB 안팎 | **여러 회차가 남는다** |
| Decision Tree | 수 KB | 여러 회차 |
| KNN, SVM | 수 KB (참조형) | 여러 회차 |
| Random Forest | 수백 KB ~ 수 MB | **최근 것만** |

**전처리기는 그 묶음 모델 전체의 전제다.** 예산에 못 들어가면 그 묶음의 모델은 담아 봐야
쓸 수 없으므로 통째로 뺀다. 반대로 담긴 모델이 하나도 없으면 전처리기도 짐이므로 뺀다.

그래서 학생은 **과거 버전으로도 시험할 수 있고**, 버전별로 여러 개를 골라 동시에 입력할 수 있다.
계수 몇 개짜리 모델을 굳이 버릴 이유가 없다.

**저장은 항상 성공한다.** 예산을 넘으면 모델을 빼지, 저장을 실패시키지 않는다.

### 4.3 데이터셋을 바꾸면 기존 묶음을 지운다

참조형 모델(KNN·SVM)은 `dataset/data.csv`의 **행 번호**를 가리킨다.
데이터를 새로 올리면 그 번호가 다른 것을 가리키게 되어 **조용히 틀린 예측**을 한다.
지표도 다른 데이터 기준이라 비교가 성립하지 않는다.

**데이터셋 교체 시 경고하고 기존 묶음을 전부 삭제한다.**
IndexedDB 저장은 이 교체를 **한 트랜잭션에서** 처리한다. 중간에 끊겨
"새 데이터 + 옛 모델"이 남는 상태를 만들지 않는다.

## 5. `model/` — 형식은 가변이다

포맷 계층은 모델 안을 들여다보지 않는다. **어떻게 해석할지만 적어 둔다.**

| `format` | 대상 | 전처리 | 예측에 필요한 것 |
|---|---|---|---|
| `mlpx-tree-v1` | Decision Tree, Random Forest | 밖 | 모델 + preprocessor |
| `mlpx-linear-v1` | Logistic Regression, Naive Bayes | 밖 | 모델 + preprocessor |
| `mlpx-reference-v1` | **KNN, SVM** | 밖 | 모델 + preprocessor + **`dataset/`** |
| `onnx-v1` | V5 이후 딥러닝 | **그래프에 포함** | 모델 하나 |

해석기는 알고리즘 등록부와 같은 방식으로 등록한다. `if format === 'onnx'` 분기를 만들지 않는다.

### 5.1 참조형 — 데이터를 중복 저장하지 않는다

KNN의 모델은 사실상 학습 데이터 전체다. 그런데 그 데이터는 **이미 `dataset/`에 있다.**

```jsonc
// model/run-5.json
{
  "format": "mlpx-reference-v1",
  "algorithm": "knn",
  "hyperparameters": { "n_neighbors": 5, "weights": "uniform", "metric": "minkowski", "p": 2 },
  "trainIndices": [0, 3, 5, …]        // dataset/data.csv 의 행 번호
}
```

SVM도 같다. 서포트 벡터는 학습 데이터의 부분집합이므로 행 번호 + 계수만 담는다.
덕분에 **가장 큰 모델은 KNN이 아니라 Random Forest**가 된다.

### 5.2 모르는 형식을 만나면 파일을 거부하지 않는다

알고리즘 추가는 **등록부 변경이지 포맷 변경이 아니다.** 그래서 `formatVersion`이 오르지 않고,
같은 버전 파일 안에 이 빌드가 모르는 모델이 들어 있을 수 있다.

```
☑ Random Forest       정확도 96.7%   [예측 가능]
☐ 이미지 분류 모델     정확도 91.2%   ⚠ 이 버전에서는 실행할 수 없습니다
```

`client.MODEL_FORMAT_UNSUPPORTED`. 파일 열기 실패(`PROJECT_FILE_*`)와 성격이 다르다.
**파일은 멀쩡히 열리고 그 모델로 예측만 못 한다.**

같은 이유로 `algorithm` 이름과 `model.format`은 **스키마에서 검증하지 않는다.**

## 6. 인적사항과 표절 흔적

### 6.1 원칙과 충돌하지 않는다

CLAUDE.md §1.1은 "**서버는** 인적사항을 받지 않는다"이지 "파일에 없다"가 아니다.
학번·이름은 `.mlpx` 안에만 존재하고 서버로 가는 경로를 **구조적으로 막는다.**

1. 학습·예측·검증 요청 타입에 `manifest`를 넣을 수 없게 한다
2. 전송 페이로드에 인적사항 키가 있으면 실패하는 테스트를 둔다
3. `privacy.md`에 "`.mlpx` 파일 자체는 개인정보를 담는다"를 명시한다

### 6.2 둘 다 선택 입력

| | 형식 | 필수 |
|---|---|---|
| `studentId` | 자유 문자열 (상한은 `limits.ts`) | 아니오 |
| `name` | 텍스트 (상한은 `limits.ts`) | 아니오 |

숫자 강제는 없다. `1-2-03`, `2026-0101` 같은 학번 체계가 실재한다.

**`required`로 만들지 않는 이유**: 안 쓸 학생은 `0000`을 넣는다.
강제는 입력을 만들지 품질을 만들지 않는다. 반면 교사 시연·독학·동아리에서
"student ID"를 요구받는 건 확실한 장벽이다.

**대신 파일명이 검사 수단이다.**

```
있음 →  10203_홍길동_붓꽃품종분류.mlpx
없음 →  붓꽃품종분류.mlpx
```

학생이 저장 시점에 스스로 알아채고, 교사는 수거 폴더만 봐도 찾아낸다.
`required`는 `0000`을 못 걸러내지만 이건 걸러진다.

파일명은 금지 문자와 공백만 지우고 **한글과 하이픈은 그대로 둔다.**

### 6.3 표절은 이렇게 드러난다

파일을 열 때 두 갈래를 고른다.

| 고른 것 | `projectId` | `derivedFrom` |
|---|---|---|
| 이어서 작업 (기본) | 유지 | 없음 |
| 이걸 바탕으로 새로 시작 | 새로 발급 | 기록 |

- **학생이 집에서 이어서 함** → 유지. 흔적 없음. 정상
- **교사가 나눠준 빈 파일에서 시작** → `hadResults: false`. 30명이 같은 부모를 가리키고
  그 부모는 비어 있었다 → **정상 배포로 판별**
- **B가 A의 완성본을 복사** → "이어서"면 `projectId` 중복, "새로"면 `hadResults: true`.
  zip을 풀어 `projectId`를 고치면 해시가 어긋난다 — 다만 해시는 다시 계산할 수 있으므로
  이건 방지턱이지 증거가 아니다(§7.2)

**가장 강한 표절 신호는 암호학이 아니라 파일들을 가로질러 보는 것이다.** 학생은 자기 파일은
고칠 수 있어도 나머지 29개는 못 고친다. `projectId` 중복, 같은 `derivedFrom`, `trainedAt`
간격의 일치 — 이것들은 해시도 서명도 없이 그대로 작동한다.

세 번째 단서는 `trainedAt` 타임스탬프다. 사람이 자판을 두드린 간격이 초 단위까지
두 번 일치할 확률은 없다.

**고아 모델 파일을 탐지 수단으로 쓰지 않는다.** run을 지울 거면 모델 파일도 지우면 그만이라
너무 쉽게 우회되고, 허술한 탐지기를 옆에 두면 교사가 그걸 신뢰하게 된다.

**한계**: B가 A의 데이터·설정만 받아 처음부터 자기가 돌리면 못 잡는다.
그리고 그건 표절인지 자체가 애매하다. **도구는 신호를 보여주고 판단은 교사가 한다.**

## 7. 무결성 — 위협 모델

**왜 필요한가:** `.mlpx`는 zip이고 수행평가 제출물이다. 학생이 압축을 풀어 지표를
고칠 수 있다. "재학습 없이 결과 확인"이 기본 동작이므로 변조 흔적을 볼 수 있어야 한다.

**전제부터 분명히 한다. 브라우저에서 도는 코드로는 위조를 막을 수 없다.**
학생 컴퓨터에서 실행되는 이상 학생이 통제한다. 클라이언트에 내려간 비밀은 비밀이 아니다.
그러므로 목표는 "위조 불가능"이 아니라 **"흔적을 남기고 판단은 교사에게 넘긴다"**이다.

### 7.1 세 층으로 나눈다

| 층 | 잡는 것 | 필요한 것 |
|---|---|---|
| 엔트리별 + 전체 해시 | 손으로 고친 흔적, **어디가** 바뀌었는지 | 없음 |
| 수거 시점 해시 기록 | 제출 이후의 변조 | 교사 앱의 기록 |
| **재실행 대조** | **지표가 이 데이터·설정에서 실제로 나오는지** | 없음 |

**세 층 전부 서버가 필요 없다.** 공식 배포에 서버가 없으므로(CLAUDE.md §1.1) 서버만 할 수
있는 검증은 애초에 설계하지 않는다.

**HMAC 서명은 넣지 않는다.** 자가호스팅 서버가 키를 쥐면 기술적으로는 가능하지만, 서버를
설치해서 쓰는 사람이 극소수일 것이므로 거의 아무도 못 쓰는 경로를 위해 키 관리·환경 변수·
검증 API를 유지할 이유가 없다. `SIGNING_SECRET`도 `core/signing`도 만들지 않는다.

**재실행 대조가 기본값이다.** `randomState`와 `trainIndices`를 항상 저장하는 것이 여기서
값을 한다 — 교사가 파일을 열고 다시 학습하면 지표가 재현되고, 학생이 숫자를 고쳤으면
재현되지 않는다.

앞의 두 층(해시)은 **바이트**를 검사하고 재실행은 **주장**을 검사한다. 데이터를 바꿔치기하면
해시는 통과시킬 수 있어도(다시 계산하면 되므로) 재실행은 통과하지 못한다.

### 7.2 해시 — 무엇을 위한 것인지 정직하게

엔트리별 해시와 그 전체를 덮는 해시를 파일에 남긴다. **이건 위조 방지가 아니라 방지턱이다.**
계산 코드가 오픈소스이고 비밀이 없으므로, 파일을 가진 사람은 고친 뒤 다시 계산할 수 있다.
git이 blob·tree·commit을 전부 해시하면서도 `commit -S`를 따로 두는 이유와 같다.

그럼에도 값이 있다.

- 압축을 풀어 숫자를 고치고 다시 압축하는 시도는 걸린다. 교실에서 실제로 일어나는 시도의
  대부분이 이 수준이다.
- **어디가 바뀌었는지**를 짚어준다. "`runs.json`은 바뀌었고 `dataset/`은 그대로"는 교사에게
  넘길 신호로서 쓸모가 있다.

**해시가 진짜 이빨을 갖는 순간은 신뢰할 수 있는 경로로 받은 값과 비교할 때다.**
교사가 제출물을 수거하는 시점이 그 경로다 — 그때 전체 해시를 기록해 두면 이후의 변조는
확실히 잡힌다. 학생은 자기 파일은 통제해도 교사가 적어둔 값은 통제하지 못한다.

**속도 규칙: 데이터셋은 import 시점에 한 번만 해싱한다.** 정본 바이트는 그 뒤로 바뀌지
않으므로(아래) 다시 계산할 이유가 없다. 저장할 때마다 도는 것은 JSON 넷뿐이고 수 KB다.
`ImportedTable.hash`가 그 한 번이고, `ProjectFile.datasetHash`가 그 값을 저장까지 나른다 —
**타입이 규칙을 강제한다.**

> `@noble/hashes`의 SHA-256을 쓴다. **`crypto.subtle`을 쓰지 않는다** — 보안 컨텍스트에서만
> 존재하는데 자가호스팅은 `http://192.168.x.x:8000`이 보통이라 없는 셈이다. 분기와 폴백을
> 두면 "어떤 학교에서는 해시가 없다"는 상태가 생기고 화면과 테스트가 그걸 다 알아야 한다.
> 단일 경로로 간다. → `frontend/src/hash.ts`

### 7.2.1 파일에 남는 모양 — `hashes.json`

별도 엔트리다. **자기 자신은 해싱 대상에서 빠진다.**

```jsonc
{
  "algorithm": "sha256",
  "entries": { "manifest.json": "…", "dataset/data.csv": "…", "model/run-1.json": "…" },
  "contentHash": "…"
}
```

`contentHash`는 zip 바이트가 아니라 **엔트리 해시들에서** 나온다 — 경로로 정렬해
`"경로\n해시\n"`를 이어 붙인 것의 SHA-256이다. `JSON.stringify`를 쓰지 않는 이유는 키 순서와
들여쓰기가 값을 바꾸기 때문이다.

그래서 **다시 압축해도 안 변한다.** 부수 효과로 두 제출물의 `contentHash`가 같으면 내용이
같다는 뜻이 되어 §6.3의 신호에 그대로 얹힌다.

**옛 파일에는 없으므로 선택 항목이다.** 없거나 깨져 있으면 "확인할 수 없음"이지 파일 열기
실패가 아니다. 무결성 정보 때문에 학생의 작업물이 안 열리는 일은 없어야 한다.

대조 대상은 **아는 엔트리만**이다 — 고정 엔트리, `settings.dataset.path`, `model/` 아래.
`__MACOSX/` 같은 쓰레기까지 세면 맥에서 압축을 풀었다 다시 압축한 파일이 전부 "고쳐졌음"이
되고, 그러면 아무도 이 표시를 믿지 않는다. 반대로 `model/`을 통째로 보는 이유는 끼어든
고아 모델도 신호이기 때문이다.

**수거 시점에 기록하는 해시는 `.mlpx` 바이트 자체를 해싱하면 된다.** 파일 안에 아무것도
넣을 필요가 없다.

### 7.3 UI 문구 — 과신을 만들지 마라

**"검증됨"이라고 쓰지 않는다.** 도구가 보증할 수 있는 것보다 강한 말이고, 교사가 그 말을
믿기 시작하면 허술한 탐지기가 판단을 대신하게 된다.

정직한 표현은 "고쳐진 흔적 없음", "지표가 재현됨", "재현되지 않음" 수준이다.
어휘의 단일 출처는 `frontend/src/errors.ts`의 `FILE_HASH_STATUSES` / `ENTRY_HASH_STATUSES` /
`REPRODUCTION_STATUSES`다. 파일 전체와 엔트리 하나는 축이 다르므로 열거형도 다르다 —
"이 파일이 고쳐졌는가"와 "이 엔트리가 무엇이 됐는가"는 같은 낱말로 말할 수 없다.

### 7.4 데이터셋 바이트를 가공하지 않는 이유

읽고 쓰면서 인코딩을 바꾸거나 줄바꿈을 정규화하면 해시가 달라져 대조가 전부 무너진다.
그래서 **정본으로 확정된 뒤에는 누구도 손대지 않는다.**

정규화는 정본이 되기 **전에**, 가져오기 시점에 딱 한 번 일어난다(§1.1). 그 이후가 이 규칙의
적용 범위다.

교사 화면이 파일에 적힌 `datasetHash`를 그대로 믿으면 대조는 무의미하다.
**반드시 `.mlpx` 안의 `dataset/`에서 다시 계산해 비교해야 한다.**
데이터 원본이 빠진 프로젝트 파일(이미지·음성 후보안)은 그 재계산이 불가능하다.

## 8. 포트폴리오 — "나의 AI 모델 정리"

열면 이미 채워져 있다.

```
내가 만든 것      붓꽃 품종 분류 · 분류 · 모델 3개
사용한 데이터     iris_data.csv · 150행 5열 · 결측치 0개
가장 좋았던 것    Random Forest 96.7%
가장 중요했던 것  petal_length (44%)
```

학생이 쓰는 것은 5개 빈칸: 동기 / 입출력 설명 / 모델 선택 이유 / 결과 해석 / 소감.
**자기점검 체크리스트는 넣지 않는다.**

```jsonc
// 내장 템플릿
{ "template": { "id": "default-v1" }, "answers": { "motivation": "…" } }

// 교사가 자기 문항을 쓸 때
{ "template": { "id": "custom",
    "sections": [ { "id": "q1", "title": "해결하려는 문제를 정의하시오" } ] },
  "answers": { "q1": "…" } }
```

내장은 로케일 키, 커스텀은 파일 안 문구(`title`).
i18n 원칙은 내장에만 적용되고 커스텀은 애초에 번역 대상이 아니다.

`.json`이 원본인 이유는 채점 편의가 아니라 **템플릿이 가변이기 때문**이다.
`.md`는 도구 없이 파일만 받은 사람이 읽게 하는 용도다.

**렌더링된 `.md`는 저장하는 쪽이 만들어 넘긴다.** 포맷 계층은 `t()`를 모른다 —
i18n을 끌어들이면 zip 왕복 테스트마다 번역을 부팅해야 한다. 대신 인자를 **필수로** 두어
빠뜨릴 수 없게 한다.

## 9. 버전과 마이그레이션

1. **하위 버전은 조용히 올려서 연다.**
2. **상위 버전은 거부한다** — `PROJECT_FILE_VERSION_TOO_NEW`.
   학교 PC와 집 PC의 앱 버전이 다를 때 조용히 깨지는 것보다 낫다.
3. 마이그레이션 함수는 **순수 함수**. 파일 I/O 없이 객체만 변환한다.
4. 버전을 올리는 커밋에 마이그레이션 함수와 테스트가 함께 온다. **테스트로 강제한다.**

**검사 순서가 설계의 핵심이다.**

```
압축 해제 → JSON 파싱 → formatVersion 확인 → 마이그레이션 → zod 검증
                             ↑ 여기가 zod보다 앞
```

구버전 파일은 현재 스키마를 만족하지 않는 게 당연하다. 순서를 뒤집으면 올려서 열 수 있는
파일이 전부 `PROJECT_FILE_INVALID`가 된다.

그리고 이 순서 덕분에 **검증 단계에 도달하는 파일은 항상 같은 버전이다.** 그래서 어휘를
엄격하게 막아도 호환성 문제가 생기지 않는다(§10).

마이그레이션은 문서 넷(`manifest`/`settings`/`runs`/`portfolio`)을 묶은 단위로 동작한다.
스키마 변경이 여러 파일에 동시에 걸치는 것이 정상이기 때문이다.
`formatVersion`은 체인이 올린다 — 함수마다 잊지 않기를 기대하지 않는다.

## 10. 검증 정책 — 관대함과 엄격함의 경계

**필드는 관대하게, 어휘는 엄격하게.**

| | 규칙 | 이유 |
|---|---|---|
| 모르는 **필드** | 살려서 그대로 다시 쓴다 (`looseObject`) | 지우면 소리 없이 데이터가 사라진다 |
| 모르는 **어휘** | 거부한다 (`z.enum`) | 같은 버전인데 모르는 값이면 깨진 값이다 |
| **사용자 데이터** | 어떤 문자열이든 받는다 | 한글·공백·특수문자가 오는 게 정상이다 |

`looseObject`는 **중첩된 안쪽까지 전부** 적용한다. 최상위만 열어 두면 `metrics` 안의
새 지표가 사라진다.

어휘를 엄격하게 막는 대가는 **어휘가 늘어나는 변경마다 `formatVersion`을 올려야 한다는 것**이다.
`schema.spec.ts`가 어휘 목록을 고정해 두고 있어서 잊고 지나갈 수 없다.

예외는 축이 다른 것뿐이다 — `algorithm` 이름과 `model.format`은 등록부에 속하고
등록부 변경은 포맷 변경이 아니다(§5.2).

**파일 파싱은 관대하게, 폼 입력은 엄격하게.** 같은 규칙을 두 곳에 똑같이 적용하지 않는다.
학번 길이 상한은 입력 화면에만 걸린다 — 상한을 넘는 학번이 든 남의 파일도 열려야 한다.

## 11. 브라우저 저장소

프로젝트 보관은 IndexedDB에서 이루어진다. store를 셋으로 나눈다.

| store | 담는 것 | 왜 나눴나 |
|---|---|---|
| `projects` | 문서와 요약(이름·시각·용량) | 목록 화면이 읽는 것 |
| `datasets` | 원본 바이트 | 수십 MB. 목록 뽑을 때 딸려오면 안 된다 |
| `models` | 모델·전처리기 바이트 | Random Forest가 MB 단위다 |

- 저장은 **한 트랜잭션**이다. 모델을 전부 지우고 새로 넣는다(§4.3).
- 쓰기 전에 `navigator.storage.estimate()`로 여유를 확인하고 부족하면
  `STORAGE_QUOTA_EXCEEDED`로 거부한다. `estimate()`가 없는 브라우저에서는
  `QuotaExceededError`를 같은 코드로 바꾼다.
- 언어 선택 저장 실패는 삼키지만 **프로젝트 저장 실패는 삼키지 않는다.**
  학생의 작업물이 날아가는 일이라 화면이 반드시 알아야 한다.
