# 국제화 (i18n) 규칙

> `CLAUDE.md` §3의 상세 문서. **문구를 쓰거나 로케일 파일을 건드릴 때 읽는다.**
> 여기 있는 것은 **구조**이고, 말투와 내용은 `copy.md`다.
>
> **규칙 번호는 저장소 전체가 참조한다** (`docs/i18n.md 규칙 7`처럼). 번호를 바꾸지 마라 —
> 새 규칙은 뒤에 붙인다.

지원 언어는 배열로 관리한다. **2개 언어(en/ko) 전용 분기를 만들지 마라.** ja가 추후 추가된다.

---

## 백엔드

**사람이 읽는 문장을 절대 반환하지 않는다** — 이건 규칙이 아니라 절대 원칙이다
(`CLAUDE.md` §1.4). 여기 있는 것은 그것을 지키는 방법이다.

1. 반환하는 것은 **코드와 파라미터**뿐이다.
2. 에러 응답 형식은 전 API가 동일하다 — `{"error": {"code": "...", "params": {...}}}`
   WebSocket 진행 이벤트도 같은 원칙 — `{"jobId": "...", "stage": "...", "progress": 0.42}`
3. **예외: 사용자 데이터에서 온 값**(CSV 컬럼명, 클래스 라벨)은 그대로 통과시킨다.
   UI 문자열이 아니라 데이터다. 알고리즘 id 같은 **식별자도 값**이다.
4. 코드 목록은 `backend/app/errors.py`의 `StrEnum` 하나가 **유일한 출처**다.
   명명 규칙은 `{도메인}_{문제}` 대문자 스네이크.
5. 예외는 `AppError(code, params)` 하나로 통일하고, 핸들러가 위 형식으로 직렬화한다.

## 프런트엔드

1. `frontend/src/locales/{en,ko}.json`. 키는 백엔드 코드와 1:1 대응한다.
2. 컴포넌트 안에 자연어 문자열 리터럴 금지. 전부 `t()`를 거친다. 포트폴리오 템플릿
   문구도 마찬가지다.
3. **한 문장은 한 키다. 조각을 이어 붙이지 마라.**

   ```ts
   t('train.done') + ' ' + count + ' ' + t('models')   // 금지
   t('train.done', { count })                          // 문장 하나, 값은 이름으로
   ```

   **어순은 언어마다 다르다.** 조각으로 만들면 영어에서 우연히 말이 되고 한국어에서
   어색해지고 일본어에서 무너진다. 그런데 **키 집합은 완벽히 일치하므로 검사는 통과한다.**
   화면의 버튼·라벨·개수 표시에서 슬금슬금 생기는 종류라 사람의 주의로는 못 막는다.
4. **수를 포함한 문장은 처음부터 복수 규칙(`|`)으로 쓴다.** 영어는 두 형태, 한국어·일본어는
   하나다. `{count} models`라고 쓰면 영어에서 "1 models"가 된다. `if (count === 1)` 분기를
   만들지 마라 — 그건 2개 언어 전용 분기를 문장 안으로 옮긴 것이다.
5. **사용자 데이터는 문장 한가운데 넣지 말고 끝에 괄호로 뺀다.**

   ```
   "이 파일 형식은 지원하지 않습니다. ({fileName})"
   ```

   한국어 조사가 앞 글자의 받침에 따라 갈리기 때문이다(`{column}을` / `{column}를`).
   CSV 컬럼명과 클래스 라벨은 값이 무엇일지 우리가 모른다. `{name}이(가)` 같은 회피형도
   쓰지 마라 — 읽기 나쁘고 다른 언어에 옮길 때 그대로 짐이 된다.
6. 숫자·날짜·백분율은 `Intl` API로 포맷팅한다. 직접 문자열 조립 금지.
   **로케일은 현재 선택을 넘긴다** — `'ko-KR'` 같은 값을 코드에 박으면 그 자리는 영원히
   한국어다.
7. **레이아웃이 글자 길이를 가정하지 않는다.** 같은 문장이 영어에서 30% 정도 길다.
   버튼·탭·라벨에 고정 너비를 주지 마라. 컴포넌트를 만드는 시점이 이걸 지키는 유일하게
   싼 시점이다.
8. 언어 선택은 사용자가 명시적으로 바꿀 수 있고, 선택은 IndexedDB에 저장된다. 초기값은
   `navigator.language` 기반. `<html lang>`은 현재 선택을 따라간다 — CJK 글꼴 선택과
   줄바꿈, 스크린리더가 여기에 달려 있다.
9. **낱말 중간에서 줄이 바뀌는 자리는 로케일 파일이 정한다.** 좁은 칸(레일·탭·배지)에
   긴 낱말이 들어가면 브라우저가 아무 데서나 끊는다. 한국어는 글자마다 줄바꿈 기회가
   있어 "대시보/드"가 되고, 영어는 하이픈 없이 "Portfoli/o"가 된다. **CSS로는 자리를
   정할 수 없다** — `word-break: keep-all`은 띄어쓰기가 없는 낱말을 아예 안 끊어 넘치게
   만든다. 그러므로 **문자열이 자리를 들어야 하고, 그 문자는 언어마다 다르다.**

   | 문자 체계 | 문자 | 왜 |
   |---|---|---|
   | 한국어·일본어·중국어 | `​` 폭 없는 공백 | 낱말 중간을 끊을 때 하이픈을 넣지 않는다 |
   | 라틴 문자 | `­` 소프트 하이픈 | 하이픈이 찍혀야 한 낱말로 읽힌다. 없으면 두 낱말로 보인다 |

   둘 다 **끊길 때만 보이고 평소에는 없는 문자**라, 같은 키를 넓은 화면에서 그대로 써도
   흔적이 안 남는다. 라벨마다 좁은 화면용 키를 따로 만들지 마라.

   **`hyphens: auto`에 맡기지 마라.** 하이픈 사전이 없는 브라우저에서는 조용히 아무 데서나
   끊고, 로케일 파일은 멀쩡하므로 **어떤 검사도 이걸 못 잡는다**(아래 "검사가 못 잡는
   것"과 같은 함정이다). 두 문자 모두 JSON 이스케이프로 적어 **소스에서 눈에 보이게** 둔다.

   새 언어를 넣는 사람은 위 표에서 자기 문자 체계의 문자를 고르고, 어느 낱말의 어디를
   끊을지 **직접 정한다.** 우리가 정해 줄 수 있는 것이 아니다.
10. **데이터 종류를 가리는 문구는 `{화면}.{dataType}.*`에 둔다.** 공통 자리에는 어느
    종류의 문장도 두지 않는다.

    ```
    data.tabular.dropHint     여기에 CSV나 엑셀 파일을 끌어다 놓으세요
    data.image.dropHint       사진이나 압축 파일을 여기에 끌어다 놓으세요
    data.unsupportedKind      (종류를 안 가린다 - 공통 자리에 남는다)
    ```

    **표의 문장을 이름 없이 두면 그것이 기본값이 된다.** 그러면 다음에 들어오는 종류가
    자기 문장을 안 써도 화면이 멀쩡해 보이고 — 조용히 표의 말을 한다. 실제로
    `steps.data.purpose`가 "어떤 **열**이 있는지"였고, 이미지가 그것을 물려받지 않게
    막은 것은 검사가 아니라 사람의 기억이었다.

    **그러므로 종류를 가리는 자리에는 기본값이 없다.** 어느 종류가 덮은 자리는 **모든
    종류가 덮어야 한다** — 그 자리 목록은 `router/steps.ts`가 갖고, 빠뜨리면 검사가 운다.

    **네임스페이스는 한 번에 하나씩 옮긴다** (2026-08-12에 `data.*`부터 시작했다).
    문구 감사를 하려면 비슷한 문장이 한자리에 모여 있어야 하므로, 자리를 먼저 정리하고
    문장은 그다음이다 — **옮기는 커밋에서 문장을 고치지 마라.** 섞이면 diff가 "무엇이
    옮겨졌나"를 더 이상 못 말한다.

## CI로 강제한다

**사람이 규칙을 지키길 기대하지 않는다.** 아래는 전부 실패하면 빨개진다.

- `backend/app/`의 `.py` **문자열 리터럴**에 한글이 있으면 실패.
  주석과 docstring은 예외다 — 한국어로 써도 된다. 막으려는 건 UI로 새어 나가는 문자열이지
  개발자용 설명이 아니다. (구현: `ast`로 문자열 상수만 순회한다. 주석은 애초에 AST에 없다.)
- 로케일 파일들의 키 집합이 다르면 실패. **두 파일 하드코딩이 아니다** — `locales/`의
  `*.json`을 전부 훑으므로 `ja.json`을 넣는 순간 검사 대상이 된다.
- `errors.py`의 모든 코드가 각 로케일 파일에 존재하지 않으면 실패.
- **`t()`를 `+`나 템플릿 리터럴로 잇거나, 한 텍스트 노드에 mustache를 둘 이상 두면 실패**
  (규칙 3). 사람이 못 지키는 종류라 검사로 막는다.
- **자리표시자 바로 뒤에 조사가 붙으면 실패** (규칙 5).
- 소스의 정적 `t('a.b')`가 로케일에 없으면 실패. **키를 옮기면 참조가 남기 때문이다.**
- **아무 데서도 안 불리는 키가 있으면 실패.** 위 규칙의 반대 방향이다 — 화면이 바뀌면
  참조만 사라지고 문장은 두 언어에 그대로 남는다. 그 문장은 **아무도 못 보는데 번역
  감사와 새 언어 추가에는 그대로 짐이 된다.**

  **불린다는 것은 정적 참조만이 아니다.** `t(`errors.${code}`)`처럼 이름을 조립하는
  자리도 함께 센다 — 그쪽은 앞부분(`errors.`)으로 판정한다.

  **예외는 목록에 이름과 이유를 적는다** (`tests/locales.spec.ts`의 `NOT_ON_SCREEN_YET`).
  아직 화면이 없는 기능의 어휘가 거기 산다 — 무결성 확인 화면, 백엔드 큐 단계처럼
  **문구가 먼저 정해진 것들**이다. 목록에 없는 것이 안 불리면 그대로 실패다.
- **키를 조립하는 자리에 짝이 없으면 실패.** `t(`errors.${code}`)`처럼 뒷부분이 실행 중
  값인 자리는 **정적으로 확인할 방법이 없다.** 그래서 조립해도 되는 앞부분을 목록으로
  선언하고(`tests/locales.spec.ts`의 `PAIRED_PREFIXES`), 줄마다 **그 값 집합을 로케일과
  짝지어 보는 검사**를 적어 둔다. 목록에 없는 조립이 새로 생기면 실패한다.

  **짝이 사라지는 쪽이 더 조용하다** — 실제로 `steps.`의 세 자리 중 둘을 종류 아래로
  옮기면서 짝만 지웠고 조립하는 코드는 남아, 대시보드에 `steps.data.purpose`가 그대로
  떴다 (2026-08-13). 그래서 **등록부가 답을 갖는 자리는 아예 조립을 막는다**
  (`tests/ui-rules.spec.ts`).

  **마지막 그물은 실행이다.** `src/i18n.ts`의 `missing`이 없는 키를 만나면 검사에서
  던진다 — 화면을 마운트하는 스펙이 그 순간 빨개진다.
- **종류를 가리는 단계 문구를 한 종류라도 빠뜨리면 실패** (규칙 10). 그 자리 목록은
  `router/steps.ts`의 `KIND_SPECIFIC_STEP_TEXT`이고, `locales.spec`(공통 자리에 없어야
  한다)과 `kinds.spec`(모든 종류가 자기 것을 가져야 한다)이 그 목록 하나를 함께 본다.

## 검사가 못 잡는 것

**번역이 됐는가.** 영어를 채운 `ja.json`은 모든 검사를 통과한다. 그래서 **번역할 사람이
생기기 전에 로케일 파일을 만들지 마라.** 키만 맞는 파일은 "일본어를 고르면 영어가 나오는"
상태를 조용히 만든다.

**새 에러 코드를 추가하면 같은 커밋에서** `en.json`, `ko.json`, `docs/error-codes.md`를
함께 갱신한다.
