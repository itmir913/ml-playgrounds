# 국제화 (i18n) 규칙

> `CLAUDE.md` §3이 가리키는 규칙 문서. **문구를 쓰거나 로케일 파일을 건드릴 때 읽는다.**
> 여기 있는 것은 **구조**이고, 말투와 내용은 `copy.md`다. 이유와 판례는 `docs/cases/i18n.md`.
>
> **규칙 번호는 저장소 전체가 참조한다** (`docs/i18n.md 규칙 7`처럼). 번호를 바꾸지 마라 —
> 새 규칙은 뒤에 붙인다.

지원 언어는 배열로 관리한다. **특정 언어 전용 분기를 만들지 마라.** 언어를 늘리는 자리는
`src/i18n.ts`의 `SUPPORTED_LOCALES`다.

---

## 백엔드

**사람이 읽는 문장을 절대 반환하지 않는다** (`CLAUDE.md` §1.4).

1. 반환하는 것은 **코드와 파라미터**뿐이다.
2. 에러 응답 형식은 전 API가 동일하다 — `{"error": {"code": "...", "params": {...}}}`
   WebSocket 진행 이벤트도 같은 원칙 — `{"jobId": "...", "stage": "...", "progress": 0.42}`
3. **예외: 사용자 데이터에서 온 값**(CSV 컬럼명, 클래스 라벨)과 식별자는 그대로 통과시킨다.
4. 코드 목록은 `backend/app/errors.py`의 `StrEnum` 하나가 **유일한 출처**다.
   명명 규칙은 `{도메인}_{문제}` 대문자 스네이크.
5. 예외는 `AppError(code, params)` 하나로 통일하고, 핸들러가 위 형식으로 직렬화한다.

## 프런트엔드

1. `frontend/src/locales/{언어}.json`, 언어마다 하나. 키는 백엔드 코드와 1:1 대응한다.
2. 컴포넌트 안에 자연어 문자열 리터럴 금지. 전부 `t()`를 거친다.
   **예외: 포트폴리오 양식의 문항 문구와 프리셋 이름표**는 `public/`의 언어별 파일에 있다
   (`mlpx-spec.md` §8.7). 지원 언어마다 그 파일이 있어야 하고, 없으면 CI가 운다.
3. **한 문장은 한 키다. 조각을 이어 붙이지 마라.**

   ```ts
   t('train.done') + ' ' + count + ' ' + t('models')   // 금지
   t('train.done', { count })                          // 문장 하나, 값은 이름으로
   ```
4. **수를 포함한 문장은 처음부터 복수 규칙(`|`)으로 쓴다.** `if (count === 1)` 분기를 만들지 마라.
5. **사용자 데이터는 문장 한가운데 넣지 말고 끝에 괄호로 뺀다.** `{name}이(가)` 같은 회피형도 쓰지 마라.

   ```
   "이 파일 형식은 지원하지 않습니다. ({fileName})"
   ```
6. 숫자·날짜·백분율은 `Intl` API로 포맷팅한다. 직접 문자열 조립 금지.
   **로케일은 현재 선택을 넘긴다** — `'ko-KR'` 같은 값을 코드에 박지 마라.
7. **레이아웃이 글자 길이를 가정하지 않는다.** 버튼·탭·라벨에 고정 너비를 주지 마라.
8. 언어 선택은 사용자가 바꿀 수 있고 IndexedDB에 저장된다. 초기값은 `navigator.language`.
   `<html lang>`은 현재 선택을 따라간다.
9. **낱말 중간에서 줄이 바뀌는 자리는 로케일 파일이 정한다.** CSS로 정하지 마라.

   | 문자 체계 | 문자 |
   |---|---|
   | 한국어·일본어·중국어 | `​` 폭 없는 공백 |
   | 라틴 문자 | `­` 소프트 하이픈 |

   라벨마다 좁은 화면용 키를 따로 만들지 마라. **`hyphens: auto`에 맡기지 마라.**
   두 문자 모두 JSON 이스케이프로 적는다. 새 언어는 자기 문자 체계의 문자를 고르고 자리를 직접 정한다.
10. **데이터 종류를 가리는 문구는 `{화면}.{dataType}.*`에 둔다.** 공통 자리에는 어느
    종류의 문장도 두지 않는다. **종류를 가리는 자리에는 기본값이 없다** — 어느 종류가 덮은
    자리는 모든 종류가 덮어야 한다.

    **집이 셋이고, 무엇에 대한 문장인가로 고른다.**

    | 무엇에 대한 문장인가 | 어디에 두나 | 누가 읽나 |
    |---|---|---|
    | 그 화면의 본문 | `{화면}.{dataType}.*` | 그 화면 하나 |
    | 그 **단계**의 문구 | `steps.{step}.{dataType}.*` | 대시보드 줄 · 레일의 잠금 사유 · 화면 머리 · 그 화면의 빈 상태 |
    | 그 **프로젝트**를 설명하는 낱말 | `meta.{dataType}.*` | 프로젝트 요약 · 화면 머리의 문맥 배지 · 실험 변경 요약 |

    - 가르는 기준은 **그 화면에 실제로 뜨는가**다. "읽는 자리가 하나인가"로 재지 마라.
    - **단계 문구의 자리 넷** — `purpose`·`locked`·`emptyReason`·`emptyNext`.
    - **갈리는 자리의 목록은 `KIND_SPECIFIC_STEP_TEXT` 하나다.** 새 자리는 목록과 로케일을 함께 늘린다.
    - **갈리는 자리만 종류 칸을 갖는다.**
    - **네임스페이스는 한 번에 하나씩 옮기고, 옮기는 커밋에서 문장을 고치지 마라.**

## CI로 강제한다

**사람이 규칙을 지키길 기대하지 않는다.** 아래는 전부 실패하면 빨개진다.

- `backend/app/`의 `.py` **문자열 리터럴**에 한글이 있으면 실패. 주석과 docstring은 예외다.
  FastAPI 자동 문서는 꺼 두고 `tests/test_no_schema_endpoints.py`가 본다.
- 로케일 파일들의 키 집합이 다르면 실패. `locales/`의 `*.json`을 전부 훑는다.
- `errors.py`의 모든 코드가 각 로케일 파일에 존재하지 않으면 실패.
- **`t()`를 `+`나 템플릿 리터럴로 잇거나, 한 텍스트 노드에 mustache를 둘 이상 두면 실패** (규칙 3).
- **자리표시자 바로 뒤에 조사가 붙으면 실패** (규칙 5).
- 소스의 정적 `t('a.b')`가 로케일에 없으면 실패.
- **아무 데서도 안 불리는 키가 있으면 실패.** 조립하는 자리는 앞부분으로 센다. 예외는
  `tests/locales.spec.ts`의 `NOT_ON_SCREEN_YET`에 이름과 이유를 적는다.
- **키를 조립하는 자리에 짝이 없으면 실패** (`PAIRED_PREFIXES`). 등록부가 답을 갖는 자리는
  조립을 막는다(`tests/ui-rules.spec.ts`). 마지막 그물은 `src/i18n.ts`의 `missing`이다.
- **한 언어에서 같은 문장이 다른 언어에서 갈리면 실패.** 정당한 갈림은 `ALLOWED`에 이유와 함께 적는다.
- **한국어 값에 한글이 없거나 영어 값에 한글이 있으면 실패.** 예외는 `NOT_TRANSLATED`.
- **종류를 가리는 단계 문구를 한 종류라도 빠뜨리면 실패** (규칙 10). `locales.spec`과
  `kinds.spec`이 `KIND_SPECIFIC_STEP_TEXT`를 함께 본다.
- **문구가 부르는 버튼 이름이 실재해야 한다.** 대괄호로 인용한 것은 로케일의 실제 값 중 하나여야 한다.

## 검사가 못 잡는 것

- **공통 자리의 문장이 어느 종류에서 거짓인가**는 사람이 본다. 볼 곳은
  `KIND_SPECIFIC_STEP_TEXT`와 `DataKind.stepText`, 규칙 10의 표다.
- **같은 키가 두 언어에서 다른 것을 말하는지**는 사람이 읽는다.
- **새 언어는 그대로 뚫린다.** 그래서 **번역할 사람이 생기기 전에 로케일 파일을 만들지 마라.**
  번역 중인 파일은 **옮긴 네임스페이스만** 담는다 — 다른 언어로 빈자리를 채우지 마라.
  `SUPPORTED_LOCALES`에는 키가 다 찬 뒤에 올린다.

**새 에러 코드를 추가하면 같은 커밋에서** 모든 로케일 파일과 `docs/error-codes.md`를
함께 갱신한다.
