# `.mlpx` — 버전·검증·브라우저 저장소 (§9~§11)

> `mlpx-spec.md`에서 갈라져 나온 절이다. **절 번호는 안 바뀌었다.** 전체 차례는 허브(`../mlpx-spec.md`)에 있다.
> **규칙만 적는다.** 이유와 경위는 같은 절 번호로 `docs/cases/mlpx-spec.md`에 있다.

## 9. 버전과 마이그레이션

배포 뒤로는 아래가 예외 없이 적용된다. 버전을 올리는 판단 기준은 `docs/workflow.md` §4다.

1. **하위 버전은 조용히 올려서 연다.**
2. **상위 버전은 거부한다** — `PROJECT_FILE_VERSION_TOO_NEW`.
3. 마이그레이션 함수는 **순수 함수**. 파일 I/O 없이 객체만 변환한다.
4. 버전을 올리는 커밋에 마이그레이션 함수와 테스트가 함께 온다. **테스트로 강제한다.**

**검사 순서가 설계의 핵심이다.**

```
압축 해제 → manifest 파싱 → formatVersion 확인 → 나머지 엔트리 요구 →
마이그레이션 → zod 검증
                  ↑ 여기가 zod보다 앞이고, 엔트리 존재 검사보다도 앞이다
```

- **`formatVersion` 확인은 zod 검증과 엔트리 존재 검사보다 앞이다.**
- 마이그레이션은 문서 넷(`manifest`/`settings`/`runs`/`portfolio`)을 묶은 단위로 동작한다.
  `formatVersion`은 체인이 올린다.
- **zip 엔트리의 구성은 v1에서 동결이다.** 엔트리 구성을 바꾸려면 마이그레이션 체계를 다시 설계한다.

### 9.1 v1 → v2 — 백본 id 개정 (2026-08-19)

근거는 `open-decisions.md` **"백본 입력 범위가 그래프의 계약과 어긋났다"**.

| 자리 | v1 | v2 |
|---|---|---|
| `settings.data.backboneId` | `mobilenet-v2` | `mobilenet-v2-r2` |
| `runs.experiments[].settings.data.backboneId` | `mobilenet-v2` | `mobilenet-v2-r2` |

- **옛 id일 때만 바꾼다.** 모르는 id는 그대로 둔다.
- **임베딩은 마이그레이션이 안 만진다** (§1.3 규칙 2가 처리한다).
- 어휘는 안 바뀌지만 **좌표계가 바뀌었으므로 버전은 오른다.**
- 이미 나간 파일의 지표는 그대로 남는다.

### 9.2 구조 정본 — 버전마다 박제한다 (2026-09-18)

**구조를 버전마다 파일로 박제한다.** 정본은 `projectDocumentSchema`를 JSON Schema로 뜬 것이다.

| 파일 | 무엇인가 |
|---|---|
| `frontend/tests/fixtures/schema/vN.json` | **지금 vN이 받아들이는 구조.** 호환 변경이면 이것만 갱신한다 |
| `frontend/tests/fixtures/schema/vN.released.json` | **vN이 처음 배포된 날의 구조. 역사다 — 고치지 마라** |

- **v1 정본은 없다.** 정본은 v2부터 쌓인다.

#### 읽기 호환을 깨는 변경 넷

1. **필수 경로가 늘었다.**
2. **속성이 사라졌다.**
3. **타입이 바뀌었다** — `type`, `enum`/`const`, 유니온의 가지 수. 어휘에서 값이 빠지는 것도 여기다.
4. **제약이 좁아졌다** — 하한 상승, 상한 하락(없다가 생긴 것 포함), `pattern` 변경·신설.

**깨지 않는 것**: 선택 속성 추가, 필수 → 선택, 제약 완화·제거, 설명 변경.

- 상한이 정본에 새는 것은 의도다(좁히면 울어야 맞다).

#### 갱신 절차

| 무엇을 바꿨나 | 무엇이 따라온다 |
|---|---|
| 호환 변경 | `vN.json`만 다시 뜬다 |
| **깨는 변경** | `FORMAT_VERSION` 상승 · `vN+1.json` · `vN+1.released.json`(둘은 같은 내용) · 마이그레이션 함수 · 어휘 지문 한 줄 · `versions.spec.ts`의 기대값 |

- **`*.released.json`은 어느 쪽에서도 안 고친다.**
- 검사는 `frontend/tests/schema-structure.spec.ts`이고, **`src/`에는 아무것도 안 더한다.**
- 못 보는 것: `superRefine`/`refine`(→ `schema.spec.ts`), `.default()`의 값, 등록부 축.

### 9.3 v2 → v3 — 설정이 적용되지 않는 값을 든다 (2026-09-23)

- 살아 있는 설정은 **학생이 켠 것을 그대로 든다**(`open-decisions.md` 55, §3). 옛 판이 그 뜻을 모르므로 버전을 올린다.
- **마이그레이션은 번호만 올리는 항등 함수다.** 어휘도 구조도 안 바뀐다.
- 옛 판은 `PROJECT_FILE_VERSION_TOO_NEW`로 거부한다.

### 9.4 v3 → v4 — 업로드 인코딩 어휘에 `cp932`·`cp1252`가 더해진다 (2026-10-06)

근거는 `open-decisions.md` **"인코딩 판정과 지원 목록"**.

- 데이터셋 참조의 `sourceEncoding`(§3)이 받는 값에 `cp932`(일본어 윈도의 Shift_JIS)와
  `cp1252`(영어 윈도의 코드 페이지)가 더해진다.
- **`cp1252`는 0.33.0에서 어휘에만 있었고, 0.33.1부터 영어 화면의 마지막 대체로 판정이 낸다**
  (`open-decisions.md` 97). 형식 버전을 두 번 올리지 않으려고 같은 버전에 함께 들였다 — 판정이 그것을
  내기 시작해도 형식은 v4 그대로다.
- **어휘가 늘었으므로 버전은 오른다**(§10). 옛 판이 새 값을 만나면 깨진 값으로 읽기 때문이다.
- **마이그레이션은 번호만 올리는 항등 함수다.** v3 파일에는 새 값이 없고, 있던 값의 뜻도 안 바뀐다.
- 구조 정본의 차이는 `enum`에 값이 는 것뿐이다 — 읽기 호환을 깨지 않는 변경이다(§9.2).
- 옛 판은 `PROJECT_FILE_VERSION_TOO_NEW`로 거부한다.

## 10. 검증 정책 — 관대함과 엄격함의 경계

**필드는 관대하게, 어휘는 엄격하게.**

| | 규칙 | 이유 |
|---|---|---|
| 모르는 **필드** | 살려서 그대로 다시 쓴다 (`looseObject`) | 지우면 소리 없이 데이터가 사라진다 |
| 모르는 **어휘** | 거부한다 (`z.enum`) | 같은 버전인데 모르는 값이면 깨진 값이다 |
| **사용자 데이터** | 어떤 문자열이든 받는다 | 한글·공백·특수문자가 오는 게 정상이다 |

- `looseObject`는 **중첩된 안쪽까지 전부** 적용한다.
- **어휘가 늘어나는 변경마다 `formatVersion`을 올린다.** `schema.spec.ts`가 어휘 목록을 고정한다.
- 예외는 축이 다른 것뿐이다 — `algorithm` 이름과 `model.format`은 등록부에 속한다(§5.2).
- **파일 파싱은 관대하게, 폼 입력은 엄격하게.** 학번 길이 상한은 입력 화면에만 걸린다.
- **다시 압축한 파일도 연다.** 엔트리 **이름**의 `\`는 `/`로 읽고, 이름은 NFC로 모으되
  `hashes.json`에 같은 글자로 적힌 이름이 있으면 그 표기를 따른다. 옛 인코딩으로 이름을 되살리는
  것은 `hashes.json`에 적힌 경로(한 겹 감싼 파일은 그 한 겹 아래)와 **이미 같은 이름에는 하지
  않는다** — 같다는 것이 증거이고, 글자가 전부 0xFF 이하인 범주(`Größe`)를 다시 읽으면 다른 이름이
  된다. 루트에 `manifest.json`이 없고 잡음(§7.2.1)을 뺀 엔트리가 전부 한 폴더 아래이며 그 폴더에 `manifest.json`이 있으면 그 한 겹을
  벗긴다. 포맷 변경이 아니라 읽기 관용이다 — **문서가 적은 경로의 검증은 느슨해지지 않는다.**
- **관용은 푸는 자리 밖으로 새는 이름에는 미치지 않는다.** 그런 엔트리는 대조 뒤에 버리고 대조에는
  남긴다(§7.2.1). 파일은 열리고, 문서가 가리키던 첨부는 떼어진다. 범주 이름도 같다 — 폴더 조각이나
  `settings.data.categories`에서 폴더 한 겹으로 못 서는 이름(빈 이름·`.`·`..`·구분자)은 범주로 세우지
  않는다. 범주 이름 규칙 전체를 대지는 않는다(옛 파일의 범주를 지킨다).

## 11. 브라우저 저장소

프로젝트 보관은 IndexedDB에서 이루어진다. store를 넷으로 나눈다.

| store | 담는 것 | 왜 나눴나 |
|---|---|---|
| `projects` | 문서와 요약(이름·시각·용량) | 목록 화면이 읽는 것 |
| `datasets` | 원본 바이트 | 수십 MB. 목록 뽑을 때 딸려오면 안 된다 |
| `models` | 모델·전처리기 바이트 | Random Forest가 MB 단위다 |
| `preferences` | 언어·상한 해제 같은 앱 설정 | 프로젝트가 아니라 이 브라우저의 것이다 |

- 저장은 **한 트랜잭션**이다. 모델을 전부 지우고 새로 넣는다(§4.3).
- **쓰기 전에 여유를 재지 않는다.** 쓰기가 던지는 `QuotaExceededError`만 `STORAGE_QUOTA_EXCEEDED`로 바꾼다
  (`open-decisions.md` 71). 여유를 미리 묻는 자리는 사진을 굽기 전 하나다.
- `projects` 레코드는 파일에 없는 이 기기의 사정을 둘 든다 — 마지막으로 내보낸 시각(`exportedAt`)과 파일로 안
  나간 편집이 있는가(`unexportedEdits`). 편집 저장은 참이고, 내보낸 판이 레코드에 그대로 있을 때의 내보내기와
  `.mlpx` 가져오기는 거짓이다. 이 칸이 없는 옛 레코드는 상태 표시줄의 판정을 쓴다 (`open-decisions.md` 73).
- 언어 선택 저장 실패는 삼키지만 **프로젝트 저장 실패는 삼키지 않는다.**
- **우리 쪽 용량 상한은 없다.** 프로젝트 수 상한도 없다 (`open-decisions.md` #7).
- **`navigator.storage.persist()`를 데이터셋이 처음 들어간 저장에서 한 번 부른다.**
  **성공하든 실패하든 저장은 그대로 진행된다.**
