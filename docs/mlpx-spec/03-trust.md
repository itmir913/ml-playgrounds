# `.mlpx` — 인적사항과 무결성 (§6~§7)

> `mlpx-spec.md`에서 갈라져 나온 절이다. **절 번호는 안 바뀌었다.** 전체 차례는 허브(`../mlpx-spec.md`)에 있다.
> **규칙만 적는다.** 이유와 경위는 같은 절 번호로 `docs/cases/mlpx-spec.md`에 있다.

## 6. 인적사항과 표절 흔적

### 6.1 원칙과 충돌하지 않는다

학번·이름은 `.mlpx` 안에만 존재하고 서버로 가는 경로를 **구조적으로 막는다.**

1. 학습·예측·검증 요청 타입에 `manifest`를 넣을 수 없게 한다
2. 전송 페이로드에 인적사항 키가 있으면 실패하는 테스트를 둔다
3. `privacy.md`에 "`.mlpx` 파일 자체는 개인정보를 담는다"를 명시한다

### 6.2 둘 다 선택 입력

| | 형식 | 필수 |
|---|---|---|
| `studentId` | 자유 문자열 (상한은 `limits.ts`) | 아니오 |
| `name` | 텍스트 (상한은 `limits.ts`) | 아니오 |

- 숫자를 강제하지 않고, **`required`로 만들지 않는다.** 대신 **파일명이 검사 수단이다.**

```
있음 →  10203_홍길동_붓꽃품종분류.mlpx
없음 →  붓꽃품종분류.mlpx
```

- 파일명은 금지 문자와 공백만 지우고 **한글과 하이픈은 그대로 둔다.**

### 6.3 표절은 이렇게 드러난다

- **파일을 열면 `projectId`는 언제나 그대로다.** 새 id를 발급하는 선택지를 두지 않는다.
- **열 때 이 컴퓨터에 같은 `projectId`의 판이 있고 그쪽이 더 새거나 파일로 안 나간 편집이 있으면 묻는다** —
  [이 컴퓨터의 것 열기] / [파일로 교체] 둘뿐이고, 어느 쪽이든 `projectId`는 그대로다. 로컬 레코드를 못 읽으면
  묻지 않고 파일로 교체한다 (`open-decisions.md` 75).
- **프로젝트 파일 자체를 여러 사람에게 나눠 주는 경로를 만들지 않는다.**
- 신호는 파일들을 가로질러 본다 — `projectId` 중복, `trainedAt` 간격의 일치.
- **고아 모델 파일을 탐지 수단으로 쓰지 않는다.**
- **도구는 신호를 보여주고 판단은 교사가 한다.**

## 7. 무결성 — 위협 모델

**브라우저에서 도는 코드로는 위조를 막을 수 없다.** 목표는 **"흔적을 남기고 판단은 교사에게 넘긴다"**이다.

### 7.1 세 층으로 나눈다

| 층 | 잡는 것 | 필요한 것 |
|---|---|---|
| 엔트리별 + 전체 해시 | 손으로 고친 흔적, **어디가** 바뀌었는지 | 없음 |
| 수거 시점 해시 기록 | 제출 이후의 변조 | 교사 앱의 기록 |
| **재실행 대조** | **지표가 이 데이터·설정에서 실제로 나오는지** | 없음 |

- **세 층 전부 서버가 필요 없다.**
- **HMAC 서명은 넣지 않는다.** `SIGNING_SECRET`도 `core/signing`도 만들지 않는다.
- **재실행 대조가 기본값이다.**

### 7.2 해시 — 무엇을 위한 것인지 정직하게

- 엔트리별 해시와 전체를 덮는 해시를 파일에 남긴다. **위조 방지가 아니라 방지턱이다.**
- 해시가 이빨을 갖는 것은 **수거 시점에 기록한 값과 비교할 때다.**
- **데이터셋은 import 시점에 한 번만 해싱한다.** `ImportedTable.hash` → `ProjectFile.dataset.hash`로
  나르고, 타입이 강제한다.
- `@noble/hashes`의 SHA-256을 쓴다. **`crypto.subtle`을 쓰지 않는다** — 단일 경로다 (`frontend/src/hash.ts`).

### 7.2.1 파일에 남는 모양 — `hashes.json`

별도 엔트리다. **자기 자신은 해싱 대상에서 빠진다.**

```jsonc
{
  "algorithm": "sha256",
  "entries": { "manifest.json": "…", "dataset/data.csv": "…", "model/run-1.json": "…" },
  "contentHash": "…"
}
```

- `contentHash`는 **엔트리 해시들에서** 나온다 — 경로로 정렬해 `"경로\n해시\n"`를 이어 붙인 것의
  SHA-256이다. `JSON.stringify`를 쓰지 않는다. 다시 압축해도 안 변한다.
- **옛 파일에는 없으므로 선택 항목이다.** 없거나 깨져 있으면 "확인할 수 없음"이지 열기 실패가 아니다.
- 대조 대상은 **아는 엔트리만**이다 — 고정 엔트리, `settings.data`가 가리키는 정본, `model/` 아래.
  이미지는 정본 한 장 한 장이 대상이다.
- **압축 도구가 넣는 잡음은 신호가 아니다.** 내용 없이 `/`로 끝나는 디렉터리 엔트리, `__MACOSX/` 아래,
  이름이 `.DS_Store`·`Thumbs.db`·`desktop.ini`이거나 `._`로 시작하는 엔트리는 대조와 사진 수집 **전에**
  버린다. 탐색기·bsdtar·`Compress-Archive`로 다시 압축한 멀쩡한 파일이 "고쳐졌음"이 되면 안 된다.
- **푸는 자리 밖으로 새는 엔트리 이름(`..` 조각·절대 경로)은 대조 뒤에 버린다.** 대조에는 남아
  신호가 되고(`hashes.json`에 없으면 "더해짐"), 사진·첨부·임베딩으로는 들이지 않는다 — 잡음과 달리
  대조 **전에** 버리면 주입한 엔트리가 흔적 없이 사라진다. 판정은 `frontend/src/project/entry-path.ts`
  하나다.

**해시가 둘인데 쓰임이 다르다. 섞지 마라.**

| | 무엇인가 | 무엇에 쓰나 |
|---|---|---|
| `contentHash` | 파일 **안**의 값. 엔트리 해시들에서 계산 | 어디가 바뀌었나 · 표절 대조(§6.3) |
| 수거 해시 | 파일 **밖**의 기록. `.mlpx` 바이트 자체 | 제출 이후의 변조 |

- **수거 시점에 기록하는 해시는 `.mlpx` 바이트 자체를 해싱한 값이다.** 교사가 우리 도구 없이
  계산할 수 있어야 한다. 안내는 윈도우 명령으로 적는다.

```
certutil -hashfile 10203_홍길동_붓꽃품종분류.mlpx SHA256
Get-FileHash 10203_홍길동_붓꽃품종분류.mlpx -Algorithm SHA256   # PowerShell
```

### 7.3 UI 문구 — 과신을 만들지 마라

- **"검증됨"이라고 쓰지 않는다.** "고쳐진 흔적 없음", "지표가 재현됨", "재현되지 않음" 수준이다.
- 어휘의 단일 출처는 `frontend/src/errors.ts`의 `FILE_HASH_STATUSES` / `ENTRY_HASH_STATUSES` /
  `REPRODUCTION_STATUSES`다. 파일 전체와 엔트리 하나는 열거형이 다르다.

### 7.4 데이터셋 바이트를 가공하지 않는 이유

- **정본으로 확정된 뒤에는 누구도 손대지 않는다.** 정규화는 가져오기 시점에 한 번이다(§1.1).
- **데이터셋 해시를 문서에 따로 적어 두지 않는다.** 여는 쪽은 zip 안의 바이트에서 다시 계산해 대조한다.
- **참조가 가리키는 본체가 없는 파일은 아예 열지 않는다**(§1).
