# `.mlpx` — 포트폴리오 (§8)

> `mlpx-spec.md`에서 갈라져 나온 절이다. **절 번호는 안 바뀌었다.** 전체 차례는 허브(`../mlpx-spec.md`)에 있다.
> **규칙만 적는다.** 이유와 경위는 같은 절 번호로 `docs/cases/mlpx-spec.md`에 있다.

## 8. 포트폴리오 — 양식은 마크다운, 답은 글이다

**양식과 답은 다른 물건이고, 형식도 다르다.**

| | 형식 | 어디서 오나 |
|---|---|---|
| 양식 (문항) | 마크다운 | 밖에서 온다 (§8.7) |
| 답 | 서식 없는 글 | 쓰는 사람 |
| 제출물 (`portfolio/document.md`) | 마크다운 | 우리가 조립한다 (§8.5) |

- **쓰는 사람은 마크다운 기호를 한 번도 보지 않는다.**
- **수업 전용 도구가 아니다.** 빈 양식이 있고, 문항을 마음대로 고칠 수 있고, 잠그는 장치가 없다.

### 8.1 양식 — `#`은 제목, `##`이 문항이다

```markdown
# 3학년 프로젝트 보고서       ← 문서 제목. 문항이 아니다. 없어도 된다

## 이 주제를 고른 이유         ← 문항
데이터를 고른 과정도 함께 쓰세요.   ← 그 문항의 안내문
```

- 다음 `##`까지가 그 문항의 몫이다. 안내문은 읽기 전용으로 렌더링되어 답 칸 위에 붙는다.
- **렌더링은 살균을 거친다.** raw HTML을 통과시키지 않고 링크 프로토콜을 검사한다 — **어느 입구로
  들어왔든 같은 경로를 탄다.**
- **링크는 누를 수 있다.** **`http`·`https`만 통과하고, 새 탭에서 열리며, `rel="noopener noreferrer"`가 붙는다.**
- **우리가 주소를 링크로 만들지는 않는다**(`linkify`를 켜지 않는다).
- **안내문에서 줄바꿈은 줄바꿈이다.** 문단은 빈 줄로 나눈다.
- **그림은 안내문에 안 들어간다.** 막는 것은 그리는 일뿐이다.

### 8.2 문항 id는 제목 슬러그다

- id는 **제목에서 만든다.** 겹치면 번호를 붙이고, 만들 수 없으면 순번으로 떨어진다.
- **순서 번호(`q1`·`q2`)로 하지 않는다.**
- **우리가 내보내는 양식에는 제목 줄에 id를 적는다.** 맨손 양식은 슬러그로 계산한다 — **둘 다 열려야 한다.**

```markdown
## 이 주제를 고른 이유 {#motivation}
```

- **표기는 Pandoc 계열의 관행을 따른다.**
- **HTML 주석은 양식을 읽을 때 통째로 걷어낸다.**

### 8.3 화면

**빈 프로젝트에서 열어도 화면이 비지 않는다.** 양식이 아직 없으면 둘을 준다.

```
[빈 양식에서 시작]   [양식 가져오기 ▾]
                      ├ (내장 프리셋들)
                      └ 파일에서 가져오기
```

- **가져오는 곳은 팝오버 하나에 담고, 목록은 등록부에서 나온다.** **안 만든 경로를 비활성으로 미리 세워 두지 않는다.**
- **줄의 무게는 등록부가 갖는다.** 앞서는 줄은 `파일에서 가져오기`다.
- **바닥은 [빈 양식에서 시작]이다.** 코드가 만들고, 별도 모드를 만들지 않는다.
- **가져오기는 대체가 아니라 추가다. 이미 있는 id는 다시 붙이지 않는다.**
- 문항은 번호·크고 굵은 제목·안내문·글 칸 순이다. [작성]과 [완성본]을 오가고 나란히 두지 않는다.
- **[완성본]과 점검은 답을 쓴 그대로 보인다.** 줄바꿈과 함께 **공백과 들여쓰기도 접지 않는다.** 답 앞뒤의
  공백만 걷으므로 첫 줄 앞의 들여쓰기는 걷힌다 — `open-decisions.md` 91.
- **프로젝트 요약은 여기 넣지 않는다.**
- **문항은 마음대로 고친다.** **잠그는 장치는 두지 않는다.**
- **체크리스트 완료 기준은 "모든 문항에 답이 있는가"다.** 항목을 추가하면 완료가 풀리고, 양식에 없는
  문항의 답은 세지 않으며, 양식을 고르지 않았으면 완료가 아니다.

### 8.4 문항을 지우면 그 글도 지운다

- **문항을 지우면 그 문항의 답과 첨부까지 함께 지운다. 되돌릴 수 없고, zip 엔트리도 같이 지운다.**
- **글이 사라지는 다른 경로는 없다.**
- **다른 문항이 아직 가리키는 사진은 떼거나 문항을 지워도 남는다.** 아무도 안 가리키게 된 것만 놓는다.
- **지금 양식에 없는 id의 답을 만나면 버리지 않는다** — 화면이 "이전 문항의 답"으로 보여준다.

### 8.5 파일에 남는 모양

```jsonc
{ "template": {
    "locale": "ko",                     // 양식의 언어. 모르면 없다
    "sections": [ { "id": "동기", "title": "이 주제를 선택한 이유",
                    "description": "데이터를 고른 과정도 함께 쓰세요." } ] },
  "answers": { "동기": "…" },
  "attachments": { "동기": ["portfolio/attachments/1.webp"] } }
```

- **`template.locale`은 양식의 언어다.** UI 언어를 따라가지 않고, **아는 경우에만 적으며**, 처음 문항이
  들어올 때 박고 안 바뀐다.
- **`answerFormat`이 답의 형식을 말한다.** 지금 값은 `plain-v1`. 이름에 버전이 들어가고, **늘어나면
  `FORMAT_VERSION`과 마이그레이션을 요구한다** (§9).
- **양식에는 id가 없다.** 양식을 고르지 않았다는 것은 `sections`가 비었다는 것이다.
- **문항은 언제나 파일에 통째로 박힌다.** 내장 양식도 밖에서 온 양식과 같은 물건이다.
- 문항 문구는 번역 대상이 아니다 — 쓴 사람의 말이다.

### 8.6 `.md`로 옮길 때 — 구조를 깨는 것만 막는다

- `.json`이 원본이고 `.md`는 도구 없이 읽는 용도다.
- **머리에 프로젝트 정보를 적는다. 적었다면 학번과 이름이 맨 위다.** 안 적었으면 자리도 없다.
- **읽기 좋은 것이 기준이다.** 막을 것은 **문항 구조를 깨는 것**과 **사용자의 HTML이 태그로 서거나 링크가 http·https 밖을 가리키는 것**뿐 — 줄
  첫머리의 `#`, 앞줄을 제목으로 만드는 단독 `-`·`=` 줄, 코드 밖의 `<`, http·https가 아닌 링크. **setext 밑줄에는 최소 길이가 없다.**
- **싣는 사용자 글 전부 — 답·문서 제목·문항 제목·머리글 값 — 에서 코드 밖의 `<`는 `&lt;`로 싣는다** — HTML을
  거르지 않는 뷰어에서 학생의 코드가 교사 화면에서 돌지 않게 한다. 한 줄짜리 글도 답과 같은 판정이다(머리글은 라벨과
  값을 이은 줄 통째로). 코드 안(울타리 코드 블록, 코드 스팬)은 그대로다. 코드 스팬 판정이 모르겠으면 바꾸는 쪽이다(줄을
  넘는 스팬·링크·표 칸을 넘는 스팬이 있는 문단, 들여쓴 코드 블록). `>`와 `&`는 안 바꾼다 (`open-decisions.md` 89).
- **같은 사용자 글에서 링크·이미지·링크 참조 정의의 주소가 날글자 `http://`·`https://`로 시작하지 않으면 그 링크를 글자로
  싣는다** — 주소를 여는 `(`·`:`(`]` 뒤, 사이의 스페이스·탭 포함) 앞에 `\`를 넣어 링크 문법이 안 서고 원문이 보인다.
  스킴(`javascript:`·`data:`·그 밖)도 상대 주소도 막는다. 엔티티·백슬래시가 낀 스킴은 통과하지 못한다. http·https 링크와
  이미지는 바이트 그대로다. 코드 안은 그대로이고, 주소를 여는 모양이 있는 문단은 코드 스팬을 안 믿는다 (`open-decisions.md` 93).
- **사진 링크(§8.6.1)는 앱이 짓는 모양과 글자까지 맞는 경로만 싣는다** — `nextAttachmentPath`가 짓는 이름(1부터의 수와 사진
  형식의 확장자)이다. 경로는 파일의 `portfolio.attachments`에서 오므로, 맞지 않는 경로(조작한 파일)는 링크를 깨고 태그를
  세울 수 있어 싣지 않는다. 읽기와 앱 안의 사진 표시는 그대로다 (`open-decisions.md` 93).
- **판정의 공백과 줄 끝은 CommonMark의 정의다 — 공백은 스페이스와 탭, 줄 끝은 `\n`·`\r\n`·홑 `\r`.** 빈 줄·닫는 울타리
  뒤·한 줄 글의 줄 끝을 JS의 `trim`·`\s`·`.`으로 세지 않는다 — 유니코드 공백에서 뷰어와 갈려 태그가 선다.
- **열어 놓고 안 닫은 코드 울타리(` ``` `·`~~~`)는 답 끝에서 닫아 준다.** 0열에서 연 것만 센다.
- **닫을 때는 닫는 줄만 더한다.** 여는 줄과 그 사이의 글자는 위의 이스케이프(`#`·setext 밑줄·`<`)
  말고는 바꾸지 않는다. 줄 끝은 `\n` 하나로 맞춘다.
- **줄 규칙이 울타리를 확신하지 못하는 답은 통째 감싼다** — 울타리 모양이 줄머리가 아닌 곳(공백·탭·`>`·목록
  표지 뒤)에 있는 답이다. 감싸는 울타리는 백틱이고 길이는 답 안의 가장 긴
  백틱 연속보다 하나 길다(최소 셋). 안의 글자는 이스케이프하지 않는다. 읽는 쪽은 `.md`를 해석하지 않으므로
  포맷 버전과 무관하다. 감싸는 범위는 코드 소유자가 승인했다 (`open-decisions.md` 82).
- **안 쓴 문항도 제목은 남긴다.**
- **렌더링된 `.md`는 저장하는 쪽이 만들어 넘긴다.** 포맷 계층은 `t()`를 모른다.

### 8.6.1 상한

- **글과 첨부를 합쳐 하나의 상한을 둔다.** 값은 `limits.ts`가 갖고, 문항마다 나누지 않는다.
- **상한을 넘은 상태에서도 줄이는 편집은 받는다.** 거절하는 것은 넘으면서 늘리는 편집뿐이다.
- **첨부는 굽는다 — WebP, 못 구우면 jpg.** 형식과 품질은 정본과 같은 상수이고, **긴 변 상한을 두고
  비율을 지킨다.** 여백을 붙이지 않는다. 긴 변 값은 `limits.ts`가 갖는다.
- **`.md`에는 상대 경로로 적는다** — `attachments/3.webp`.

### 8.7 양식은 어디서 오나

**프로젝트 파일로 나누지 않는다** (§6.3). 나누는 것은 마크다운 하나다.

| 경로 | 무엇 |
|---|---|
| 내장 프리셋 | `public/portfolio/`의 언어별 마크다운 파일을 같은 오리진에서 받는다 |
| 파일 열기 | 받은 `.md`를 연다. **가장 확실하다** — 파일을 나르는 통로는 이미 있다 |

- **출처는 마크다운 문자열 하나를 돌려주는 함수로 등록하고**, 파싱·살균·문항 세우기는 한 벌이다.
  **내장이라고 특별 취급하지 않는다.**
- **내장 프리셋은 지원 언어마다 하나씩 있다.** 어긋나면 CI가 운다 (`docs/i18n.md`).
- **프리셋은 파일만 더하면 는다.** 목록은 `public/portfolio/index.json`이 갖는다.

```jsonc
// public/portfolio/index.json          그리고 파일은 portfolio/hello.ko.md · hello.en.md
{ "hello": { "ko": "회상 일기", "en": "Looking back" } }
```

- **이름은 로케일 JSON에 두지 않는다.** `index.json`도 검증을 거치고, 깨지면 프리셋 줄만 사라진다.
- **주소로 나누는 길, 짧은 코드(서버 필요 — V6의 일), URL에서 받는 길, 브라우저끼리 나누는 길은 만들지 않는다.**
