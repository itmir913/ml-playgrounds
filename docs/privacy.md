# 로깅·개인정보 정책

> **이 문서는 우리끼리 보는 정책이다.** 바깥에 내놓는 **개인정보 처리방침의 정본은
> 여기가 아니라** `frontend/public/legal/`이다 (`open-decisions.md` "바깥에 내놓는 규정은 앱이 데리고 간다").
> **조문을 여기 복사하지 마라.** 이유와 판례는 `docs/cases/privacy.md`.

## 적용 범위 (2026-08-26)

- 방침이 말하는 것은 **앱**이다 — 공식 배포와 도커 자가호스팅. **랜딩 소개 페이지는 대상이 아니다.**
- **범위는 방침 머리에 못 박는다.**

## 확정된 것 (CLAUDE.md §1.1)

- 서버는 **사용자 계정, 프로젝트, 데이터셋, 학습 결과를 영구 저장하지 않는다.**
- 서버는 **학생의 인적사항(이름, 학번, 학교 등)을 받지 않는다.**
- 업로드된 데이터는 작업 종료 즉시 삭제되고, 고아 파일 청소기가 별도로 돈다 → `architecture.md` §2.2

## 개인정보가 존재하는 유일한 자리는 학생의 파일 안이다

- `manifest.json`의 `student`(학번·이름)는 학생이 내보내기 순간에 적는 선택 입력이고
  **어디로도 전송되지 않는다.**
- **파일 자체가 개인정보를 담는다는 사실과 지우는 방법(파일을 지운다)을 방침에 적는다** (`mlpx-spec.md` §6.1).

## 앱이 바깥으로 보내는 것 (2026-08-26에 전수)

- 앱 코드의 외부 주소는 **백본 내려받기 한 곳**이다(`ml/backbones.ts`). 방향은 내려받기뿐이다.
- 호스팅 쪽 접속 기록에 우리는 접근하지 않는다.
- **둘 다 방침에 적는다.** 외부 주소가 늘면 방침도 함께 바뀐다.

## 조 번호는 얼려 둔다 — 체크리스트가 그것을 인용한다

- **조를 다시 매기지 마라.** 번호가 주소다.

| 체크리스트 | 우리 답 | 조 |
|---|---|---|
| 1-1·1-2·1-3 최소 수집·목적·항목·보유기간 | 충족 — 수집 없음을 기재 | 제1조 |
| 2-1 안전성 확보 조치 | 충족 — 전송 없음·기기 내 저장 | 제6조 |
| 3-1 열람·정정·삭제·처리정지 | 충족 — 학생이 직접 지운다 | 제5조 |
| 4-1 만 14세 미만 아동 | 해당없음 — 동의 대상이 없다 | 제8조 |
| 5-1 보호책임자 | 충족 — `hello@luminousky.com` | 제9조 |
| 5-2 제3자 제공 · 5-3 위탁 | 해당없음 | 제2·3조 |

- `legal.spec.ts`가 이 조들이 방침에 실재하는지 확인한다.

## 백엔드가 서면 열리는 것

- 남기는 것은 **운영에 필요한 최소 로그**뿐이다 — IP, 타임스탬프, 작업 유형, 상태 코드.
- 남기지 않는 것 — 업로드된 데이터의 내용, 컬럼명, 클래스 라벨, 파일명, 결과 지표.
- **동작과 방침은 함께 바뀐다.**

### 결정해야 할 것

- IP를 그대로 남길 것인가, 해시하거나 마스킹할 것인가
- 보존 기간의 기본값 (환경 변수로 조정 가능해야 한다)

→ `open-decisions.md` #1. 백엔드 구현 전에 확정해야 한다.
