# 작업 리듬과 관문

`CLAUDE.md` §4가 가리키는 규칙 문서. **규칙만 적는다.** 왜 그런지와 무슨 일이 있었는지는
같은 절 번호로 `docs/cases/workflow.md`에 있다.

> 둘이 어긋나면 이 문서를 믿어라. **`CLAUDE.md`가 가리키지 않는 규칙을 여기 만들지 마라** —
> 새 규칙은 `CLAUDE.md`에 한 줄을 적고 이 문서의 절을 가리키게 한다.

---

## 1. 문서 갱신이 코드보다 먼저다

- 결정이 걸린 작업은 `docs/`를 고쳐 커밋한 뒤 구현 커밋을 낸다.
- 결정이 안 걸린 순수한 버그 수정에는 해당하지 않는다.
- **결정이 걸린 작업은 계획을 독립 감사자에게 먼저 보이고, APPROVE를 받은 뒤 구현을 시작하는 것을 권장한다.**
  계획을 쓴 쪽은 감사자에게 자기 결론을 주지 않고 문제와 계획만 준다. APPROVE WITH CHANGES면 고쳐서 다시 받는다.
  (사람 확인 — 지키는 검사는 없다.)

## 2. 검증은 앞뒤가 다르다

### 백엔드 — 본 코드와 테스트를 함께 쓴다

- 테스트 없는 백엔드 코드를 내놓지 마라. 먼저 쓰라는 뜻이 아니라 같은 작업 단위로 묶으라는 뜻이다.

### 프런트엔드 — 두 갈래다

- 화면은 눈으로, 로직(파싱·마이그레이션·IndexedDB·스토어·컴포저블)은 vitest로 덮는다.
- 화면을 만들 때는 **검증 가능한 로직을 컴포넌트 밖으로 빼서** 테스트할 수 있게 하라.
- **눈으로 확인하는 쪽은 사용자가 자기 브라우저로 직접 본다.** 브라우저 자동화 도구는 사용자가
  명시적으로 켜 달라고 할 때만 쓰고, 화면을 고칠 때마다 스스로 띄우지 마라.

## 3. 관문

### 명령 하나다

- 관문은 `npm run ci`다. 백엔드 관문(`backend/scripts/ci.py`)과 로케일 계약도 그 안에서 돈다.
- CI가 부르는 것도 그 하나뿐이다. **검사를 더할 때는 그 안에 넣는다** — 워크플로 파일에 단계를 풀어 쓰지 마라.

### 커밋마다 닿는 검사, 배포 전에 전부

- **전체 관문은 배포(태그) 직전에 한 번 돌린다.** 커밋마다는 **닿는 검사만** 돌린다.
- 닿는 검사: 소스 전체를 훑는 검사(`docs/rule-coverage.md`의 목록) · 건드린 스펙 ·
  `vue-tsc --build`와 `lint:check` · 로케일을 건드렸으면 로케일 계약 · 백엔드를 건드렸으면 백엔드 관문.
- "닿는 검사"를 좁게 잡지 마라. 소스 전체를 훑는 검사는 늘 돌린다.
- **트립와이어 검증은 그 스펙 파일 하나만 돌린다.** 전체를 돌리면 겨눈 검사가 잡았는지 구분이 안 된다.

### 감사가 안 도는 동안

- 이 저장소는 `기능 개발 → 감사`를 오간다. **감사 국면을 여는 것은 사용자다.**
- **규칙·상한·어휘를 세우면 그 자리에서 검사를 세운다.** 다음 커밋으로 미루지 마라.
- **세운 검사를 망가뜨려 우는 것까지 본다.** 초록은 도는 증거이지 무는 증거가 아니다.
- **"나중에 확인한다"를 적지 마라.**
- 감사가 안 본 경계는 `roadmap.md` "지금 어디인가"에 있다. 그쪽 코드를 만질 때는 그 스펙부터 열어라.

### 감사 국면은 어떻게 도는가

- **감사자는 찾기만 하고 고치지 않는다.** 수정은 코드를 쓰는 세션이 한다.
- **증거는 돌연변이뿐이다.** 한 곳을 뭉개고 → 그 스펙과 `vue-tsc`를 돌리고 → 파일 하나의 정확한
  경로로 즉시 되돌린다. **안 운 것이 그 라운드의 답이다.**
- 돌연변이 묶음 사이마다 `git diff --quiet -- frontend/src`를 본다. 커버리지 판은 `Test Files`의
  분모가 스펙 목록 수와 같은지부터 본다.
- 등급은 **A**(학생이 지금 다치거나 초록불이 거짓) · **B**(결정이 걸려 문서가 먼저) · **C**(제안).
  **실측 없이 A를 매기지 않고, 확인 못 한 의심은 "못 한 것"에 적는다.**
- **C는 쌓아 두지 않는다.** 나오는 대로 코드를 쓰는 세션이 판단해 고치거나 반박하고, 그 판단을 감사자에게
  반박받는다. **설계를 고쳐야 하는 C는 처음부터 B다** — 코드 소유자가 정한다.
- **지적마다 같은 병의 이웃을 `grep`으로 세어 붙인다.** 한 군데뿐이면 그렇다고 적는다.
- **처방도 실측한다.** 고침을 임시로 넣고 원래 돌연변이가 그 상태에서 우는지까지 본다.
- **이미 운 돌연변이는 다시 돌리지 않는다 — 그 사이 안 바뀌었으면.** 확인한 커밋 이후 그 검사 파일과 그
  검사가 지키는 소스가 둘 다 그대로면(`git diff <확인 커밋>..HEAD -- <검사> <소스>`가 빈다) 표에 "확인 커밋
  이후 변경 없음 — 생략"으로 적는다. 하나라도 바뀌었으면 다시 잰다. 남는 시간은 안 본 것에 쓴다.
- **"표준 라이브러리와 갈린다"고 주장하려면 그 라이브러리를 돌려라.** 돌린 출력을 붙이고, 경계를
  양쪽으로 재고, 고칠 때는 저쪽이 통과시키는 입력에서 우리도 통과하는지 검사로 못 박는다.
- **여는 시점은 커밋 범위로 정한다** — 한 덩어리를 닫은 직후 · 고침 라운드 직후 · 실측 상수나
  수치 로직을 만진 뒤 · 배포선 직전. 규모는 돌연변이를 전부 돌릴 수 있는 만큼이다.
- **재고 나서 적되 반대편도 재라.** 측정값에는 조건과 반복 횟수를 적고, 처방의 기전이 성립하는지를
  함께 확인한다. 감사자에게도 같은 것을 요구한다.

### 인수 테스트 국면

- 소유자가 **"인수 테스트 시작"**이라고 말하면 연다. 브라우저 자동화를 요청한 것으로 본다(§2의 예외).
- 절차는 `docs/acceptance.md` 하나다. 에이전트는 §1 브라우저 몫을, 소유자는 §2 실기기 몫을 같은 시각에 돈다.
- 체크리스트는 세션 스크래치패드에 복사해 체크한다. 메모리와 저장소에 사본을 두지 않는다.

### 의존성은 감사 국면에 올린다 (2026-09-23)

- Dependabot은 메이저만 PR로 준다(`.github/dependabot.yml`).
- **감사 국면을 열 때 `frontend/`에서 `npm outdated`부터 돌리고**, 올린 뒤 관문을 통째로 돌린다.
- **예외는 취약점 알림이다.** 학생 파일을 여는 의존성(exceljs·SheetJS·papaparse·fflate)이면 국면을 기다리지 않는다.

### 요청서는 무엇을 담는가

- 공통은 이 절이, 라운드 파일은 겨냥할 슬라이스·의심할 것·제외할 것·첫 돌연변이·규모만 적는다.
- 범위는 "이 패턴을 N번 더 반복해도 되나"로 잡고, **제외할 것을 반드시 적는다.**
- 아는 약점은 미리 주되 "내가 틀리게 알고 있으면 그건 새 항목"이라는 단서를 단다.
- **감사자에게 금지:** `git commit`·`push`·`tag`·`add` · 영구 수정 · `npm run lint` ·
  `git stash`·`git checkout .`·디렉터리 단위 되돌리기 · 하위 에이전트와 클라우드 · 버전 올리기 제안.
- `git status --short`가 더러운 것은 정상이라고 미리 말해 둔다(병렬 세션).

### 보고서에 반드시 있어야 하는 것

- 지적마다 **자리(`경로:줄`) · 주장 · 재현 · 처방.**
- 못 찾은 항목은 못 찾았다고 명시한다. "확정 불가"·"확인 못 했다"를 쓴 자리를 따로 모은다.
  **돌연변이 표 전체**를 운 것까지 적는다.
- **받은 보고서를 그대로 믿지 않는다.** 저장소에서 재현하고 고칠 것과 반박할 것을 가른다.

### 감사가 되풀이해 잡은 병

요청서에 이 목록을 붙인다.

1. 유창하게 틀린 주석.
2. 조각마다 초록인데 잇는 검사가 없다.
3. 픽스처가 상태를 미리 주면 그 경로를 안 지나간다 — **진짜 입구로 재현하라.**
4. `toContain`은 자리를 안 본다.
5. `looseObject`가 오타를 숨긴다.
6. 같은 판정을 두 곳에서 계산하거나, 한 벌을 서로 다른 축으로 좁히는 것.
7. 부동소수의 정확 비교와 덧셈 순서.
8. 실측 문장이 표본보다 넓은 것.

검사 자체도 대상이다 — 우는 이유가 겨냥한 것과 다른 항목을 따로 본다.

### 확인과 고침은 다른 명령이다

- 확인은 `npm run ci`(안에서 `lint:check`), 고치는 것은 `npm run lint`다.
- `lint`는 남의 작업 파일까지 고쳐 쓴다. **확인하려던 것뿐이라면 절대 `lint`를 쓰지 마라.**

### 관문이 빨갛다고 다 빨간 것이 아니다 — 격리부터 (2026-09-10)

- **격리해서 통과했다고 넘어가지 마라. 종류부터 가른다.**
- **시간 초과**는 부하다 — 검사 상한은 `vite.config.ts`가 갖는다.
- **단언 실패**는 검사의 경합이다 — 정해진 틱 수 대신 끝 상태를 `vi.waitFor`로 기다리게 고친다.
- **해결·파일 열기 실패**(`Tsconfig not found`, `UNKNOWN: open`)와 워커 시작 실패는 기계 자원이다 —
  에이전트를 관문과 겹쳐 돌리지 않는다. 격리해서 다시 돌리는 것은 이 갈래를 가리는 데만 쓴다.

### 관문의 출력은 파일로 받는다 (2026-09-08)

- `npm run ci > ci.log 2>&1`로 받고 `tail`·`grep`으로 읽는다. **`| tail`이나 `| grep`으로 받지 마라.**

### CI가 뱉는 글자는 영어다

- 실패할 때 딸려 나오는 글자(`expect`의 메시지, `throw new Error`)는 영어다.
  `tests/ci-language.spec.ts`가 막는다.
- **검사 이름은 예외다.** 이유는 아래 절.

### 이 저장소는 한국어로 쓴다

- 주석·문서·결정문·검사 이름은 한국어다. 검사 이름만 영어로 바꾸지 마라.
- 다시 열 조건은 **한국어를 못 읽는 기여자가 실제로 왔을 때**이고, 그때는 언어 정책 전체를 논의한다.

### DOM이 필요한 스펙은 스스로 밝힌다

- 첫 줄에 `// @vitest-environment jsdom`을 적는다. 기본 환경은 `node`다.
- **DOM 부재 판정은 `typeof X === 'undefined'` 한 표기만 쓴다.** `ui-rules.spec.ts`가 강제한다.

## 4. 버전

- **관리하는 버전은 `frontend/package.json` 하나다.** 학생 파일의 `manifest.appVersion`에 박힌다.
- **나머지 버전 문자열은 전부 `0.0.0`으로 둔다** (백엔드 `pyproject.toml`, FastAPI 앱, 문서 예시, 테스트 픽스처).

### 포맷·엔진 버전은 다른 물건이다

- `FORMAT_VERSION`·`DB_VERSION`·엔진 `version`·모델 형식 이름의 `-vN`은 값 자체가 뜻을 가진다.
- 배포 전의 규칙 — 형식이 바뀌어 기존 테스트 프로젝트가 안 맞으면 마이그레이션을 설계하지 말고
  그 `.mlpx`를 지운다 — 는 배포로 끝났다. 저장소의 옛 인용은 이 문장을 가리킨다.
- 배포 뒤로는 어휘나 좌표계가 바뀌면 **반드시** 올라가고, 지문과 마이그레이션이 같은 커밋에 온다.
- **판정 기준은 하나다 — 지시가 있었는가.** `tests/versions.spec.ts`가 깨졌을 때 기대값을 고치는
  것은 답이 아니다. 지시가 없었다면 되돌릴 것은 올린 쪽이다.

### 나가는 것과 되돌리는 것 (2026-09-22)

- **배포는 코드 소유자가 그때 명시적으로 허락해야만 돈다.** 태깅·푸시 지시, 감사 CLEAN, 관문 초록,
  앞서 받은 허락("CLEAN이면 배포까지")은 배포 허락이 아니다 — 에이전트는 배포 명령을 스스로 돌리지 않고,
  준비가 끝나면 묻는다.
- **배포는 손으로만 돈다.** `gh workflow run "Deploy frontend" --ref <태그>` — `main`이 아니라 태그를 준다.
  태그가 아닌 ref는 `deploy.yml`의 `tag-only` 잡이 거절한다.
- **되돌리기는 같은 명령에 옛 태그다.**
- **배포 시각은 교실이 정한다.** 수업 일과 중에 내보내지 않는다.
- **나간 뒤 확인은 해시다** — 라이브 HTML의 `assets/index-*.js`가 그 태그로 빌드한 `dist/`의 것과 같은지 본다.

## 5. 남의 코드를 들일 때

- **파일 머리에 셋을 적는다** — 출처(저장소·버전·파일), 라이선스, **우리가 바꾼 것 전부.**
- **벤더링은 마지막 수단이다.** 먼저 의존성으로 쓸 수 없는 이유가 `docs/open-decisions.md`에 있어야 한다.
- **나눠 줄 때는 고지가 함께 간다.** 목록은 사람이 관리하지 않는다 — 빌드(`frontend/scripts/notices.ts`)가
  세고, 전문을 못 찾으면 선다 (`open-decisions.md` "나눠 주는 남의 코드는 산출물이 세어서 고지한다").

## 6. 문서를 나눌 때

문서는 **허브와 스포크**다 (`docs/architecture.md` ↔ `docs/architecture/`). 근거는
`open-decisions.md` "문서를 나누되 주소는 안 바꾼다 — 허브와 색인".

- **절 번호와 제목을 바꾸지 마라.** 저장소가 그것으로 문서를 가리킨다.
- **스포크의 표제는 허브 차례에 다 있어야 한다.** `doc-refs.spec.ts`가 막는다.
- **옮기는 작업과 고쳐 쓰는 작업을 한 커밋에 섞지 마라.**

## 8. 규칙과 판례를 나눈다

위계는 셋이다.

| 층 | 무엇을 담는가 |
|---|---|
| `CLAUDE.md` | 절대 규칙 한 줄과, 어떤 경우에 어느 문서를 볼지 |
| `docs/X.md` | 그 분야의 규칙만 |
| `docs/cases/X.md` | `docs/X.md` 규칙의 이유·결정 과정·판례 |

- **규칙 문서에는 규칙만 둔다.** 이유·경위·사례는 같은 이름의 `docs/cases/X.md`로 간다.
- **`CLAUDE.md`에는 날짜를 적지 않고 줄 수 상한을 넘기지 않는다.** `claude-md.spec.ts`가 막는다.
  상한은 그 검사 파일의 이름 있는 상수이고, 늘리려면 상수를 고친다.
- 판례 파일의 형식과 색인은 `docs/cases/README.md`가 갖는다. **추가만 하고 고치지 않는다.**
- **규칙과 판례는 짝으로 맞물린다.** `docs/X.md`마다 `docs/cases/X.md`가 있고 그 반대도 같다. 규칙 문서는
  자기 판례를 이름으로 가리키고, 판례 색인은 판례 파일을 전부 싣는다.
- **결정문의 상태는 `**[미정]**`·`**[결정]**`·`**[폐기]**`다.** `[폐기]`는 뒤의 결정에 대체되어 더는 유효하지 않은 것이고,
  표제에 "대체됨"·"폐기"를 적으며 대체한 결정의 제목을 가리킨다. 결정문(`###`)마다 표제 바로 아래 그 한 줄과 결론
  한 문장을 두고, 경위는 `docs/cases/open-decisions.md`의 **같은 제목** 아래에 둔다.
- **규칙 문서의 본문에도 날짜를 적지 않는다.** 날짜는 표제(주소)와 차례 줄에만 남고, 경위의 날짜는 판례가 갖는다.
- **목록을 개수로 가리키지 마라** — "위 N개" 같은 말은 항목이 하나 늘거나 줄면 곧바로 낡는다.
  가리키는 것의 이름을 적는다.
- 규칙·판례의 짝, 결정문 상태, 본문의 날짜, 개수로 가리키는 말은 `docs-structure.spec.ts`가 막는다.

## 9. 커밋

**예외 없다.**

- **`main`에서 순차적으로 작업한다.** 기능 브랜치를 만들지 마라.
- **모든 커밋은 GPG 서명한다.** `--no-gpg-sign`이나 `-c commit.gpgsign=false`를 쓰지 마라.
  서명이 실패하면 우회하지 말고 그대로 멈추고 원인을 보고하라.
- **태그도 서명한다.** 설정(`tag.gpgsign=true`)은 기기마다다 — 새 기기에서 첫 태그를 낼 때
  확인하라. **과거 태그를 소급 서명하지 마라.**
- **커밋 메시지에 `Co-Authored-By`, `Generated with` 같은 도구 표기를 넣지 마라.**
  메시지에는 변경 내용만 적는다.
- **모든 커밋에 `-s`를 붙인다.** `Signed-off-by:`는 도구 표기가 아니라 **DCO 서명**이다
  (`docs/open-decisions.md` "기여는 MIT로 들어오고, DCO로 서명하고, 재라이선스를 허락한다").
- **스테이징 경로를 반드시 명시한다.** `git add .`, `git add -A`, `git commit -a` 전부 **금지**.
  - 추적 중인 파일: `git commit -- <경로1> <경로2>`
  - 새 파일: `git add -- <경로1> <경로2>` 로 **하나씩 열거한 뒤** 같은 경로로 커밋한다.
- 메시지는 Conventional Commits (`feat:` `fix:` `docs:` `refactor:` `test:` `chore:`).

## 10. 소스를 쓰는 법

### 단정형 주석은 무는 검사를 가리킨다

- 실측값이나 *"X는 Y다"*를 적었으면 지키는 검사를 이름으로 함께 적고, 없으면 **"사람 확인"임을 밝혀라.**
- **주석은 증언이지 증거가 아니다** — 근거로 쓰기 전에 재라.
- **소급 적용하지 마라** — 새로 쓰는 것부터.

### 힙독으로 쓰지 않는다

- **소스 파일을 셸 힙독(`cat > 파일 <<'EOF'`)으로 쓰지 마라. 파일 도구를 쓴다.**
  훅(`.claude/hooks/no-heredoc.mjs`)이 막는다. 히어스트링(`<<<`)은 통과한다.
- **스크립트로 꼭 써야 하면** 백슬래시를 `chr(92)`로 조립하고 `cat -v`나 `repr()`로 확인한다.
  파이썬은 **`newline=''`을 준다.**
- **되돌리기는 `git checkout -- <파일>`이 아니라 심은 것만 되돌린다.**

## 11. 코드 소유자와 함께 일하는 법

코드 소유자는 이 도구를 자기 수업에서 쓰는 **중·고교 정보/인공지능 교사**다. 교실에서 안 통하는 설계는
기술적으로 옳아도 틀린 설계다.

- **답변과 질문 선택지는 한국어로 쓴다.**
- **코드를 쓰기 전에 계획을 보이고 판단을 받는다.** 결정이 걸린 것은 추측해 구현하지 않는다.
- **코드 소유자가 정할 것은 추천과 함께 묻는다.** 선택지마다 대가를 적고, 추천하는 것을 맨 앞에 이유와 함께 둔다.
- **"필요하냐"고 물으면 필요성부터 답한다.** 자리나 방법으로 비껴가지 마라. 없어서 다치는 사람이 없으면 안 만든다.
- **근거 없는 임계값이 필요한 안은 선택지가 아니라 탈락이다.** 대등한 안처럼 내놓지 마라.
- **기다림은 비용이지 실패가 아니다.** 상한을 정할 때 시간·메모리·실패 모양을 따로 재서 나란히 보인다.
- **화면은 원칙대로 먼저 만들고, 코드 소유자가 실물을 보며 감사한다.** 디자인 감각이 예민하므로 화면 변화는
  스크린샷으로 맞춰 간다. 색의 기준선은 코드 소유자가 만든 시뮬레이터들이다.
- **코드 소유자가 정해 준 낱말은 바꾸지 않는다.** 용어는 화면·주석·검사 이름·문서까지 하나다 (`docs/terms.md`).
- **클라우드(아티팩트·원격 하위 에이전트)를 쓰지 않는다.** 전부 로컬에서 돈다. `git push`만 예외다.
- **이 저장소에는 병렬 세션이 함께 돈다.** 커밋 전에 `git status`를 보고 남의 파일은 포맷팅도 하지 마라.
- **push 전의 잘못된 커밋은 fix 커밋으로 덮지 말고 rebase로 지운다.**
- **배포는 코드 소유자의 지시로만, 손으로 돈다**(§4). "태깅하라"는 버전 결정이다. 순서는 ① 문서·구현 커밋
  ② `npm run ci` 전부 초록 ③ `frontend/package.json`·`package-lock.json`(두 자리) 버전 ④ `chore: <버전>` 커밋
  ⑤ `git tag -s <버전> -m "<버전>"`(`v` 접두사 없음)과 `git tag -v` ⑥ `main`과 태그 push ⑦ 배포는 코드 소유자가
  그때 명시적으로 허락할 때만(§4 — 태깅 지시·감사 CLEAN·앞선 허락은 배포 허락이 아니다).
  **이슈는 배포가 확인된 뒤에 닫는다.**
- **메모리에는 규칙을 두지 않는다.** 규칙은 이 저장소에 적고, 메모리는 그 기기에서만 참인 것만 둔다.

## 12. 검사를 세울 때 밟은 함정

이유와 사례는 `docs/cases/workflow.md` 같은 절에 있다.

- **시끄럽게 실패하게 만든다** — 타입 → 검사 → 문서 순으로 강제하고, 세운 검사는 우는지 확인한다.
- **진짜 입구로 재현하라.** 내부 자료구조를 손으로 조립한 재현은 방어선을 건너뛴다.
- **픽스처는 매번 새 복사본을 준다.** 격리하면 초록이고 전체에서만 빨가면 공유 참조를 의심하라.
- **node 전역이 jsdom에 샌다** — `BroadcastChannel`·`navigator.locks`가 워커 스레드를 가로질러 통한다. 스펙에서 지운다.
- **워커 경계는 프로토타입을 벗긴다.** `toJSON()`이 JSON이 아닌 라이브러리 객체는 경계를 건너기 전에 평범한 값으로 바꾼다.
  가짜 풀이 진짜 경계보다 관대하면 검사는 초록인데 브라우저에서 죽는다.
- **흩어진 결함은 빠진 연산이다.** 같은 병이 여러 자리에 있으면 자리를 세지 말고 없는 원시 연산을 세운다.
- **같은 숫자는 같은 상수가 아니다.** 경로를 확인하기 전에 값만 보고 이름을 붙이지 마라.
- **실측 문장은 표본만큼만 쓴다.** "하나도 없다"는 반례 하나로 깨진다 — 잰 범위를 문장에 넣는다.
- **성질은 재고 나서 적는다.** 짐작을 단정으로 적지 마라.
- **의존성 갱신이 계약을 옮긴다.** patch·minor라도 `.mlpx`가 받는 집합을 좁힐 수 있으니 관문을 통째로 돌린다.
- **로케일 JSON은 정규식 일괄 치환이 아니라 경로로 고치고, diff를 눈으로 본다.**
- **폴백 검사는 본진의 실패부터 못 박는다.** 안 그러면 폴백을 한 번도 안 지나간다.
- **캔버스·`<dialog>`·CSS 뒤는 jsdom 검사가 구조적으로 못 본다.** 그런 기능은 사람이 한 번 몰아 보는 것을 합격 조건에 넣는다
  (브라우저 자동화는 코드 소유자가 요청할 때만).
