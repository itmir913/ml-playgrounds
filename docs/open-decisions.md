# 열려 있는 결정

**구현 전 반드시 확인한다.** 잘 모르겠으면 추측해서 구현하지 말고 여기 항목을 추가하고 물어라.
결정되면 "결정됨" 절로 옮기고 날짜와 근거를 남긴다.

## 미결정

### 1. 로깅 정책 — 필요 시점: 백엔드 구현(4단계)
IP를 수집할 것인가, 보존 기간은 얼마인가. 현재 방향은 최소 수집 + 기간 설정 가능.
정해지면 `privacy.md`에 명시한다. CLAUDE.md §1.1의 유일한 예외 조항이다.

### 2. 모델 직렬화 형식 — 필요 시점: 예측 기능(4~5단계)
`.mlpx`에 모델을 담기로 했으므로 형식을 정해야 한다.
**`pickle`은 역직렬화가 곧 임의 코드 실행이다.** 학생이 만든 파일을 서버가 언피클하면
그 자체로 원격 코드 실행 취약점이 된다. 후보:

| 후보 | 장점 | 단점 |
|---|---|---|
| ONNX (`skl2onnx`) | 안전, 브라우저 실행(onnxruntime-web) 가능 | 의존성 추가, 일부 sklearn 모델 미지원 |
| 자체 JSON (계수·트리 구조) | 완전 통제, 사람이 읽을 수 있음(교육적) | 알고리즘마다 직렬화기를 직접 써야 함 |
| pickle | 즉시 구현 | **서버에서 역직렬화 금지. 브라우저 전용으로도 실행 불가** |

### 3. 브라우저 학습 엔진 — 필요 시점: V1.5 착수 전
Pyodide + sklearn(WASM)이 유력. 초기 다운로드 크기와 결과 일치 수준을 확인하고 결정.
→ `architecture.md` §3

### 4. 이미지/음성 데이터의 `.mlpx` 포함 방식 — 필요 시점: V5 착수 전
원본을 담을 것인가, 썸네일+해시만 담을 것인가.
후자를 택하면 **무결성 검증이 무력해진다**는 점을 감수해야 한다. → `mlpx-spec.md` §1

### 6. 메모리 예산 — 필요 시점: 백엔드 구현(4단계)
`MAX_MEMORY_MB`(2048) × `MAX_CONCURRENT_JOBS`(CPU 코어 수)가 호스트 메모리를 넘는다.
8코어면 16GB를 요구하는데 CLAUDE.md §1.5와 충돌한다. 후보:
- 총 메모리 예산(`TOTAL_MEMORY_BUDGET_MB`)을 두고 동시 실행 수를 거기서 역산
- `MAX_CONCURRENT_JOBS` 기본값을 코어 수가 아니라 보수적 상수로

### 7. IndexedDB 할당량 정책 — 필요 시점: `storage.ts` 구현(3단계)
50MB CSV를 자동 저장하면 브라우저 할당량을 빠르게 소모한다.
`navigator.storage.estimate()`로 사전 경고할 것인가, 프로젝트 수 상한을 둘 것인가,
`persist()`를 요청할 것인가.

### 9. 세션 상한값 — 필요 시점: 백엔드 구현(4단계)
세션이 WebSocket 연결 수명만큼 살게 되면서 디스크 점유가 "작업 중"에서 "접속 중"으로 늘었다.
30명 학급 × 50MB = 1.5GB가 상주한다. 아래 값을 정해야 한다 (전부 환경 변수).

| 항목 | 제안 기본값 | 환경 변수(안) |
|---|---|---|
| 세션 유휴 타임아웃 | 15분 | `SESSION_IDLE_TIMEOUT_SECONDS` |
| heartbeat 간격 / 무응답 허용 | 30초 / 3회 | `WS_PING_INTERVAL_SECONDS`, `WS_PING_MAX_MISSED` |
| 동시 세션 수 상한 | 미정 (디스크에서 역산) | `MAX_CONCURRENT_SESSIONS` |
| 세션당 디스크 상한 | 업로드 상한과 동일 | `MAX_SESSION_DISK_MB` |
| 고아 디렉터리 정리 기준 | 마지막 접근 후 30분 | `ORPHAN_SWEEP_AFTER_SECONDS` |

상한에 걸리면 새 세션을 `SERVER_BUSY`로 거절한다. 접속 중인 세션을 죽이지 마라.

### 10. 배포 패키징 — 필요 시점: 배포 단계
로컬 개발은 도커 없이 한다(`uv run` / `npm run dev`). 도커 이미지, nginx 설정,
`docker-compose.yml`은 실제 배포 환경을 확인한 뒤 만든다. 확정할 것:
리버스 프록시 구성, WebSocket 프록시 타임아웃, 작업 디렉터리를 tmpfs로 올릴지,
`SIGNING_SECRET` 주입 방식.

### 11. 브라우저 학습 엔진의 배포 방식 — 필요 시점: V1.5
Pyodide + sklearn은 최초 로드가 10~25 MB다. 자체 서빙(전송량 소모, 방화벽에 안전) vs
공개 CDN(전송량 0, 학교 방화벽에 막힐 수 있음). 현재 방향은 자체 서빙 기본 + CDN 선택지.
→ `architecture.md` §7.4

### 12. 브라우저 학습 결과의 검증 흐름 — 필요 시점: 교사용 화면
브라우저를 기본으로 삼으면 대부분의 제출물이 "미검증"이 된다. 교사가 "서버에서 검증"을
눌렀을 때 재학습 후 지표를 대조하고 서명본을 만드는 흐름으로 해결하려 한다.
확정할 것: 지표 일치 판정의 허용 오차(WASM과 네이티브의 부동소수점 차이), 학급 단위 일괄 검증 여부.
→ `architecture.md` §7.5

### 13. 브라우저 학습 행 수 상한 — 필요 시점: V1.5
`BROWSER_ROW_LIMIT`은 현재 5,000으로 잠정 설정돼 있다(`frontend/src/ml/backend.ts`).
실제 값은 엔진을 정한 뒤 저사양 학교 PC에서 측정해 정한다.
서버 상한(`MAX_ROWS`)과는 무관한 값이다.

### 14. CSV 파서 — 필요 시점: 데이터 업로드 화면
SheetJS를 쓰려 했으나 **npm의 `xlsx`는 0.18.5에서 멈춰 있다.** SheetJS는 배포를 자체
CDN으로 옮겼고 npm 레지스트리는 갱신되지 않는다. 0.18.5에는 프로토타입 오염
(CVE-2023-30533)과 ReDoS(CVE-2024-22363)가 남아 있으며 두 수정 모두 npm에 오지 않았다.
**학생이 올린 파일을 파싱하는 자리**이므로 그대로 쓸 수 없다. 후보:

| 후보 | 장점 | 단점 |
|---|---|---|
| Papa Parse | CSV 전용 표준. 스트리밍·웹워커·인코딩 처리. 큰 파일에서 화면이 멈추지 않는다 | xlsx를 못 읽는다 |
| SheetJS (자체 CDN) | xlsx까지 읽는다 | npm 밖에서 받아야 해 락파일·CI·오프라인 설치가 번거롭다 |
| 직접 구현 | 의존성 0 | 따옴표 안 줄바꿈, BOM, 인코딩 등 함정이 많다 |

현실적으로 학생이 엑셀 파일을 가져오는 경우가 잦다. V1은 CSV만 범위이므로 Papa Parse로
가고, xlsx 지원은 별도 결정으로 미루는 것을 제안한다.

## 결정됨

### 백엔드 코드의 한국어 (2026-08-04)
**주석과 docstring은 한국어로 써도 된다.** 막으려는 것은 UI로 새어 나가는 문자열이지
개발자용 설명이 아니다. CI 검사는 `ast`로 **문자열 리터럴만** 순회한다(주석은 AST에 없다).

### 예측 기능의 모델 보관 (2026-08-04)
서버가 학습 후 직렬화된 모델을 클라이언트로 내려보내고, 클라이언트가 `.mlpx`에 담는다.
서버는 모델을 보관하지 않는다. §1.1(서버 무상태)과 "재학습 없이 예측"이 양립한다.
→ `mlpx-spec.md` §5 (형식은 위 미결정 2번)

### 문서 언어 (2026-08-04)
`docs/`와 `CLAUDE.md`는 한국어. 백엔드 코드의 식별자는 영어.

### 파일 확장자: `.mlpx` (2026-08-04)
`.docx` / `.pptx` / `.hwpx` 계열로 읽히고 **그 포맷들도 실제로 zip**이라 이름이 구조와 일치한다.
"hwpx처럼 여러 파일을 하나로 묶은 것"이라는 한 문장 설명이 교실에서 그대로 통한다.
`.mlp`는 MeshLab 프로젝트이자 Dolby TrueHD 오디오 확장자라 탈락.
코드에서는 상수 하나로만 관리하므로 변경 비용은 여전히 낮다.

### zip 라이브러리: fflate (2026-08-04)
gzip 기준 약 8KB로 가장 가볍고 빠르다. 비동기·스트리밍을 지원해 큰 CSV에서 화면이 멈추지 않는다.
JSZip은 약 30KB에 유지보수가 활발하지 않아 제외.

### 런타임 검증: zod (2026-08-04)
`.mlpx`는 외부에서 들어오는 파일이다. 스키마 하나로 타입과 검증을 함께 얻고,
"어느 필드가 왜 잘못됐는지"를 위치 정보와 함께 돌려주므로 깨진 파일을 연 학생에게
무엇이 문제인지 알려줄 수 있다.

### Python 하한 3.12 (2026-08-04)
numpy 2.x 스텁이 `type` 문 등 3.12 문법을 쓴다. mypy를 3.11로 고정하면 스텁 파싱에서
막혀 검사 자체가 진행되지 않는다.

### IntegrityStatus를 ErrorCode에서 분리 (2026-08-04)
"검증됨"은 실패가 아니라 상태다. 검증 요청 자체는 성공했고 결과가 셋 중 하나일 뿐이다.
로케일 네임스페이스도 `errors.*`가 아니라 `integrity.*`.
