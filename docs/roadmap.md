# 범위와 로드맵

기능을 만들기 전에 "이게 지금 범위인가"를 여기서 확인한다. **규칙만 적는다.** 배포판마다
나간 것, 단계의 경위, 감사가 남긴 것은 `docs/cases/roadmap.md`에 있다.

## 지금 어디인가 (2026-09-03)

**지금은 기능 국면이다.** 감사는 그만둔 것이 아니라 주기의 한 국면이고 — `기능 개발 → 감사`를
오가며 — **여는 시점은 사용자가 정한다.** 국면마다 무엇을 하는지는 `workflow.md` §3의
"감사가 안 도는 동안"과 "감사 국면은 어떻게 도는가"가 갖는다. 다음 감사는 **기능을 한 덩어리
끝낸 뒤의 diff 감사**다.

**재야 할 것** — 사진 로지스틱 회귀의 상한을 `tools/bench.html` [상한 찾기]의
`limit_image_logistic_regression`으로 개발 PC에서 다시 잰다(코드 소유자 결정).
`MLJS_IMAGE_LOGISTIC_REGRESSION_ROW_LIMIT`의 옛 실측이 기준표와 서너 배 갈린 까닭을 확인하려는 것이다.
그리고 [클래스만 훑기]로 클래스 수 사다리(`CLASS_LADDERS`)를 재서 `MLJS_*_CLASSES_MS`를 채운다 —
채우기 전에는 예상 시간이 클래스 수를 보지 않는다(open-decisions 88).

순수 JS 사진 기준표(`baseline.image`)는 두 길로 찼다
(`limits.ts`의 `MLJS_IMAGE_*_BASELINE_MS`). 나이브 베이즈·로지스틱·KNN·K-평균·인공신경망은
`tools/bench.html` [사진만 훑기]가 도는 사다리(`IMAGE_LADDERS`)가 개발 PC 크롬에서 쟀고,
의사결정트리·랜덤 포레스트·SVM은 [상한 찾기]의 사진 상한 사다리가 기준표를 겸해 다른 기기에서
재 개발 PC 기준으로 환산했다. 백본이 하나 더 생기면 두 길 다 다시 잰다.

**감사가 안 본 채로 남은 경계** — 거기를 만질 때 먼저 볼 자리다.

- **두 시점을 견줘야 잡히는 것 — 갱신 누락과 상태 이력.**
- **비결정적 실행에서만 나는 경합.** 경합을 겨누는 요청서는 **"순서를 강제해 재현하라"를 명시한다.**
- 실기기·실측·스크린 리더는 `rule-coverage.md`가 감사 밖으로 적어 두었다.

**파일에 적히는 어휘를 하나 바꾸면 `FORMAT_VERSION` 증가와 마이그레이션이 붙는다**
(`tests/schema-version.spec.ts`). 어휘는 `.mlpx`에 그대로 적히는 코드값(`z.enum`의 목록)이고,
**로케일 문구는 여기 안 걸린다.**

**번호는 순서가 아니다. 번호를 다시 매기지 않는다.**

| 순서 | 단계 | 무엇을 |
|---|---|---|
| 끝 | **점검 (교사용 화면)** | 닫혔다. 화면은 `architecture.md` §8.21 |
| 끝 | **학습 병렬화** | 닫혔다 |
| 끝 | **두 탭 잠금** | 닫혔다 |
| 끝 | **V11 · R6~R9** | 코드 감사 — 닫혔다 |
| 끝 | **V10** | 랜딩과 행정 — 닫혔다 |
| 끝 | **V12** | 결정된 대기열 — 닫혔다 |
| 끝 | **데이터 시각화** | 닫혔다. **표 경로에만 있다** (`open-decisions.md` "44. 데이터 화면의 시각화") |
| 다음 학기 | **V6** | 자가호스팅 백엔드 (도커) |
| 다음 학기 | **V8 → V9** | 음성 분류 → 텍스트 분류 — V6과 함께 간다 |

- **우선순위 기준은 하나다 — 지금 학생이 무엇을 잃는가.**
- **결정문이 있고 구현이 없는 것은 단계로 세워 이 표에 올린다.** 대기열이 표 밖에 있으면 없는 것이 된다.
- **배포 뒤 목록은 이 순서 바깥에 있다.** V5에서 넘긴 둘은 닫혔고, 남은 일은 `open-decisions.md`의
  미결정 항목과 저장소의 이슈가 갖는다.
- 옛 이름 `교사용 화면`은 지금의 `점검`이다 (`terms.md`의 `점검 (Inspect)`).

## 단계별 기록

단계마다의 기록(V1~V12 — V12의 상한 off 스위치와 학습 예상 시간까지, 감사 라운드)은 `docs/cases/roadmap.md`에 있다.

## 명시적으로 범위 밖

- 사용자 계정 / 로그인 / 서버 측 프로젝트 목록
- 실시간 협업 편집
- 워크플로 노드 편집기 (Orange3 방식을 따라가지 않는다)
- **투영 계열 시각화** (FreeViz · Linear Projection · Radviz)와 **바이올린 플롯** —
  `open-decisions.md` "44. 데이터 화면의 시각화"
- 모델 파일의 **세션을 넘어선 서버 보관** (모델은 클라이언트로 내려보내고 `.mlpx`에 담긴다)
- **우리가 운영하는 공용 백엔드** (CLAUDE.md §1.1 · `architecture.md` §7.1)
- **HMAC 서명·전자서명 기반 무결성** (`mlpx-spec.md` §7.1)

## 구현 순서 (권장)

- **포맷과 규칙이 UI보다 먼저다.** 흔들리면 그 위에 쌓은 모든 게 흔들린다.
- **백엔드(V6)는 마지막이다.** 서버를 먼저 만들면 "서버가 있어야 되는 기능"이 슬며시 생긴다.
- 지나온 순서와 단계마다 무엇이 섰는지는 `docs/cases/roadmap.md` 같은 절.

```
프로젝트 목록·열기 → 데이터 업로드·미리보기 → 전처리(타깃·특성·다듬기·나누기)
→ 학습(유형·모델·진행 표시) → 결과 분석 → 예측 → 포트폴리오 편집 → 교사용 화면
```

## 원칙 이탈 점검 (작업이 길어질 때 주기적으로)

- 서버에 상태가 남는 코드가 생겼는가
- 백엔드가 자연어 문자열을 반환하는 곳이 있는가
- 프런트엔드에 `t()`를 거치지 않은 문자열 리터럴이 있는가
- 임시 파일이 삭제되지 않는 경로가 있는가
- 코드가 출처여야 할 값이 문서에 복사돼 있는가
