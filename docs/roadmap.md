# 범위와 로드맵

기능을 만들기 전에 "이게 지금 범위인가"를 여기서 확인한다. **규칙만 적는다.** 배포판마다
나간 것, 단계의 경위, 감사가 남긴 것은 `docs/cases/roadmap.md`에 있다.

## 지금 어디인가 (2026-09-03)

**지금은 기능 국면이다.** 감사는 그만둔 것이 아니라 주기의 한 국면이고 — `기능 개발 → 감사`를
오가며 — **여는 시점은 사용자가 정한다.** 국면마다 무엇을 하는지는 `workflow.md` §3의
"감사가 안 도는 동안"과 "감사 국면은 어떻게 도는가"가 갖는다. 다음 감사는 **기능을 한 덩어리
끝낸 뒤의 diff 감사**다.

**재야 할 것** — 코드는 다 있고 사람이 브라우저에서 돌리는 일만 남았다.

| 무엇 | 돌릴 것 | 남은 것 |
|---|---|---|
| 사진 기준표 (`baseline.image`) | `tools/bench.html` [전부 훑기] | 나이브베이즈·로지스틱·KNN·K-평균 넷. **개발 PC 크롬에서 잰다** |

**감사가 안 본 채로 남은 경계** — 거기를 만질 때 먼저 볼 자리다.

- **두 시점을 견줘야 잡히는 것 — 갱신 누락과 상태 이력.**
- **비결정적 실행에서만 나는 경합.** 경합을 겨누는 요청서는 **"순서를 강제해 재현하라"를 명시한다.**
- 실기기·실측·스크린 리더는 `rule-coverage.md`가 감사 밖으로 적어 두었다.

**파일에 적히는 어휘를 하나 바꾸면 `FORMAT_VERSION` 증가와 마이그레이션이 붙는다**
(`tests/schema-version.spec.ts`). 어휘는 `.mlpx`에 그대로 적히는 코드값(`z.enum`의 목록)이고,
**로케일 문구는 여기 안 걸린다.**

**번호는 순서가 아니다. 번호를 다시 매기지 않는다.**

| 순서 | 단계 | 무엇을 |
|---|---|---|
| 끝 | **점검 (교사용 화면)** | 닫혔다. 화면은 `architecture.md` §8.21 |
| 끝 | **학습 병렬화** | 닫혔다 |
| 끝 | **두 탭 잠금** | 닫혔다 |
| 끝 | **V11 · R6~R9** | 코드 감사 — 닫혔다 |
| 끝 | **V10** | 랜딩과 행정 — 닫혔다 |
| 끝 | **V12** | 결정된 대기열 — 닫혔다 |
| 끝 | **데이터 시각화** | 닫혔다. **표 경로에만 있다** (`open-decisions.md` "44. 데이터 화면의 시각화") |
| 다음 학기 | **V6** | 자가호스팅 백엔드 (도커) |
| 다음 학기 | **V8 → V9** | 음성 분류 → 텍스트 분류 — V6과 함께 간다 |

- **우선순위 기준은 하나다 — 지금 학생이 무엇을 잃는가.**
- **결정문이 있고 구현이 없는 것은 단계로 세워 이 표에 올린다.** 대기열이 표 밖에 있으면 없는 것이 된다.
- **배포 뒤 목록은 이 순서 바깥에 있다.** V5에서 넘긴 둘은 닫혔고, 남은 일은 `open-decisions.md`의
  미결정 항목과 저장소의 이슈가 갖는다.
- 옛 이름 `교사용 화면`은 지금의 `점검`이다 (`terms.md`의 `점검 (Inspect)`).

### V12 — 결정된 대기열

[`roadmap/04-v12.md`](roadmap/04-v12.md)

- **V12 — 결정된 대기열 — 2026-09-01에 닫혔다 (2026-08-29에 열었다)**
  - ~~**상한 off 스위치와 학습 예상 시간 — 짝이라 함께 낸다**~~ — 예상 시간은 `0.13.0`으로,
    **스위치는 2026-09-01에 나갔다.** 짝의 한쪽이 **사진에는 아직 없다** (아래 줄)
  - **알고리즘 상한을 다시 잰다 — 이제 시간이 아니라 실패를 잰다** (2026-09-01,
    코드 소유자). `MLJS_*_ROW_LIMIT` 여덟이 전부 **시간**으로 정해져 있는데, 그건
    예상 시간이 없던 시절의 보호막이다. **막을 것은 느린 것이 아니라 실패하는 것**이고
    (open-decisions.md "그러면 상한은 시간으로 정하는 것이 아니다"), 느린 것은 예상이
    말하고 학생이 정한다. 재는 도구는 `frontend/tools/bench.html`이다.
    **셋을 2026-09-01에 올렸다** — SVM 3,000→8,000 · KNN 10,000→50,000 ·
    트리 20,000→50,000. **랜덤포레스트만 남았고**, 그것을 재려면 하니스를 워커로
    옮기는 편이 낫다 — 지금은 메인 스레드라 "브라우저가 멈춘다"와 "계산이 실패한다"가
    구분되지 않는다. **그 이사를 2026-09-01에 했다** — 점마다 워커를 새로 띄우고,
    못 끝낸 방식을 셋으로 갈라 적는다
  - **사진 칸 일곱도 같은 질문을 받는다** (2026-09-01). `MLJS_IMAGE_*_ROW_LIMIT`은
    표 쪽을 다시 재는 동안 손대지 않아 **2026-08-14의 근거 그대로** 남았고, 그 근거도
    시간이다(*"500장 113초"*). **하니스에 사진 사다리가 하나도 없던 것이 이유다** —
    재려면 코드를 먼저 써야 했다. 사다리 일곱을 세웠고(`tests/bench-rules.spec.ts`가
    이제 등록부의 칸마다 사다리를 요구한다), 남은 것은 실측이다
  - **K-평균의 10만 행은 그대로 둔다** (2026-09-01, 코드 소유자). 평가에 천장이 생겨
    상한이 견딘다
- **닫은 근거 — 남은 것이 코드가 아니라 실측이다 (2026-09-01)** — 이 절의 입회 조건은
  *"결정은 섰는데 코드가 없는 것"*이었고, 남은 셋(랜덤포레스트 상한 · 사진 칸 일곱 ·
  사진 기준표)은 하니스와 사다리가 다 서서 **돌리는 일만 남았다.** 여기 두면 영영 안
  닫히는 칸이 되므로 위 **`재야 할 것`**으로 옮겼다

## 구현 순서 (권장)

- **포맷과 규칙이 UI보다 먼저다.** 흔들리면 그 위에 쌓은 모든 게 흔들린다.
- **백엔드(V6)는 마지막이다.** 서버를 먼저 만들면 "서버가 있어야 되는 기능"이 슬며시 생긴다.
- 지나온 순서와 단계마다 무엇이 섰는지는 `docs/cases/roadmap.md` 같은 절.

```
프로젝트 목록·열기 → 데이터 업로드·미리보기 → 전처리(타깃·특성·다듬기·나누기)
→ 학습(유형·모델·진행 표시) → 결과 분석 → 예측 → 포트폴리오 편집 → 교사용 화면
```

## 원칙 이탈 점검 (작업이 길어질 때 주기적으로)

- 서버에 상태가 남는 코드가 생겼는가
- 백엔드가 자연어 문자열을 반환하는 곳이 있는가
- 프런트엔드에 `t()`를 거치지 않은 문자열 리터럴이 있는가
- 임시 파일이 삭제되지 않는 경로가 있는가
- 코드가 출처여야 할 값이 문서에 복사돼 있는가
