# 범위와 로드맵

기능을 만들기 전에 "이게 지금 범위인가"를 여기서 확인한다.

## V1 (MVP) — 표 데이터 분류와 회귀

| 영역 | 내용 |
|---|---|
| 프로젝트 | 새 프로젝트 / 저장(`.mlpx`) / 열기 / IndexedDB 자동 저장 |
| 데이터 | CSV·엑셀 업로드, 시트 선택, 미리보기, 컬럼 타입 추론, 결측치 표시 |
| 전처리 | 결측치 처리, 스케일링, 범주형 인코딩 |
| 알고리즘 | Decision Tree, Random Forest, Logistic Regression, KNN, SVM, Naive Bayes, Linear Regression |
| 평가 | 분류 — 정확도, Precision, Recall, F1, 혼동 행렬 · 회귀 — R², RMSE, MAE |
| 학습 | **브라우저에서 실행.** 서버 없이 동작한다 → `architecture.md` §3 |
| 예측 | 새 값을 입력해 예측 (모델은 `.mlpx`에 담긴다 → `mlpx-spec.md` §5) |
| 배포 | GitHub Pages 정적 배포 — **워크플로는 있고, 실제 배포는 V7이다** (감사 뒤) |

**브라우저 학습이 V1에 들어온다.** 예전에는 V1.5로 미뤄져 있었지만, 공식 배포에 서버가
없기로 정해지면서(CLAUDE.md §1.1) **V1이 성립하는 조건**이 됐다.
엔진은 둘이다 — 순수 JS가 기본이고 scikit-learn은 학생이 켜는 선택지다
(`open-decisions.md` "브라우저 학습 엔진은 둘 다 간다").

**회귀도 V1에 들어온다** (2026-08-06에 문서를 사실에 맞췄다. 코드는 그 전부터 그랬다).
원래 V2였는데 앞당긴 이유가 기능이 아니라 **구조**다.

- **기계학습 유형이 처음부터 여럿이어야 축이 축으로 산다.** 분류 하나만 두면 유형은
  이름만 축이고 실제로는 상수다. 그 위에 쌓은 등록부·화면·지표는 전부 "하나뿐인 경우"에
  맞춰지고, **회귀를 넣는 순간 구조를 바꿔야 한다.** 군집·딥러닝을 더할 때마다 같은 일이
  반복된다.
- 실제로 이 축 하나가 여러 자리를 갈랐다 — 지표 등록부(`EVALUATORS`와 표시 등록부),
  타깃 자료형 판정(`requiredTargetKind`), 결과 화면의 지표 열, 알고리즘 등록부의
  `taskTypes`. **둘로 돌려 봤기 때문에 셋째를 더하는 일이 "등록부에 줄 하나"가 됐다.**
- CSV를 올린 학생에게 **고를 것이 실제로 여럿 있어야 한다**는 이유도 있다. 숫자 열을
  예측하려는 학생에게 분류만 주면 도구가 답을 못 한다.

**군집(V3)은 여전히 나중이다.** 알고리즘이 하나도 없고, 타깃이 없다는 점에서 축을 한 겹
더 건드린다 — 문구를 미리 쓰지 말라는 규칙이 거기서 나온다 (`architecture.md` §8.10).

**포트폴리오 화면과 교사용 화면은 V1에서 뺐다 (2026-08-07).** 둘 다 앞에 결정이 걸려
있고(`open-decisions.md` #23·#12), 그것보다 **모든 유형과 데이터 종류가 실제로 도는
것이 먼저**라고 판단했다. V5로 옮겼다.

## V2 — 감사

**만드는 단계가 아니라 점검하는 단계다.** 화면이 다 선 지금이 적기다.

- **프런트엔드 감사** — 사용자가 직접 화면을 보며 (완료: 2026-08-07)
- **1단계 · ml.js 수치 정확성** (완료: 2026-08-11) — 순수 JS 엔진을 scikit-learn과
  대조했다. **조용히 틀린 숫자를 내던 자리 셋이 나왔다** — 벤더링한 SMO의 상계 수식이
  표준과 달라 잡음 있는 600행부터 가중치가 발산했고(원본 `ml-svm`의 결함), 로지스틱
  회귀가 교실 데이터에서 기준선 이하였으며(솔버를 sklearn 구조로 교체), KNN의 득표
  동점 규약이 sklearn과 달랐다. **셋 다 붓꽃 한 벌로는 안 걸리는 종류였다.**
  남은 것은 `tests/sklearn-parity.spec.ts` — 파이썬 없이 도는 CI 관문이고, 옛 코드를
  넣으면 셋 다 빨개진다.
- **2단계 · 명세와 코드의 정합성** (완료: 2026-08-11) — `docs/`의 규칙이 실제 코드와
  어긋난 곳을 찾았다. 에러 코드 넷 누락, Node 요구 버전 불일치, 죽은 절 참조, 그리고
  **1단계가 뒤집은 숫자를 근거로 든 문장 여럿.** 트립와이어에 일부러 위반을 심어
  **검사가 실제로 우는지**까지 확인했다. **문서를 통독해야 나오는 종류였다** — 가리켜진
  절만 읽은 1왕복에서는 절반이 안 걸렸다.

파일 자체를 검증하는 실물 `.mlpx` 감사는 여기가 아니라 **V7**이다 — 포맷을 건드리는
작업(V4 이미지, V5 포트폴리오 첨부)이 그 앞에 있기 때문이다.

- **3단계 · 스키마 감사** (완료: 2026-08-11) — 스키마 표면 열 곳을 "지금 확정하지 않으면
  나중에 무엇이 함께 깨지는가"로 물었고, **확정해야 하는 것은 하나도 없었다.** 배포 전이라
  모든 변경이 "파일을 새로 만들면 끝"이고, 미룰 때 마이그레이션이 붙거나 V3·V4가 가정
  위에 서는 요소가 없었다. 본 안건이던 **다중 타깃은 `open-decisions.md` #27에 결정됨으로
  닫혔다 — 안 한다.** 못 만들어서가 아니라 **단일 타깃이 교육적으로 옳은 형태**여서다.
- **4단계 · 한국어 용어 감사** (완료: 2026-08-11) — 두 패스로 나눴다. 먼저 **용어 사전**을
  세우고(`docs/terms.md`), 그 사전을 옆에 놓고 화면 문구를 대조했다. 나눈 이유는 한 패스로
  하면 **기억에 의존하게 되어 그럴듯한 오답이 사실처럼 섞이기** 때문이다.
  낱말이 갈린 열 곳은 코드 소유자가 직접 골랐고, 그 결정을 **문서 전체가 따라가도록
  47곳을 함께 고쳤다.** `학습`을 동작으로 쓰는 자리(단계 이름·버튼·진행 문구)를
  `훈련`으로 바꿀지는 **남은 안건이다** — `기계학습`처럼 바꾸면 안 되는 자리가 섞여 있다.

**V2는 여기서 끝난다.** 실물 `.mlpx` 감사는 V7이다.

## V3 — 군집화 (K-means)

**축이 세 값을 다 갖게 하는 단계다.** 분류·회귀만으로는 `taskType`이 이름만 축이다.

**코드 감사는 닫혔다** (2026-08-11). 지적 22건 → 수정 8단계 → 감사자 독립 재검증까지
끝났다. 잡힌 것 중 셋이 **조용히 틀린 숫자와 조용히 열린 경로**였다 — 빈 군집 중심점이
원점으로 가던 것, 중심점과 군집 번호가 한 스텝 어긋나던 것, 남의 `.mlpx`의 키가
`runPython()`에 닿던 것. 재검증이 새로 연 것은 문서 문장의 강도 하나뿐이었다.
**실물 `.mlpx` 감사는 V2와 마찬가지로 여기가 아니라 V7이다.**

**끝난 것** (2026-08-11, 감사와 그 수정까지 포함):

- **엔진** — 직접 짰다(`ml/engines/mljs-kmeans.ts`). K-Means++ 초기화 + Lloyd 반복이고,
  빈 군집은 sklearn처럼 재배치한다. 근거는 `open-decisions.md` "군집화의 핵심 결정 넷"
- **군집 지표** — 실루엣 계수와 이너셔. 시그니처가 달라 `EVALUATORS`가 아니라
  `CLUSTER_EVALUATOR`가 따로 산다(`architecture.md` §3.7)
- **모델 형식** `mlpx-kmeans-v1` + 해석기 등록 (여덟 번째 형식, `mlpx-spec.md` §5.10)
- **mljs 행 상한 실측** — 10만 행 k=20이 112회 반복 6.4초. 데이터셋 천장을 그대로 쓴다
- **군집에는 학습/평가 나누기를 하지 않는다** — 전체 데이터로 학습하고 전체로 채점한다
- 하이퍼파라미터 `n_clusters`와 그 문구
- **scikit-learn(Pyodide) 어댑터** — 등록은 끝났다. 남은 것은 아래 "워커 배선"이다

**남은 것:**

- **산점도** — 군집 결과를 표로만 보여주면 학생은 아무것도 못 본다. **군집은 그림으로
  봐야 뜻이 생기는 유일한 유형이다.** 특성이 셋을 넘으면 축을 골라야 하고(Orange3 방식),
  차원 축소가 필요해진다면 **여기서 파생된다**. **설계는 닫혔다** — 중심점 표시·축 선택
  자리·색과 모양·재료의 출처가 `open-decisions.md` #28에 있고, 실측이 남은 것은 그릴
  점의 상한 하나다 (#28-5)
- 예측 화면에서 군집의 "답"(군집 번호)을 어떻게 말할지
- **Pyodide 워커 배선** — `setPyodide()`를 부르는 코드가 아직 없어 어댑터가 도달하지
  않는다. 그때 아래의 `pyodide-sklearn` 행 상한도 함께 잰다

준비된 것: 타깃 없는 흐름(`FACTS_NOT_IN_TASK`), 세 값짜리 `TASK_TYPES`, 등록부 한 줄로
화면이 따라오는 구조.

**scikit-learn(Pyodide) 엔진도 여기서 함께 붙인다 (2026-08-07). 어댑터는 붙었다
(2026-08-11).**

`ml/engines/index.ts`의 `ENGINES`에 항목이 **`mljs` 하나뿐이던 상태가 여기서 끝났다.**
실행 위치 축은 값이 셋인데 구현이 하나면 **축이 이름만 축이다** — 회귀를 V1로 당긴
논리와 같다(유형이 처음부터 여럿이어야 축이 축으로 산다). K-평균을 새로 등록하면서
두 엔진을 동시에 붙였고, 그 축이 처음으로 실물 둘을 갖는다.

**다만 화면은 아직 학생에게 반쯤 틀린 말을 한다.** 알고리즘 여덟 줄이 전부
`'pyodide-sklearn': true`라고 선언하는데(축이 말하는 것은 "sklearn에 이 알고리즘이
있다"이고 그건 참이다) **워커가 Pyodide를 부팅해 `setPyodide()`로 넣어 주는 배선이
없어서** `runtimeOptions`가 `ENGINE_NOT_READY`("엔진이 준비되지 않았습니다")를 준다.
그건 "준비하면 된다"는 뜻인데 **아직 준비할 방법이 없다.** 이유를 주는 목적이 학생이
무엇을 하면 되는지 알게 하는 것인데(§9.4) 그 자리는 여전히 반대다.

그때 정할 것: **준비 상태를 엔진 등록부에서 끌어올 것인가.** 그러면 어댑터가 들어오는
순간 문구가 저절로 맞아진다. 다만 `ml/backend.ts`가 `ENGINES`를 import하면
**학습 라이브러리가 첫 화면 번들에 들어온다** — `ml/selection.ts`가 같은 이유로 엔진을
안 부른다. 가벼운 목록을 따로 둘지, 판정을 위로 올릴지가 그 자리의 결정이다.

**그리고 그때 행 상한을 재서 등록부의 `pyodide-sklearn` 칸을 채운다.** 지금 그 칸은
알고리즘 여덟 줄 전부 `UNMEASURED`이고(`ml/algorithms.ts`), 그건 빠뜨림이 아니라
**아직 못 재는 사실**이다 — 어댑터는 있지만 Pyodide를 띄우는 배선이 없다. 숫자를 미리 지어 넣지
않는 이유는 둘이다. 그 칸은 카드가 `ENGINE_NOT_READY`로 잠기므로 **학생에게 닿지
않고**, 지어낸 값은 옆 칸의 실측값과 나란히 앉아 실측처럼 보인다.

**재는 방법은 순수 JS 때와 같다** (`open-decisions.md` #13의 "쟀다 (2026-08-07)"에 표와
조건이 있다. 이 저장소가 도는 PC가 그 실측 기기다). 다만 **Node의 Pyodide로 재면 안 된다** —
학생이 만나는 것은 브라우저 워커이고, 거기서 갈리는 것이 정확히 메모리다. `pyodide-sklearn`은
순수 JS보다 빠를 것이므로 **상한이 올라갈 가능성이 높다.** 그때까지는 전역 기본값을
따르므로 보수적으로 틀려 있다.

## V6 — 자가호스팅 백엔드

학교가 컴퓨터실에 도커로 설치해 무거운 연산을 넘길 수 있게 한다.
**우리는 이것을 호스팅하지 않는다.** 없어도 앞의 모든 기능이 동작해야 한다.

**이미지를 브라우저로 해 본 뒤다.** 서버를 먼저 만들면 "서버가 있어야 되는 기능"이
슬며시 생긴다.

## V7 — 실물 `.mlpx` 감사, 그리고 배포

**포맷을 건드리는 작업이 전부 앞에 있다** — V4의 이미지 담기, V5의 포트폴리오 첨부.
되돌리기 비싼 것을 지나가기 전에 본다는 원칙에 맞으려면 여기가 맞다.

**배포는 감사 뒤다.** `tests/schema-version.spec.ts`의 `RELEASED`를 `true`로 뒤집는
순간부터 어휘를 바꾸려면 `formatVersion` 증가와 마이그레이션이 붙는다 —
**감사가 포맷을 고치라고 할 수 있는 마지막 기회가 배포 직전이다.**

**코드가 다 돼도 배포가 안 되는 것 둘이 남는다.** 전국 단위 학교 배포라 기술적
완성도만으로는 문이 안 열린다.

- **개인정보취급안내** — 학생·학부모·교사가 읽는 안내가 있어야 한다. `docs/privacy.md`는
  우리끼리 보는 정책이고 **바깥에 내놓는 안내는 아직 없다.** 서버가 없어 학생 데이터가
  브라우저를 떠나지 않는다는 사실(CLAUDE.md §1.1·§1.2)이 여기서 가장 강한 답이다 —
  "수집하지 않는다"를 쓸 수 있는 상태를 만들어 둔 것이 그 설계의 값이다.
- **에듀넷 학습지원 소프트웨어 체크리스트** — 학교 보급을 위한 제출물이다.

**둘 다 랜딩 페이지 작업과 한 덩어리다.** 랜딩은 별도 저장소(`teacher-utility-kit`)이고
그 갈림은 `open-decisions.md` #10에 있다 — 안내가 앉을 자리도 그쪽이다.

## V8 이후

V8 음성 분류 → V9 텍스트 분류. **텍스트는 안 와도 이 프로젝트는 성공이다.**

(V2였던 회귀는 위 이유로 V1에 들어갔고, V4였던 차원 축소는 지웠다 — 이름만 남은 단계를
두면 다음 사람이 "이걸 언제 하지"를 반복해서 묻는다. 필요해지면 V3에서 파생된다.
**번호가 두 번 흔들렸으므로 옛 논의를 찾을 때는 날짜로 찾는 편이 빠르다.**)

## 구현 순서 (권장)

포맷과 규칙이 흔들리면 그 위에 쌓은 모든 게 흔들린다. UI보다 먼저 만든다.

1. **저장소 골격** — 디렉터리, `pyproject.toml`, `package.json`, `.gitignore`, `docker-compose.yml`
2. **i18n 기반** — `errors.py`(StrEnum + `AppError` + 핸들러), 로케일 파일, `i18n.ts`, CI 검사
3. **`.mlpx` 포맷** — `schema.ts` / `format.ts` / `migrate.ts` / `storage.ts` + 왕복 테스트 ✅
4. **표 파일 파싱** — CSV·엑셀 읽기, 시트 선택, 인코딩 판정 ✅
5. **무결성 해시** — `hashes.json`(엔트리별 + `contentHash`), 재실행 대조의 토대 ✅
6. **브라우저 학습 엔진** — 여기가 V1의 심장이다. 순수 JS 완료, 남은 것은 아래 둘
   - 분할 / 전처리 / 알고리즘·지표 등록부 / ml.js 엔진 ✅
   - 실험 실행 — 엔진 등록부 + `runExperiment`. 지표까지 나온다 ✅
   - **모델 직렬화** ✅ — 형식·해석기 등록부와 **일곱 형식 전부**
     (`mlpx-tree-v1`·`linear-v1`·`linear-v2`·`naive-bayes-v1`·`linear-regression-v1`·
     `reference-v1`·`svm-v1`). #21의 부채 셋도 닫혔다
   - **Web Worker 껍데기** — 순수 함수들이 워커 뒤에 있다 ✅ (`ml/worker/`).
     부르는 화면은 학습 화면과 함께 온다
   - scikit-learn(Pyodide) 엔진은 **등록만 추가하면 된다. 시점은 V3(군집)이다** —
     거기서 K-means와 함께 붙여야 실행 위치 축이 처음으로 실물 둘을 갖는다
7. **프런트엔드 UI** — 아래 순서로, 화면 하나씩. 틀은 `architecture.md` §8
   - **셸** — 도구 막대 / 레일 / 작업 공간 / 상태 표시줄 ✅ (§8.6)
   - **프로젝트 목록·만들기·열기·`.mlpx` 저장·불러오기·자동 저장** ✅
   - **데이터 화면** — CSV·엑셀 불러오기, 시트 선택, 미리보기, 열 요약, 정본 확정 ✅
   - **UX 리팩터** ✅ (2026-08-05). 강의노트형이던 첫 UI를 작업실로 바꿨다. 색은 그대로
     두고 밀도와 크롬만 바꿨다 — 겉모습이 `styles/theme.css`의 토큰 뒤에 있어 값과
     컴포넌트 내부만 바뀌었다 (§8.4). 어두운 배색도 그 토큰 덕에 값 한 겹으로 끝났다.
   - **전처리 화면** — 타깃·특성·결측치·스케일링·인코딩·분할 ✅ (2026-08-05).
     **데이터 얘기만 담는다** — 기계학습 유형과 모델 선정은 학습 화면이다
     (`open-decisions.md` "기계학습 유형은 모델을 고르는 자리에서 고른다")
   - **학습 화면** ✅ (2026-08-05). 유형 → 모델 선정 → 실행 방법이 **한 카드 안의 세 축**이고
     서로를 좁힌다 (`architecture.md` §8.12). [학습]은 워커에서 돌고 진행 표시는 모델
     단위이며 취소가 된다. 끝나도 결과 화면으로 옮기지 않는다 — 설정을 바꿔가며 반복
     학습하는 것이 이 도구의 핵심 활동이다.
   - **결과 화면** ✅ (2026-08-06). 순위표가 아니라 **변경 이력**이다 — 왼쪽 세로줄이
     학습 기록이고 오른쪽이 고른 실험의 속이다 (`architecture.md` §8.13). 지표 표시
     등록부와 변경 서술(`ml/metrics.ts`·`ml/changes.ts`)이 화면 밖에 있다
   - **결과 화면 2차 손질** ✅ (2026-08-07). 사람의 감사를 받고 고친 것들이다 —
     그 run에 먹인 하이퍼파라미터를 속 맨 위에(§8.13), 지표 이름과 혼동 행렬 칸을 눌러
     여는 용어 설명(수식 포함, §8.13), **특이도**를 범주별 점수에 추가(`mlpx-spec.md` §4),
     그리고 강조가 없는 차이를 지어내던 버그. 학습 화면도 함께 고쳤다 — 담은 모델마다
     대기·학습 중·완료·실패를 보인다 (§8.17)
   - **데이터 화면의 열 검사기를 표 옆으로** ✅ (2026-08-06). 접어 두면 펼칠 때 표가
     먹혔다 (`architecture.md` §8.9). 같은 날 낮은 창에서 표가 잘리던 버그도 고쳤고
     규칙이 됐다 (§8.14)
   - **예측 화면** ✅ (2026-08-06). 왼쪽이 입력 한 줄, 오른쪽이 모델들의 답이다
     (`architecture.md` §8.13.1). **아직 사람의 감사를 안 받았다.**
     - **순수 JS SVM** ✅ (2026-08-06). 솔버는 벤더링한 SMO이고(`ml/engines/svm-smo.ts`)
       모델은 `mlpx-svm-v1`이다. 상한이 알고리즘마다 갈리는 자리가 여기서 처음
       생겼고(`MLJS_SVM_ROW_LIMIT`), 수렴하지 못한 학습은 실패가 아니라 `run.warning`이다
       (`mlpx-spec.md` §5.9)
     - 화면보다 먼저 만들 **이음매 둘** ✅ (2026-08-06). `ml/predict.ts`의 학습 행
       만들기와 입력 한 줄 벡터화, 그리고 파일에서 읽은 전처리기를 검증하는
       `parsePreprocessor`. 확인하는 것은 "던지는가"가 아니라 **두 이음매가 같은
       좌표계에 있는가**다 (`architecture.md` §8.13.1)
   - **여기까지가 V1이다 (2026-08-07).** 포트폴리오 화면·교사용 화면·키보드·패널 크기
     조절은 **V5로 옮겼다** — 앞에 결정이 걸려 있고, 그보다 모든 유형과 데이터 종류가
     실제로 도는 것이 먼저다
   - **등록부와 축** ✅ (2026-08-07). 데이터 종류 × 과제 유형 × 실행 위치를 등록부가
     선언하고 **축이 늘면 컴파일이 깨진다** (`architecture.md` §9·§10). 지표 상세 패널과
     전처리 작업 공간도 등록부에서 나온다. V3(군집)과 V4(이미지)가 이 장치를 처음 쓴다
   - **재실행 대조의 로직** ✅ (2026-08-06). `ml/reproduce.ts` — 파일의 설정과 분할로
     다시 돌려 지표를 견준다. 엔진을 넘지 않고, **허용 오차는 정하지 않는다**
     (`open-decisions.md` #12). 교사용 화면은 그 결정 뒤다
8. **자가호스팅 백엔드 (V6)** — `config` / `diskguard` / `lifecycle` / `quota` / `jobs` / `ml` / `ws`
   **이미지를 브라우저로 해 본 뒤다.** 없어도 되는 것을 먼저 만들지 않는다.

```
프로젝트 목록·열기 → 데이터 업로드·미리보기 → 전처리(타깃·특성·다듬기·나누기)
→ 학습(유형·모델·진행 표시) → 결과 분석 → 예측 → 포트폴리오 편집 → 교사용 화면
```

**백엔드가 5번에서 8번으로 내려갔다.** 서버 없이 동작하는 것이 V1의 정의이므로,
서버를 먼저 만들면 "서버가 있어야 되는 기능"이 슬며시 생긴다.

## 원칙 이탈 점검 (작업이 길어질 때 주기적으로)

- 서버에 상태가 남는 코드가 생겼는가
- 백엔드가 자연어 문자열을 반환하는 곳이 있는가
- 프런트엔드에 `t()`를 거치지 않은 문자열 리터럴이 있는가
- 임시 파일이 삭제되지 않는 경로가 있는가
- 코드가 출처여야 할 값이 문서에 복사돼 있는가
