# 인수 테스트

> 코드 소유자가 **"인수 테스트 시작"**이라고 말하면 연다 → `docs/workflow.md` §3 "인수 테스트 국면".
> 몫은 둘이다. §1은 에이전트가 브라우저로, §2는 소유자가 실기기로 한다. 같은 시각에 돌고, 판정은 합쳐서 한 번이다.

## 0. 여는 법과 보고

- [ ] §1을 **세션 스크래치패드**에 복사하고, 복사본에 `- [x]`로 체크한다. 정본은 고치지 않는다.
- [ ] 같은 턴에 §2를 채팅으로 소유자에게 그대로 보인다. 소유자는 항목마다 ✅ / ❌ + 한 줄로 답한다.
- [ ] 데이터를 만든다: `node frontend/scripts/acceptance-fixtures.mjs <스크래치패드>/fixtures`. 손으로 만들지 않는다.
- [ ] 대상 커밋(`git rev-parse --short HEAD`)과 작업 트리가 깨끗한지 적는다.
- **한 세션에서 끝낸다.** 끊기면 처음부터 다시 한다. 체크 상태는 남기지 않는다.
- 찾기만 하고 고치지 않는다.
- **CI가 지키는 것은 넣지 않는다** → `docs/rule-coverage.md`. 여기에는 브라우저나 기기에서만 드러나는 것(화면 폭·내려받기·저장소·워커·체감)만 둔다.
- 보고는 채팅으로 한다. 형식은 `docs/workflow.md` §3 "보고서에 반드시 있어야 하는 것"을 따른다.
  항목마다 ✅ / ❌ / **못 한 것**(이유). ❌에는 재현 단계·폭·실측값·의심 파일을 붙인다.
  두 몫을 합쳐 한 표로 낸다. 고칠지는 소유자가 정한다.

## 1. 브라우저 몫

에이전트가 한다. 개발 서버는 `.claude/launch.json`으로 띄우고(Bash로 띄우지 않는다) built-in 브라우저를 쓴다.
폭 세 가지를 돈다: 데스크톱 · `tablet` · `mobile` 프리셋. 끝나면 `desktop`으로 되돌린다.
확인은 `read_page`·`get_page_text`·콘솔·네트워크로, 스크린샷은 의심 자리만.

### 1.1 첫 화면

- [ ] 첫 화면이 뜨고 콘솔 에러가 0건이다.
- [ ] 서버 옵션이 **이유와 함께** 비활성화된다.
- [ ] 프로젝트 목록: 이름 바꾸기·삭제·프로젝트 사이 전환이 된다.

### 1.2 표 프로젝트

- [ ] 새 표 프로젝트를 만들고 `table.csv`를 불러온다.
- [ ] 불러오기 → 열 검사 → 차트 대화상자가 열리고 닫힌다.
- [ ] 전처리: 빈칸 처리와 범주 인코딩을 하나씩 적용한다. 잠긴 선택지에는 이유가 보인다.
- [ ] 학습: 모델을 둘 이상 골라 학습한다. 진행 중 버튼이 동작 상태를 보이고, 끝나면 풀린다.
- [ ] 결과: 점수 표·혼동 행렬(분류)·범주별 점수가 각 폭에서 보인다(가로 스크롤 뒤에 숨지 않는다).
- [ ] 설정 하나를 바꿔 두 번째 실험을 돌린다. 실험 목록에 둘이 쌓이고 바뀐 점 목록이 맞다.
- [ ] 예측: 한 행을 넣어 예측값이 나온다. 여러 행을 한꺼번에 예측하고 필터로 걸러 본다.
- [ ] 포트폴리오: 답을 적고 완성본 보기를 연다. 긴 답(공백 없는 150자+)에도 문서 폭이 넘치지 않는다.
- [ ] 포트폴리오: 템플릿을 고르고 사진 카드를 넣는다. 용량 표시가 따라 움직인다.
- [ ] 새로고침 후 프로젝트가 IndexedDB에서 그대로 돌아온다.

### 1.3 이미지 프로젝트

- [ ] 새 이미지 프로젝트를 만들고 범주를 `images/`의 폴더(숫자 0·1·2)대로 만들고 사진을 넣는다.
- [ ] 사진이 생긴 뒤에도 각 폭에서 범주 카드가 넘치지 않는다.
- [ ] 이미지 전처리 화면에서 설정 하나를 바꾼다.
- [ ] 학습 → 결과 → 예측을 표 프로젝트처럼 한 바퀴 돈다.
- [ ] 군집(범주 없이 묶기)을 돌려 예측 화면에 이웃 사진과 근거가 보인다.

### 1.4 학습 엔진 적재

- [ ] 첫 학습에서 엔진(Pyodide)과 이미지 백본을 받아 온다. 진행 표시가 보이고 네트워크에 실패가 없다.
- [ ] 새로고침 뒤 두 번째 학습은 다시 받지 않는다(네트워크에서 캐시로 온다).

### 1.5 과제 종류

- [ ] 표 회귀: `table.csv`의 `weight`를 목표로 학습한다. 결과에 회귀 점수가 나오고 분류 전용 판은 없다.
- [ ] 표 군집: 목표 없이 학습해 결과와 예측 화면이 뜬다.
- [ ] `table.csv`를 엑셀로 `.xlsx`로 저장해 불러온다(사람이 만들어 둔 파일이 없으면 못 한 것에 적는다).

### 1.6 `.mlpx` 왕복

- [ ] 표 프로젝트와 이미지 프로젝트를 각각 `.mlpx`로 내려받는다. 콘솔 에러 0건, 네트워크에 실패 없음.
- [ ] 내려받은 파일을 다시 불러온다. **재학습 없이** 결과·예측·포트폴리오가 같게 보인다.

### 1.7 검사 화면 (교사)

- [ ] `/inspect`에서 1.6의 파일을 연다. 무결성 판·포트폴리오 판이 뜬다.
- [ ] 재실행 대조를 돌려 저장된 점수와 맞는다고 나온다.
- [ ] 같은 프로젝트에서 나온 파일 둘을 열면 같은 프로젝트로 묶인다.
- [ ] 학생 정보를 고쳐 다시 내려받는다. 그 파일이 변조로 거부되지 않는다.

## 2. 실기기 몫

소유자가 한다. 브라우저 자동화로 대신할 수 없는 것만 둔다.

### 2.1 휴대폰

- [ ] 아이폰 사파리로 LAN의 개발 서버에 http로 접속해 첫 화면이 뜬다.
- [ ] 표 프로젝트 하나를 만들어 학습까지 돈다. 터치 대상이 누르기 어렵지 않다.
- [ ] 카메라·앨범으로 사진을 넣어 이미지 프로젝트를 학습한다.
- [ ] 사진이 많은 프로젝트를 `.mlpx`로 저장한다. 브라우저가 뻗지 않고 파일이 "파일" 앱에 남는다.
- [ ] 그 파일을 다시 불러온다.

### 2.2 컴퓨터실 흐름

- [ ] PC A에서 만든 `.mlpx`를 USB·메일로 옮겨 PC B(저장소가 빈 브라우저)에서 불러온다. 재학습 없이 전부 보인다.
- [ ] 브라우저 데이터를 지운 뒤(리셋 흉내) 같은 파일로 이어서 작업한다.
- [ ] 교사 입장으로 학생 파일 여러 개를 검사 화면에서 차례로 연다.

### 2.3 저사양 체감

- [ ] 개발 PC에서 큰 표·사진 많은 프로젝트(`acceptance-fixtures.mjs <폴더> --rows 5000 --images 200`)로 학습·저장이 견딜 만한 시간 안에 끝난다. 걸린 시간을 적는다.

### 2.4 문구

- [ ] 지원 언어마다 화면 문구가 자연스럽다. 어색한 문장은 키와 함께 적는다.
