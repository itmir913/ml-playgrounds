# R43-1 후속 5차 계획 재검토 — **APPROVE**

> 독립 재검토자의 회신을 오케스트레이터가 옮겨 적었다. 요청서 `request-R43-1-plan-5.md`. 임시 스펙 하나(지움)로 확인했고 소스는 안 건드렸다.

**4차 지적 1~4는 모두 닫힌다. 막혀야 할 것은 남지 않았다.** 아래 주의 둘은 막는 사항이 아니라 계획서의 문장을 바로잡는 것이다 — 구현 때 반영한다.

## 물음 1 — 4차 지적을 닫는가
- **술어 시그니처:** 닫힌다. `{ categories, testCategories, to }`라 gate가 프로젝트를 몰라도 된다. 화면은 판정 직전에 같은 파일로 입력을 계산하고 `commitName`은
  판정과 `save` 사이에 `await`가 없으며 스토어 `resolve`는 같은 `file.value`에 동기로 적용한다 — gate와 `renameCategory`는 같은 문자열·목록을 본다. 함수가 던지는
  길은 진짜 입구로 안 닿는다. `test-set.ts`는 `@/ml/selection`·`@/project/format`만 들이고 `locks.ts`는 이미 `@/ml/selection`을 들인다.
- **만들기+옮기기 우회:** 닫힌다. C의 문장은 참이되 성립 조건은 **옮기기까지**다(만들기만 하면 106이 `UNKNOWN`으로 막는다).
- **다음 행동:** 닫힌다. 새 이유는 `NAME_REFUSAL_KEYS`에 키를 더해야 타입이 맞고, [확정] 뒤 `role="alert"`로 선다.
- **검사 입구:** 닫힌다. ③의 `vi.spyOn`은 vitest 5.0.2에서 모듈 네임스페이스에 걸리고 다른 모듈이 들인 바인딩에도 닿는 것을 확인했다(`.vue`는 미확인).
- **새로 여는 것:** 진짜 입구에서 못 찾았다(쿼터 거절 → retag 돎, 닫힌 프로젝트 → 표지 안 섬).

## 물음 2 — NFC/NFD
gate와 `renameCategory` 사이에서는 안 갈린다(같은 문자열·목록, 정확한 비교). 대신 **둘이 똑같이 눈이 멀었다**: 이름 칸은 정규화 안 함(NFD도 `isValidCategoryName`
통과), 업로드는 NFC, `.mlpx`를 열 때는 기록된 표기를 되살린다(`format.ts:1030-1045`). 고아가 NFC `test/고양이`이고 NFD `고양이`로 바꾸면 술어가 거짓 → 통과 →
훈련 `[B, C_nfd]`, 테스트 `[B, C_nfc, C_nfd]` → **106이 `TEST_IMAGES_CATEGORY_UNKNOWN`으로 막는다**(시험 확인) — 틀린 점수는 안 나온다. 기존 `nameTaken`도 같은
맹점이다. 정규화를 한다면 술어 한 곳 안에서만 — 범주 이름 정규화 전체는 별도 결정감.

## 물음 3 — 막혀야 할 것: 없다. 주의 둘
1. "각 검사는 고치기 전 코드에서 운다"는 ②(쿼터 거절 뒤 retag — 지금 코드는 늘 retag)와 ⑤(기존 검사)에는 거짓이다. 둘의 빨강은 돌연변이로 본다(②는 표지를
   "저장 성공"으로, ⑤는 106 대조를 빼서). ①·③·④는 고치기 전에 운다.
2. 결정문의 되살리기 문장에 성립 조건 "사진을 옮겨 넣으면"을 남기고, NFC/NFD 맹점은 106이 막는다는 것을 한 줄 적는다.
