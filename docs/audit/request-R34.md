## 0. 이 라운드는 **재검증**이다 — 새 것을 찾는 라운드가 아니다

**R33의 지적 여섯(A1·B1·C1~C4)을 전부 닫았다.** 이 라운드가 답할 것은 셋이다.

1. **닫혔는가.** 네가 쓴 재현을 그대로 다시 돌려라. **재현이 안 되면 고쳐진 것이다.**
2. **고치면서 새로 만든 것이 있는가.** 이 저장소의 경험으로는 **여기가 값이 가장 높다** —
   R28-V가 *"회귀 0건 · 새 결함 하나 · 덜 닫힘 여덟"*을 냈고, 덜 닫힘 여덟 중 일곱이
   *"코드는 옳은데 검사가 없다"*였다.
3. **나가도 되는가.** 마지막에 한 줄로 답하라.

**새 영역을 파지 마라.** 이번 델타 밖에서 뭔가 보이면 **지적하지 말고 §7에 한 줄로만
적어라** — 다음 주기가 받는다. 이 라운드의 예산은 위 셋에 쓴다.

## 3. 새로 세운 그물 — **이것이 진짜 그물인지 봐라**

**요청서 R33이 물은 것에 코드 소유자가 답한 방식이다**: 자리마다 고치는 대신
**문 전부를 훑는다.** 그물이 둘 생겼고, **둘 다 네가 무는지 확인해야 한다.**

### 3.1 `tests/settings.spec.ts` — 설정 문 전수

문 열하나에 적대적 값을 넣고, 각 문이 **스키마를 통과하는 문서를 내거나 `ClientError`로
선다**는 것을 본다. 조용히 못 읽는 문서를 내는 것만 금지다. **목록이 닫혀 있는지도
소스에서 센다**(`^export function with\w+\(`를 세어 `DOORS`와 맞춘다).

- **이 잣대가 비어 있지 않은가.** 적대적 값이 실제로 스키마의 경계를 찌르는가, 아니면
  전부 안전한 값이라 무엇을 지워도 통과하는가.
- **`ClientError`를 허용한 것이 구멍인가.** 문이 그냥 던져 버리면 이 검사는 통과한다 —
  그 여지가 실제로 악용될 모양인지.
- **목록 세기가 정말 닫히는가.** 새 문을 소스에 더해 보고 우는지.

> 이 검사는 **세우자마자 둘을 더 잡았다** — `withSplit`의 `testSize: 0`(스키마는 열린
> 구간)과 `withRandomState`의 소수. 둘 다 문에서 막았고, **막는 방식은 클램프가 아니라
> 무시다**(범위 밖이면 **지금 값을 지킨다**). 그 판단이 맞는지도 봐라 — 근거는 결정문에
> 적었다: 클램프하면 화면 밖에서 온 정상 파일(`testSize` 0.7)을 학생이 다른 설정을
> 건드릴 때마다 조용히 고쳐 쓰게 된다.

### 3.2 `tests/reopenable.spec.ts` — 학습 결과 문

**망가진 데이터로 진짜 학습을 돌려** 그 문서가 다시 열리는지 본다(타깃이 전부 같은 회귀,
특성이 전부 같은 분류, 겹친 점의 군집 둘, 한 줄짜리 범주).

**이 파일은 처음에 안 물었고, 그 사실이 이 라운드의 교훈이다.** 파스만 보던 판에서는
지표 가드 셋을 지워도 전부 초록이었다 — 파고 보니 **`r2`의 분모 가드를 지우면 문서는
멀쩡히 열리고 run만 조용히 `failed`로 떨어진다.** 그래서 계약을 셋으로 바꿨다:
**끝까지 돌았는가 · 지표가 전부 유한한가 · 문서가 열리는가.**

- **심어서 확인한 것**(코드 소유자): `ratio`의 0-분모 가드 → 운다. `r2`의 `total === 0`
  가드 → 운다. `settings.ts`의 문 둘 → 운다.
- **못 닿은 것**: 실루엣의 `maxAB === 0` 가드. 겹친 점을 두 군집으로 쪼개도 안 지나간다.
  소스는 위쪽 `filled` 가드가 먼저 막는다고 적지만 **그건 코드 소유자가 잰 것이 아니다.**
  **닿는 벌이 있는지 찾아 보고, 없으면 "없다"고 적어라.**
- **네가 볼 것**: 이 다섯 벌이 실제로 극단을 만드는가. **다른 지표의 분모가 0이 되는
  벌이 더 있는가**(정밀도·재현율·F1·이너셔·MAE·RMSE).

## 4. C-3 — 실측했다. **등급만 매겨라**

네가 *"끝에서 끝까지는 안 쟀다"*고 적은 자리를 코드 소유자가 쟀다(2026-09-19,
`predictPage`를 진짜로 부르고 전처리가 낸 벡터를 그대로 꺼냈다).

```
키 '150'   -> [150, 40, 1, 0, 0]   정상
키 '없음'   -> [  0, 40, 1, 0, 0]   글자가 0이 됐다
키 '1,650' -> [  0, 40, 1, 0, 0]   천 단위 쉼표도 0이 됐다
```

**셋 다 실패 없이 답이 나온다.** 화면에는 평범한 예측 한 줄이 뜬다.

- **닿는 길은 파일 예측 하나다.** 손으로 치는 칸은 `type="number"`라 브라우저가 막는다
  (`InputRow.vue:119`). 파일 쪽은 `parsePredictDataset`가 **열 이름만** 본다.
- **교실에서 흔한 모양이 쉼표다.** 한국 학교 자료의 수는 `1,650`으로 적힌다.
- **새것이 아니다.** 이 동작은 `0.21.4`가 이미 나간 채로 들고 있다 — 이번 sklearn
  작업이 만든 것이 아니다.

**고치려면 결정이 걸린다**: 새 실패 사유(어휘 + ko/en 문구)를 만들어 그 칸을 *"숫자가
아닙니다"*로 세울지, 아니면 지금처럼 두고 파일을 붙일 때 경고할지. **문구와 어휘는 코드
소유자의 것이므로 네가 고르지 마라.** 네가 답할 것은 하나다 — **이것이 배포를 막는가.**

## 6. 제외할 것

**설계 결정은 코드 소유자가 정했다. 반대 제안을 하지 마라.**

1. 쓰는 길에 검증을 넣는 길은 안 간다 — `내보내기는 무조건 성공해야 한다`.
2. 범위 밖 값은 클램프가 아니라 무시다(예외는 `nSamples`, 결정문에 근거가 있다).
3. 큰 모델은 만들기 전에 거절한다 · 어휘는 `tooLarge`다 · `formatVersion`은 안 올린다.
4. 배수는 (알고리즘 × 실행 방법)마다 둔다 · 시동은 학습마다 낸다.

**이미 아는 부채 — 시간 쓰지 마라**: 브라우저 워커에서 113MB가 죽는 모양 ·
`splitBoundary`의 부동소수 세부 · 다중 클래스 SVM의 동점 규칙 · UTF-16 정렬 ·
사진 경로의 실물 왕복 · `modelOmission.engineUnsupported`의 *"아직"*.

**그리고**: 버전 올리기 제안 금지. 문구 말투 금지. `npm run lint` 금지.
**`ruff format scripts/`도 금지** — 이 세션이 그걸로 남의 파일을 두 번 고쳤다.
