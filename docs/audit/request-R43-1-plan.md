# R43-1 후속 — 범주 편집과 테스트 사진의 계획 검토 요청서

> 독립 검토다. 공통 규칙은 `docs/workflow.md` §3 "감사 국면은 어떻게 도는가"·"감사가 되풀이해 잡은 병"과 §10.
> **읽기 전용이다** — 소스를 고치지 마라(돌연변이·임시 스펙도 이번에는 필요하면 심고 되돌리는 것까지만).
> 금지: `git commit`·`push`·`tag`·`add` · `npm run lint` · `npm run ci` 전체 · `git stash` · `git checkout .` · 하위 에이전트·클라우드.
> 기준 커밋 `b502e00`. 배경: `docs/audit/report-R43-1.md` A-1, `docs/open-decisions/08-implemented.md`·`docs/cases/open-decisions.md`의 106.

## 문제

사진 프로젝트에서 테스트 사진(`split.method = 'provided'`, `dataset/test/<범주>/`)을 받은 뒤 데이터 화면에서 범주를 고치면 테스트
자리는 옛 이름 그대로였다. 지금(`b502e00`)은 학습 입구(`ml/training-source.ts`)가 `testZipBlockFor`로 **훈련 사진이 든 범주**와 테스트
범주를 다시 대조해 거절한다(결정 106). 코드 소유자가 묻는다: *"범주 이름을 바꾸면 테스트 사진도 함께 바꾸고, 범주를 지우면 테스트
사진도 지우는 것이 논리적으로 맞지 않나?"*

## 검토할 계획

| 편집 (`project/images.ts`) | 테스트 사진 | 실험 기록 |
|---|---|---|
| `renameCategory` | 같은 트랜잭션에서 `dataset/test/<옛>/` → `<새>/`로 옮긴다 | 그대로 |
| `removeCategory` | 그 범주의 테스트 사진을 지운다. 확인 창이 장수를 미리 말한다 | **그대로 둔다** |
| `moveImages`(새 범주로) · `removeImages`(한 범주의 훈련 사진을 다 지움) | 손대지 않는다 | 그대로. 학습 입구의 대조(결정 106)가 막는다 |

**실험 기록을 안 지우는 근거(계획 작성자의 주장 — 깨 봐라).**
1. 사진 프로젝트는 데이터가 바뀌어도 실험을 안 버리고 스냅숏(`project/schema.ts`의 `imageSnapshotSchema` — 범주·범주별 장수·순서
   지문)으로 차이를 말한다. 실험을 통째로 버리는 것은 표의 규칙이다(`mlpx-spec.md` §4.3).
2. 범주를 지우면 훈련 쪽 범주 목록이 반드시 바뀌어 다음 실험의 스냅숏에 남는다 — 테스트가 줄어든 것이 그 변화에 실려 결과 화면이
   "같은 설정"이라고 말하지 않는다.
3. 테스트 사진은 모든 범주를 갖춰야만 올라가므로(`testZipBlockFor`), 범주 하나를 지워 테스트가 0장이 되는 일은 없다.
4. **알려진 구멍:** 테스트 사진의 상태(장수)는 스냅숏에 없다. 스냅숏 칸을 더하는 것은 포맷 결정이라 이번에는 안 한다.

**반대쪽 선례도 있다.** `applyTestImages`·`clearTestImages`는 테스트 사진을 올리거나 뗄 때 실험을 전부 지운다(R11 감사 B-5:
"provided로 채점한 점수와 holdout으로 채점한 점수가 한 비교표에 나란히 선다").

## 물음

1. 위 계획이 맞는가. 특히 **`removeCategory`에서 실험을 안 지우는 것**이 비교표·결과 화면·점검(교사 화면)·재실행 대조
   (`ml/reproduce*.ts`)·`.mlpx` 왕복 어디에서 거짓을 만드는가. 진짜 입구로 따라가 확인하라(코드 읽기로 확정 못 하면 그렇다고 적어라).
2. `removeCategory`가 테스트 사진을 지우는 것 대신 **라벨 없음으로 옮기거나 그대로 두고 학습 입구에 맡기는** 안과 비교해 어느 쪽이 낫나.
3. 이름 바꾸기 트랜잭션에서 놓치기 쉬운 것: 이미 있는 이름으로 바꿔 두 범주가 합쳐지는 경우, 임베딩·해시·예측 자리(`predict`),
   `split` 참조, 결정 106 대조와의 관계, 변경 이력(`ml/changes.ts`).
4. 이 계획이 결정 106(학습 입구 대조)을 대체하는가, 함께 두는가.
5. 계획에 없는데 같은 병을 가진 편집이 더 있는가(`grep`으로 세라).
