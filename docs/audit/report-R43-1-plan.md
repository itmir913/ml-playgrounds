# R43-1 후속 계획 검토 — 범주 편집과 테스트 사진 — APPROVE WITH CHANGES

> 독립 검토자의 회신을 오케스트레이터가 옮겨 적었다. 요청서는 `request-R43-1-plan.md`. 기준 커밋 `b502e00`.
> 확인은 임시 스펙 둘로 진짜 입구 함수를 불러 했고 지웠다.

**판정.** `renameCategory`가 테스트 사진을 함께 옮기는 것은 맞으나 고칠 점 1이 막혀야 안전하다. `removeCategory`가 테스트 사진을
지우는 것은 2·3이 붙어야 한다. 실험을 남기는 근거 1·2는 섰고, **주장 3은 거짓**, 주장 4는 부분적으로 틀렸다.

## 고칠 점

1. **이름 바꾸기가 남아 있던 테스트 폴더와 조용히 합쳐진다.** 지금의 `removeCategory`가 테스트 폴더를 남기므로 IndexedDB의 기존
   프로젝트와 손으로 고친 `.mlpx`에는 목록에 없는 `test/C/`가 있을 수 있다. 이름 판정(`locks.ts:640`)은 `imageCategories`
   (`ImagePanel.vue:156,558` — 목록 + 훈련 폴더)만 봐서 `A→C`를 통과시킨다. 계획대로 옮기면 `test 범주 ["B","C","C"]` — 옛 C 사진이
   새 C(옛 A)의 정답으로 채점되고 결정 106 대조도 통과한다(`training-source.ts:204-211`). 처방: 이름 판정 또는 `renameCategory`가
   테스트 폴더 이름과의 겹침도 거절하고 검사로 문다.
2. **테스트가 0장이 되면 `provided`만 남는 덫.** `testSetBlockFor`는 범주 1개 이상이면 받는다(`test-set.ts:55-56`) — 범주 하나짜리
   프로젝트도 테스트를 올린다(시험 확인). 그 범주를 지우거나 차례로 다 지우면 테스트 0장인데 `split.method`는 `provided`로 남고
   참조만 빠진다(시험 확인). 준비 화면은 ①(holdout)을 보이고(`ImagePrepPanel.vue:128,156-158`) ①을 골라도 파일에 안 쓰며
   (`:186-193`), 학습은 `TEST_IMAGES_CATEGORY_MISSING`으로 영영 선다 — `clearTestImages` 머리말(`images.ts:320-322`)이 경고한 상태다.
   처방: 마지막 테스트 사진이 나가면 `clearTestImages`와 같은 뜻(holdout으로 되돌리고 실험 삭제, B-5)으로 하고 확인 창에 적는다.
3. **확인 창이 되돌릴 수 없다는 것까지 말해야 한다.** 지운 뒤 같은 이름으로 범주를 다시 만들고 사진을 옮기면 `MISSING(A)`
   (지금 코드는 `started`). 테스트는 집합이 정확히 같은 묶음으로만 받으므로(`test-set.ts:88-97`) 되살리려면 전체를 다시 올려야 하고
   그러면 실험이 다 지워진다(`images.ts:295-310`). "라벨만 뗀다, 되돌린다"(`images.ts:604-609`)가 테스트 쪽에서 깨진다는 것을
   결정문에 적는다.
4. **구현 함정.** `renameCategory`는 훈련 자리만 돈다(`images.ts:587,592`). `moveImages`는 역할이 `'data'`로 박혀 있어
   (`:490,495`) 재사용할 수 없다. 장수를 말하려면 테스트 범주별로 세는 함수가 필요하다(`countByCategory`는 훈련만, `:155-163`).
5. **주장 4 바로잡기.** 테스트 장수는 이미 기록에 있다 — 총수는 `settings.testIndices.length`(`schema.ts:98-102,864`), 범주별은
   run의 `confusionMatrix` 행 합. `changed`가 분할 인덱스를 일부러 뺄 뿐이다(`experiment.ts:355`). 포맷을 안 바꾸고 `changed`의
   비교 항목으로 닫을 수 있으나 경로 이름과 로케일 키(`changes.ts`)를 정하는 결정이 필요하다.

## 물음에 대한 답

- **실험을 남기면 거짓이 생기나:** 테스트가 0장이 되지 않는 한 코드로 확정할 거짓은 없다. 재실행 대조는 사진에서 `IMAGE_NOT_OPEN`
  (`reproduce-gate.ts:84`), 혼동 행렬 칸·순열 중요도·회귀 그림은 표 전용, 점검의 예상 시간은 `categoryCounts`만 읽는다. 옛 실험의
  `testIndices`를 사진 위에서 다시 읽는 곳은 없다. 지운 범주는 다음 실험 스냅숏에 반드시 남는다. **거짓은 0장인 경우뿐이다**(고칠 점 2).
- **다른 안과 비교:** 그대로 두고 학습에 맡기면 의도한 삭제가 `UNKNOWN`으로 막혀 전체 재업로드(실험 삭제)가 필요하고, 라벨 없음으로
  옮기면 `TEST_IMAGES_UNLABELED`로 막히고 다시 붙일 화면이 없다. **계획 쪽이 낫다** — 고칠 점 2·3을 조건으로.
- **이름 바꾸기 트랜잭션:** 화면은 `nameTaken`, 함수는 `Set`으로 합치기를 막는다. 임베딩·예측 자리·`testDataset` 참조·무결성은
  영향 없음. 남은 구멍은 목록에 없는 테스트 폴더(고칠 점 1).
- **결정 106:** 대체하지 않고 함께 둔다 — `moveImages`·`removeImages`·새 범주로 올리기(`ImagePanel.vue:433`)·옛 상태·손으로 고친
  파일·고칠 점 1.
- **같은 병의 이웃:** 데이터 화면의 범주·테스트 관계를 바꾸는 편집 6곳(`ImagePanel.vue:55-65,433,533,541,602-603,634`). 파일을 열 때
  `withFolderCategories`(`format.ts:1137-1148`)의 상호작용은 확인 못 함.
