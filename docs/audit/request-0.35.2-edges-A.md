## 1. 왜 이 감사인가

`docs/roadmap.md` "지금 어디인가"의 **감사가 안 본 채로 남은 경계** 중 시간 축의 둘이다. 0.30.11 diff 감사는 같은 실험을 두 입구(학습 화면·
점검의 대조)에 태워 견주는 데까지 봤고, **한 화면의 상태가 시간을 두고 어긋나는 것**과 **겹친 이동의 알림 수위선**은 아직 안 봤다.
경합은 **순서를 강제해 재현하라** — 틱 수를 세는 재현은 증거가 아니다.

## 2. 볼 것

1. **겹친 이동의 알림 수위선** — `frontend/src/router/index.ts`의 `toastWatermark`. 코드로만 읽혔다. 이동 A가 끝나기 전에 이동 B가 시작되고,
   그 사이 알림이 쌓이거나 가드가 거절·리다이렉트하는 순서를 강제로 만들어, 지워야 할 알림이 남거나 남아야 할 알림이 지워지는지 본다.
   기존 스펙 `tests/route-watermark.spec.ts`·`tests/router.spec.ts`가 무엇을 무는지부터 돌연변이로 잰다.
2. **갱신 누락과 상태 이력** — 한 화면이 열려 있는 동안 프로젝트(스토어)가 다른 길로 바뀌면 그 화면의 파생 상태가 따라오는가. 후보를 직접
   고르되 학생이 다치는 것부터: 범주 이름 바꾸기·지우기(결정 106)나 테스트 사진 변경 뒤 학습·예측·점검 화면의 캐시, 자동 저장이 끝나기 전의
   두 번째 변경, 실험 기록 목록. **진짜 입구로 재현하라** — 스토어 내부를 손으로 조립한 재현은 방어선을 건너뛴다.
3. 여유가 되면: 그리기 창의 `bounced` 가드. jsdom의 `<dialog>`는 `close()`에서 `close` 사건을 안 올린다(`roadmap.md`). 임시 스펙에서 사건을
   흉내 내 볼 수는 있으나, **흉내가 브라우저보다 관대하면 증거가 아니다** — 그렇게 본 것은 "못 한 것"과 나란히 적는다.
