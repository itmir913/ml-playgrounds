## 1. 지적

### V-A1. 전처리 화면이 **학습이 받아들이는 타깃을 "학습이 거부한다"는 빨강으로 말한다**

**자리** `frontend/src/views/preprocess/TabularPrepPanel.vue:168`(`plannedColumns` — 타깃은
`fittedColumns`에 없어 **파일 전체의 종류**로 남는다) → `ml/selection.ts:168`(`targetIssue`) →
`ColumnPicker.vue:137`(`columnBlocks`가 빨강). 학습 쪽은 `ml/plan.ts:185`의
`usableLabels`(`usableRows`를 지난 행의 라벨)를 본다.

**주장.** A-2와 **같은 병의 타깃 쪽 얼굴**이다. 화면은 타깃 종류를 파일 전체로 세고, 학습은
**쓸 수 있는 행**(`missing: 'drop'`이면 특성 칸이 빈 행을 뺀 것)으로 센다. 회귀 타깃의 글자
칸이 **특성이 빈 행에만** 있으면 두 쪽이 갈린다. 그리고 **새 프로젝트의 기본값이
`missing: 'drop'`이다**(`project/schema.ts:338`) — 학생이 아무것도 안 바꿔도 이 길이다.

**재현** (`tests/zz-r38v-target.spec.ts`, 지운 임시 스펙). A-2의 검사와 같은 진짜 입구 —
CSV 바이트 → `openTable` → `importTable` → `applyDataset` → 설정 문. 40행 회귀, `점수`는
수치인데 5행만 `모름`.

| 입력 | 계획(`planRun`) | 실제 학습(`runExperiment`) | 전처리 판 |
|---|---|---|---|
| `drop` · `모름` 행의 `키`가 빔 | **통과** | **`done`** · R² −0.21 | 타깃 줄 **빨강** *"회귀는 숫자를 예측하는데 타깃 열에는 숫자가 아닌 값이 있습니다"* · 범주형. **요약 카드는 오류 없음** |
| `mean` · 같은 행 (대조) | `TARGET_NOT_NUMERIC` | — | 빨강 둘(타깃 줄 · 요약 카드) |
| `drop` · `모름` 행의 특성이 있음 (대조) | `TARGET_NOT_NUMERIC` | — | 빨강 둘 |

**첫 줄에서 같은 판이 반대말을 한다** — 열 표는 *"거부한다"*(빨강의 뜻, `ColumnPicker.vue:129`),
요약 카드는 말이 없다. 대조 둘은 두 쪽이 같다.

**틀리면 학생에게.** 화면이 *"회귀로 쓸 수 없다, 분류로 바꾸거나 다른 타깃을 고르라"*고
빨갛게 말한다. 학생은 그대로 **유형이나 타깃을 바꾼다** — 학습은 멀쩡히 됐을 데이터다.
**학습 화면도 같은 말을 한다**(`TrainView.vue:314`의 `targetIssue`도 파일 전체의 종류를 본다),
그런데 **[학습하기]는 그것으로 안 잠긴다**(`TrainView.vue:502`의 `nothingToTrain`은 고른 모델
수만 본다) — 눌러 보면 학습이 되고, 두 화면이 한 말이 둘 다 거짓이 된다.

**무는 검사가 있는가.** **없다.** `tabular-prep-kind.spec.ts`의 불변식이 *"학습이 쓰는 열마다"*라
**특성 열만** 센다 — 타깃은 `preprocessor.columns`에 없어서 그 그물 밖이다. **세울 수 있다** —
위 표 첫 줄이 그 검사다.

**처방 — 재 봤다.** 판 안에서 타깃 종류를 계획과 **같은 행**으로 세어 덮었다
(`detectKind(targetValues(dataset, usableRows(…), target))`).

- 첫 줄의 빨강이 **사라지고**(열 표 · 요약 카드 둘 다 조용), 대조 둘은 **그대로 두 쪽 다
  빨강**이다. 전처리 스펙 일곱 파일 104개 초록, `vue-tsc` 깨끗. 되돌렸다.
- **그러나 이 모양으로 넣지 마라** — 계획의 판정(`plan.ts:185~195`)을 화면이 **한 벌 더
  계산**한다(되풀이해 잡은 병 6번). 더 나은 자리는 **`planRun`이 타깃 종류를 내놓고**
  화면이 그것을 읽는 것이다 — `fittedColumns`가 특성 종류를 내놓는 것과 같은 모양이다.
  계획이 타깃 판정 **앞에서** 서는 경우(특성 결측 등)에는 파일 전체로 남겨도 두 쪽이 같다.
- **이웃은 `TrainView.vue:314` 하나다**(R39의 몫 — 세기만 했다). `TabularTrainContext.vue:28`은
  특성 쪽이라 이 병이 아니다.

**문서도 함께 거짓이 됐다.** `open-decisions.md` 53의 새 문단(*"축을 바로잡는다"*)이
*"전처리 화면은 R38 A-2의 고침으로 **학습이 정한 종류를 그대로 말한다** — 그래서 그 변화가
화면에 거짓 없이 보인다"*고 적는다. **타깃 열에 대해서는 아직 참이 아니다.**

### V-B1. B-3을 닫은 규칙이 **박스 플롯과 이미 반대다**

**자리** `docs/architecture/02-shell.md` §8.9.1.1의 새 문단 · `views/data/charts/BoxChart.vue:49`.

새 문단은 로그 축 한 가지를 넘어 **일반 규칙**을 세운다 — *"다음 손잡이도 이 규칙을 따른다:
**열을 바꾼다고 설정을 되돌리지 않는다.**"* 그런데 박스 플롯은 **열이 바뀔 때마다 학생이 고른
가르기를 푼다**(`watch(() => props.input.column, () => { groupBy.value = '' })`). 그 이유로 적힌
것(*"그 열이 표에서 사라진 경우 상자가 없는 그림"*)은 창이 모달이라 **창이 열린 동안 표가 안
바뀌므로 닿지 않는다**(R38 §4). 그리고 **그 줄을 지워도 조용하다**(B1, 아래 표).

**둘 중 하나다** — 규칙을 *"구간 수와 축"*으로 좁히거나, 박스 플롯이 규칙을 따르게 하거나.
요청서가 *"결정이라고 보면 B로 되돌려라"*고 했고, **새 규칙이 기존 코드와 반대라서 되돌린다.**
산점도의 세로축 재선택(`ScatterChart.vue:66`)은 **예외가 아니다** — 새 가로축과 같아진
세로축은 그릴 수가 없어서 옮기는 것이다.

### V-C3. 새 픽스처 — 거짓 초록은 없다, 사소한 것 하나

- **쓰는 스펙은 둘**(`batch-predict-download` · `predict-invalidation`)이다. 요청서의 *"셋"*은
  틀렸다.
- `predict-invalidation`은 답을 **손으로 넣으므로** 답이 한 가지뿐이어도 상관이 없다 — 그
  검사가 재는 것은 *"지워지는가"*다. 다만 그래서 **답 루프(`run()`)는 이 픽스처로도 여전히
  안 돈다**(V7이 조용한 이유와 같은 뿌리).
- `batch-predict-download`의 대조 쪽 `const table = { …, rows: grid.slice(1) }`은
  **`rows`를 아무도 안 읽는다**(`transform`에는 `PICKED`로 다시 만든 표가 간다). 틀린 것은
  아니지만 *"CSV의 행으로 다시 예측한다"*처럼 읽힌다 — 지우거나 실제로 그것을 쓰라.
- `projectFile()`에서 물려받는 설정(`missing: 'drop'` · 분할)은 **붓꽃에 결측이 없어** 판정에
  안 닿는다. 확인만 했다.

### V-C4. A-1 — **의심할 것 셋은 코드로만 봤다**

재 볼 입력을 못 만든 것은 아니고 **값이 낮다고 봤다**. 틀렸으면 다시 연다.

- **섞인 판.** 이어 붙이기(`append`)는 붙여넣기에서만 켜지고 붙여넣기는 언제나
  `IMAGE_UNLABELED`다(`ImagePanel.vue:296`). 판에 여러 범주가 섞이는 길은 **폴더 구조가 있는
  zip뿐**이고, `retagPending`이 `===`로 바꾸므로 폴더 이름이 바꾼 범주와 같은 것만 따라간다 —
  옳다.
- **왕복**(`고양이 → cat → 고양이`) — 같은 함수가 두 번 돈다. 옳다.
- **굽는 중** — `canName`이 `busy`를 보고(`:495`) 삭제 확인 단추가 `:disabled="busy"`다.
  **창을 여는 것은 안 막히지만 확정이 막힌다.** 옳다.
- **덧붙여 — 지웠다가 같은 이름으로 다시 만들면** 판의 묶음은 라벨 없음에 남는다(고치기 전에는
  되살아난 범주에 앉았다). **이미 앉은 사진과 같은 규칙**(`removeCategory`는 라벨을 떼고, 다시
  만든다고 안 돌아온다)이라 결함이 아니다.
