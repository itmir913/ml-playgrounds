## 1. §2 — R33의 지적 여섯

| # | 판정 | 재현·측정 |
|---|---|---|
| A-1 | **닫힘** | 내 재현을 그대로 다시 돌렸다. 천장은 여전히 `1`인데(실물 CSV 한 줄 → `usable: 1`) 화면의 클램프가 이제 `2`를 낸다. **문에 `1`을 직접 넣어도** 파일·저장소 둘 다 `nSamples: 2`로 열린다 |

### A-1 — 화면 절반까지 닫혔다 (R33 §8이 *"안 쟀다"*고 적은 것)

R33에서 나는 *"문만 고치면 `input.value = String(next)`가 자기 계산값을 다시 써서 화면이
거짓말한다"*고 적고 **안 쟀다.** 이번에는 **DOM을 안 띄우고 대수로 닫았다.**

- 화면: `panel = max(min(parsed, usable), MIN)`
- 문: `door = max(panel, MIN)`

`panel ≥ MIN`이 항상 참이므로 `door`는 `panel` 위에서 **항등**이다. `usable 0..12` ×
`parsed −3..15` **247쌍**을 전부 돌려 어긋나는 쌍이 **0건**임을 확인했다. 화면이 칸에
쓰는 값과 파일에 담기는 값은 **언제나 같다.**

**잔여 하나 — 오늘은 안 닿는다.** `setSampleRows`의 `NaN` 갈래는 아직
`nSamples.value ?? usableRowCount.value`라, `nSamples`가 비어 있고 천장이 바닥 아래면
화면에 `1`이 남을 수 있다. 그 갈래는 **뽑기가 켜져 있어야만 렌더되는 칸**이라
`nSamples`가 비는 일이 없고, 비더라도 **문이 `2`로 올린다** — 잃는 것은 화면 한 칸의
정직함뿐이다. 지적으로 올리지 않는다.

### A-1의 이웃 둘 — 클램프가 아니라 무시, 그 선택이 맞다

`withSplit(testSize: 0)`과 `withRandomState(0.5)`를 넣고 왕복시키니 **둘 다 지금 값을
그대로 들고 나온다**(`{method:'holdout', testSize:0.2, stratify:true, randomState:42}`).
결정문의 근거 — *"클램프하면 화면 밖에서 온 정상 파일(`testSize` 0.7)을 학생이 다른
설정을 건드릴 때마다 조용히 고쳐 쓴다"* — 는 **반대편을 재면 성립한다**: 클램프 안을
`0.5`로 잡으면 0.7짜리 파일이 층화 한 번에 0.5가 된다. 무시는 그 경로가 없다.

### B-1 — 주석을 고친 선택이 맞다

내 처방은 둘이었다. ① 검사 본문을 자르지 않은 원문으로 바꾼다 ② 주석이 대는 이름을
실제로 무는 것으로 줄인다. **코드 소유자가 ②를 골랐고, 그것이 맞다** — ①을 하면 그
스펙은 *"파일 계층이 안 자른다"*를 주장하게 되는데 **파일 계층은 실제로 안 자르므로**
그 검사는 자르는 문이 사라져도 안 우는 검사가 된다. 즉 ①은 이름과 본문을 맞추는
대신 **그물을 하나 더 늘리지 않는다.** ②는 *"무는 것이 하나다"*를 문서로 못 박았고,
M1이 그 문장을 실측으로 지킨다.

## 2. §3.1 — 설정 문 전수 그물: **잣대는 안 비었다. 목록 세기가 안 닫힌다**

### 2.1 잣대가 비어 있지 않다 — 가드 셋을 지워 셋 다 울었다

| 지운 것 | 결과 |
|---|---|
| `withSampling`의 `Math.max(nSamples, MIN_SPLIT_ROWS)` | **운다** (`withSampling: …` 1건) |
| `withSplit`의 `testSize` 범위 가드 | **운다** (`withSplit: …`) |
| `withRandomState`의 `Number.isInteger` 가드 | **운다** (`withRandomState: …`) |

적대적 값이 실제로 스키마의 경계를 찌른다. **비어 있는 잣대가 아니다.**

### 2.2 `ClientError` 허용은 구멍이 아니다

문이 무조건 던져도 이 검사는 통과한다 — 맞다. 그러나 **같은 파일의 앞쪽 스펙들이 각
문의 정상 동작을 이미 재고 있고**(`withTaskType`부터 `withHyperparameter`까지), 문
하나를 무조건 던지게 만들면 그쪽이 운다. **이 `describe`가 답하는 질문은 *"문이 동작하는가"*가
아니라 *"조용히 못 읽는 문서를 내는가"*이고, 그 질문에 대해 `ClientError` 허용은 정확하다.**

### 2.3 **B-1(새것) — 목록 세기가 두 표기를 못 본다**

**자리**: `frontend/tests/settings.spec.ts:347` (`훑는 문이 settings.ts가 내보내는 것 전부다`)

세는 정규식이 `^export function (with\w+)\(`다. 소스에 **문을 둘 더 넣고** 돌렸다.

```ts
export const withZzz = (document: ProjectDocument, now: string): ProjectDocument => …
export async function withYyy(document: ProjectDocument, now: string): Promise<ProjectDocument> { … }
```

**33개가 전부 초록이다.** 둘 다 `DOORS`에 없고, 둘 다 `runtime`에 수를 담아
**스키마를 못 지나는 문서**를 낸다 — 프로브로 확인했다:

```
{ ok: false, where: ['settings', 'runtime'] }
```

`export function withZzz(`로 같은 문을 넣었을 때는 **운다**(대조군). 즉 그물은 **한
표기에만** 붙어 있다.

**이것이 R30 C-4가 이름 붙인 병 그대로다** — *"그물이 일이 아니라 이름을 본다."*
이 검사의 주석이 **그 병을 인용하면서** 같은 병에 걸렸다.

**A가 아닌 이유**: 오늘 `settings.ts`의 열 문이 전부 `export function`이라 빠져나가는
것이 없다. 잃은 것은 *"새 문이 생기면 운다"*는 **약속의 절반**이다.

**처방(실측 안 했다)**: 세는 자리를 `^export (?:async )?(?:function|const) (with\w+)`처럼
넓히는 것이 자연스럽다. 다만 **정규식을 넓히는 것 자체가 같은 병의 다음 판**이라
(세 번째 표기가 오면 또 샌다), *"소스를 정규식으로 세는 것"* 대신 **모듈을 실제로
`import * as`로 읽어 `with`로 시작하는 내보내기를 세는 쪽**이 병을 끝낸다.
**어느 쪽인지는 코드 소유자의 결정이라 안 심었다.**

## 3. §3.2 — 학습 결과 문 그물: 문다. 그리고 **못 닿던 가드에 닿는 벌을 찾았다**

### 3.1 그물이 무는 것을 내가 다시 쟀다

| 지운 것 | 결과 |
|---|---|
| `metrics.ts`의 `ratio` 0-분모 가드 | **운다** — 벌 둘(`특성이 전부 같은…`, `한 범주가 한 줄뿐…`)과 `지표가 실제로 담겼다`까지 셋 |
| `metrics.ts`의 `r2`의 `total === 0` 가드 | **운다** — 그리고 **`status`에서 먼저 운다**(`toBe('done')`). 문서는 열린다 |

**후자가 이 그물의 설계를 정당화한다.** 파일이 열리는 것만 봤다면 `r2` 가드는 지워도
초록이었다. *"끝까지 돌았는가"*를 함께 보는 계약이 **절반을 더 잡는다.**

### 3.2 실루엣의 `maxAB === 0`에 **닿는 벌이 있다** (요청서가 열어 둔 물음)

**겹친 점을 두 군집으로 쪼개는 벌로는 못 닿는다 — 이유를 쟀다.** 같은 점 넷에
`k=2`로 `fitKMeans`를 돌리면 배정이 `[0,0,0,0]`이고 **중심점이 둘 다 `[1,1]`이다.**
`filled === 1`이라 위쪽 가드에서 `0`으로 빠진다. **일반적으로 그렇다** — 배정이
`argmin`이라 **같은 점은 언제나 같은 라벨을 받고**, 거리 0은 곧 같은 점이므로
`filled ≥ 2`이면 `bi > 0`이다.

**닿는 길은 다른 데 있었다 — 표본이다.**

```
열 100개 · 행 3,000 · 다수 군집은 전부 같은 점 · 소수 군집은 외톨이 한 점 · k=2
silhouetteSampleSize(3000, 100) = 2,500 < 3,000  → 표본이 켜진다
씨앗 20에서 외톨이가 표본에서 통째로 빠진다
→ 뽑힌 점마다 ai = 0 (전부 같은 점), 다른 군집의 표본 멤버가 0개라 bi = Infinity → 0
→ maxAB === 0
```

**가드를 지워 확인했다**: 같은 벌에서 실루엣이 유한하지 않게 되고
`evaluateCluster`가 `JOB_FAILED`로 던진다 — 즉 **그 run이 통째로 `failed`가 된다.**
**가드는 죽은 코드가 아니다.**

**소스의 단정이 반만 맞다.** *"위의 `filled` 가드가 이미 걸러내므로 여기 오지 않는다 —
방어선으로 남긴다"*는 **전수일 때만** 참이다. **표본을 켜면 `filled`는 전수를 세고
`members`는 표본을 세므로 둘이 갈린다.** 지적으로 올리지 않고 사실만 적는다 — 요청서가
물은 것이 *"닿는 벌이 있는가"*였고, 답은 **있다**이다.

**행·열이 상한 안이다**: 3,000행 ≤ `BROWSER_ROW_LIMIT` 5,000, 100열 ≤
`MAX_DATASET_COLUMNS` 1,000. 다만 *"다수가 전부 같은 점"*이라는 모양이 교실에서 흔한지는
안 쟀다.

### 3.3 다른 지표의 분모가 0이 되는 벌

- **정밀도·재현율·F1·정확도·MAE·RMSE** — 전부 `ratio()` 한 벌을 지난다. 그 가드가
  §3.1에서 울었으므로 **이미 덮여 있다.**
- **`f1Macro`** — 분모가 `perClass.length`인데, 라벨 집합이 정답과 예측의 합집합이라
  **0이 되려면 시험 몫이 비어야 한다.** 분할이 그것을 먼저 막는다.
- **이너셔** — 나눗셈이 없다. 합이다.
- **덜 쟀다**: `r2`의 `total`이 **0은 아닌데 비정상적으로 작은 경우**
  (`residual / total`이 `Infinity`가 되는 자리). CSV 글자로 그 크기를 만들 수 있는지는
  안 쟀다 — §7에 한 줄로 넘긴다.

## 4. C-3 — **라운드 중에 고쳐졌다.** 등급과 검증

요청서는 *"안 고쳤다, 등급만 매겨라"*였는데 **`79183f1`이 이 라운드 도중에 들어왔다.**
그래서 둘 다 답한다.

**등급(고치기 전 상태 기준): C — 배포를 막지 않는다.** 근거 셋.
① `0.21.4`가 이미 이 동작으로 나가 있어 **이번 델타가 만든 것이 아니다.**
② 못 여는 문서를 만들지 않는다 — 파일은 멀쩡하고 잃는 것은 **그 행의 답 하나**다.
③ 고치는 데 **새 어휘와 ko/en 문구**가 필요해 배포를 붙잡으면 문구 결정이 배포 일정에
매인다. **다만 조용히 틀린다는 점에서 C 중에는 가장 무겁다** — 실패도 경고도 없고
표준화까지 지나면 모델이 자신 있게 틀린 답을 낸다.

**고친 것의 검증 — 닫혔다.**

- **진짜 입구에 붙었다.** 가드는 `inputVector`에 있고 `predictPage`가 행마다 그것을
  부른다(`predict.ts:1015`) — 요청서가 *"닿는 길은 파일 예측 하나"*라고 적은 그 길이다.
- **그물이 문다.** 가드를 지우니 새 검사 둘이 운다(`predict.spec.ts`, 127개 중 2 실패).
  그 검사도 `predictPage`로 들어간다 — 손으로 조립한 것이 아니다.
- **빈 칸과 끝까지 나뉜다.** `PREDICTION_INPUT_INCOMPLETE`가 먼저 서고, 숫자가 아닌
  값만 `PREDICTION_INPUT_NOT_NUMBER`다. 학생이 할 일이 다르다.
- **학습을 안 깬다.** `1,650`이 든 열은 학습에서 `detectKind`가 **범주형**으로 잡으므로
  `column.kind === 'numeric'`이 거짓이고 이 가드가 안 걸린다 — **판정이 같은 `toNumber`
  한 벌이라 학습과 예측이 갈리지 않는다.**
- **문구가 둘 다 있다.** `ko.json`·`en.json` 620행, `docs/error-codes.md:303`.
  사용자 데이터가 문장 끝 괄호에 있다(`… ({feature})`) — `CLAUDE.md` §3-4대로다.

## 5. C-1 — 덜 닫혔다. 그리고 새 주석이 넓게 말한다

**자리**: `scripts/adapter_python.py:96` (`_SERIALIZER_INDENT`)

프로브를 다시 돌렸다(저장소 파일은 안 건드렸다).

| 모양 | R33 | 지금 |
|---|---|---|
| 형제 객체가 **더 깊다**(8칸) | `NESTED`를 가져갔다 | **`REAL`을 가져간다 — 막혔다** |
| 형제 객체가 **`serializer`와 같은 깊이**(4칸)이고 그 안이 6칸 | — | **`NESTED`를 가져간다 — 안 막혔다** |
| `dumps()`의 `dump: LINEAR_DUMP` 갈래 | `^ +` | **여전히 `^ +`다** — 깊이를 안 본다 |

```python
  random_forest: {
    predictor: {
      dump: 'NESTED',      # 6칸 — 이것이 이긴다
    },
    serializer: {
      dump: 'REAL',        # 6칸 — 진짜
    },
  },
```

**앵커가 못 박은 것은 깊이이지 부모가 아니다.** `serializer`의 형제 객체는 오늘 하나도
없으므로(`module`·`cls`·`fixed`는 값이다) 실물에는 0건이고, 실물 일곱의 `dump`과
`random_forest`의 `size`는 그대로 뽑힌다 — **회귀는 없다.**

**새 주석이 단정을 넓게 한다.** 그 줄은 *"항목은 2칸, `serializer:`가 4칸, 그 안이
6칸이다 — **그 자리 하나만 본다**"*고 적는데, 실제로 보는 것은 **6칸짜리 아무 `dump:`**다.
R33 B-1과 같은 모양이 **고치는 커밋 안에서** 하나 생겼다.

**등급 C** — 실물에 0건이고 `EXPECTED`/`EXPECTED_SIZES`가 *"못 찾으면 선다"*를 지킨다.
다만 **틀린 것을 가져가는 경로는 안 서고 조용하다** — 그게 이 항목이 C 중 무거운 이유다.

**C-2는 닫혔다.** `size`를 잃으면 `no size found for: random_forest`로 선다. **남는
한계는 설계다** — 둘째 알고리즘이 `size`를 얻어도 `EXPECTED_SIZES`에 **손으로 적지
않으면** 그 칸이 뒤에 사라져도 조용하다. `EXPECTED`가 이미 같은 계약이고 주석이 그것을
명시하므로 지적으로 올리지 않는다.

## 7. 다음 주기 (델타 밖 — **지적이 아니다, 한 줄씩**)

- `r2`의 `total`이 0은 아닌데 극히 작을 때 `residual / total`이 `Infinity`가 된다.
  CSV 글자로 그 크기를 만들 수 있는지 안 쟀다.
- `metrics.ts`의 *"`filled` 가드가 이미 걸러내므로 여기 오지 않는다"*는 **전수일 때만**
  참이다. 표본이 켜지면 `filled`는 전수를, `members`는 표본을 센다.
- `preprocess.ts`의 `toNumber(String(filled)) ?? 0`은 그대로다. 예측의 문이 앞에서
  막으므로 오늘은 안 닿지만, **`0`을 고르는 원시 연산 자체는 살아 있다.**
- `tests/reopenable.spec.ts`의 마지막 `it` 위에 **같은 주석 블록이 두 번** 붙어 있다.
- `silhouetteSampleSize`가 열 수로 표본을 정하므로, **열이 많은 프로젝트에서는 실루엣이
  표본값**이다. 화면이 그 사실을 말하는지는 이 라운드에서 안 봤다.
