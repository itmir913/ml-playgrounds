> **이 계획의 국면은 R38 뒤에 닫혔다** (2026-09-24, 코드 소유자 — `close-2026-09-24.md`).
> **R39·R40은 돌지 않았고** §7의 기준으로 닫힌 것도 아니다. 두 라운드의 표적(§1)과 R40의 입력(§6)은

> 되풀이해 잡은 병"**까지다. 라운드 요청서(`request-R##.md`)는 이 계획을 가리키고
> 슬라이스·첫 돌연변이·제외만 적는다.
>
> 지도의 원자료는 `docs/audit/map-2026-09-21.md`가 갖고, 결론은
> `docs/rule-coverage.md` "검사가 없는 자리의 지도"가 갖는다. **두 자리다** — 원자료는
> 라운드마다 갱신되고 결론은 국면이 닫힐 때 옮긴다.

## 1. 축은 대상이 아니라 방법이다

열여덟 라운드가 대상만 옮겨 다니고 방법이 하나였다 — 존재하는 코드의 한 줄을 바꿔
결정적 단일 스레드 vitest가 우는가(`roadmap.md` "지금 어디인가"의 사각 둘). 전수를
도는 김에 **라운드마다 방법을 하나씩 다르게 세운다.** 요청서 첫 줄은 언제나
*"이번 방법은 무엇이고, 그 방법이 못 보는 것은 무엇인가"*다.

| # | 슬라이스(소유 경로) | 방법 | 이 방법이 못 보는 것 |
|---|---|---|---|
| 준비 | 전체 — **코드 소유자 세션이 한다** | 조회와 실측으로 지도를 세운다(§2). 감사자가 아니다 | 계산의 옳고 그름 |
| R35 | `src/ml/engines/` `src/ml/models/` `src/ml/embed/` | **돌연변이 + sklearn 대조.** 저쪽을 돌린 출력을 붙인다 | 두 시점·경합 |
| R36 | `src/ml/*.ts` `src/ml/worker/` | **전수 세기.** 문·등록부·소비자를 **표기가 아니라 실물**(네임스페이스·등록부 배열)로 센다 | 화면까지의 이음매 |
| R37 | `src/project/` `src/data/` | **순서를 강제한 경합 + 실물 `.mlpx` 왕복.** 저장소를 세워 두 async의 창을 겹친다 | 결정적 실행 |
| R38 | `src/views/predict/` `src/views/preprocess/` `src/views/data/` | **두 시점 비교.** 같은 값을 화면 전후로 읽어 견준다 — 갱신 누락·캐시 무효화·"넘긴 뒤에도 참인가" | 한 시점 계산 |
| R39 | `src/views/` 나머지 · `src/components/` `src/composables/` `src/stores/` `src/router/` | 두 시점 비교 + **gate와 잠금**(`architecture.md` §10) | 〃 |
| R40 | — | **사각 메우기 + 고침 재검증.** R35~R39의 *"못 했다·안 쟀다·안 읽었다"*와 그 사이 코드 소유자가 고친 자리 | — |

**소유 경로 밖은 읽기만이다.** 병렬로 돌리면 `git status --short`가 남의 돌연변이로
더러운 것이 정상이고, 요청서가 그것을 미리 말한다.

**R36의 방법을 고른 이유.** R33·R34에서 A가 두 라운드 연속 같은 모양으로 나와(못 여는
문서) 델타를 쫓는 대신 전수로 세는 라운드로 바꿨고, 그것이 A 하나를 더 잡았다. 그때
세 번 밟은 병이 *"세는 것이 실물이 아니라 표기였다"*다(`open-decisions.md`
"문서를 만드는 문이 모양을 보장한다 (2026-09-19) — R32 A-1 · R33 A-1"). R36은 그
방법을 `ml/` 최상위에 그대로 적용한다 — `experiment.ts`·`predict.ts`가 문서로 값을
넣는 문이고, `algorithms.ts`·`backend.ts`·`metric-panels.ts`가 등록부다.

**R37·R38·R39의 방법을 고른 이유.** `roadmap.md`의 사각 둘 — 두 시점 비교와 경합 —
을 라운드의 **축**으로 세운 적이 없다. A급 둘이 우연히 거기서 나왔을 뿐이다.

## 2. 지도의 층 — 무엇을 어떻게 세는가

지도는 세 층이고 아래로 갈수록 값이 높다. **위 두 층은 준비 라운드에서 기계로 세우고,
셋째 층이 감사 라운드의 산출물이다.**

### 2.1 실측 층 — 검사가 실제로 닿는가

- **전체 스위트의 줄 커버리지**(v8, `src/**` 전부). 2026-09-02의 지도는 스펙이 `src/`를
  임포트하는 그래프를 셌는데, 그것은 **표기**다 — 임포트했다고 실행한 것이 아니다.
  커버리지는 *"이 줄을 어떤 스펙이 실제로 지나갔는가"*의 실물이다. 도구는 저장소에
  안 들인다(`@vitest/coverage-v8`를 `--no-save`로 잠깐 세운다 — `package.json`은
  그대로다).
- **돌연변이 카탈로그**(`tools/mutants.json`, `npm run mutate`). 값이 증명된 그물
  `cries`가 아직 무는지, `silent`가 여전히 조용한지.

**커버리지가 0인 줄에는 돌연변이를 심지 마라.** 조용한 것이 자명하다 — 증명할 것이
없다. **돌연변이는 실행되는데 단언이 약한 줄에 심는다.** 지도가 그 줄을 고른다.
커버리지 100%도 무는 증거가 아니다 — 지나갔을 뿐 재지 않았을 수 있다. 그 자리가
돌연변이의 자리다.

### 2.2 조회 층 — 모집단이 닫히는 것은 전수로 센다

R33이 남긴 기준이다: *"모집단이 닫히는 부류(스키마 제약·어휘·상한)는 전수로 세서 0을
확인하고 닫아라. 안 닫히는 부류(기본값·도달 경로)는 세지 말고 소비자 수를 1로
줄여라."*

- **문(門)** — 문서로 값을 넣는 함수. `project/settings.ts`의 `with*` 열, `identity`·
  `portfolio`·`roster`의 `with*`, 그리고 `ml/experiment.ts`의 run 생성. 각 문에
  *"모양을 보장하는 검사"*(`settings.spec.ts`·`reopenable.spec.ts` 모양)가 있는가.
- **등록부** — 알고리즘 9 · 실행 방법 3 · 엔진 3 · 모델 형식 10 · 지표 판 6 · 데이터
  종류 2. 각 항목을 **실제로 지나가는** 스펙이 있는가(커버리지로 답한다).
- **상한 소비자** — `limits.ts` 상수 133개 각각의 `src` 소비자 수와 `tests` 언급 수.
  소비자가 화면뿐이면 재는 검사가 없는 것이고, 소비자가 둘 이상이면 R31 C-1 → R32 B-1의
  모양(한 값을 두 소비자가 각자 기본값으로 덮는다)이 생길 자리다.
- **결정문 대 코드** — `open-decisions/`·`architecture/`가 백틱으로 부르는 이름이 코드에
  있는가. 감사는 없는 코드를 구조적으로 못 본다(두 탭 잠금이 그렇게 숨어 있었다) —
  이건 조회로만 잡힌다.

### 2.3 감사 층 — 라운드의 지적

지적마다 `workflow.md` §3의 서식(자리·주장·재현·처방·이웃 수)에 **칸 하나를 더한다**:

> **이 자리를 무는 검사가 있는가 / 없으면 세울 수 있는가 / 세울 수 없으면 왜.**

지도의 실제 산출물이 이 칸이다. *"세울 수 없다"*의 이유는 셋 중 하나여야 한다 —
실기기만 답한다 · 비결정적이라 순서를 강제해야 한다 · 화면 안에 남은 판정이라 밖으로
빼야 한다(`architecture.md` §8).

## 3. 고침 정책 — 부채 지도 목적이 바꾸는 것

- **A만 그 라운드에서 닫는다.** 학생이 지금 다치거나 초록불이 거짓인 것.
- **B·C는 지도에 남긴다.** *"나중에"*라고 적으면 안 온다 — 이 저장소가 여러 번 확인한
  사실이다. 그래서 남기는 자리를 지금 못 박는다:
  - 원자료(지적 전부, 등급, 무는 검사 칸) → `docs/audit/map-2026-09-21.md`
  - 결정이 걸린 것 → `docs/open-decisions.md`의 미결정 절
  - 국면이 닫힐 때 결론 → `docs/rule-coverage.md` "검사가 없는 자리의 지도"
- **고친 자리는 다음 라운드가 본다.** R13·R18·R26이 전부 *"어제 세운 검사가 오늘의
  A"*였다. R35의 고침은 R36 요청서에 명시적으로 옮겨 적는다 — 단계 사이의 인수인계가
  한 번 떨어진 적이 있다.

## 4. 라운드 요청서에만 있는 것

1. 첫 줄: 방법과 그 방법이 못 보는 것(§1의 표 그대로).
2. 소유 경로. 밖은 읽기만.
3. **첫 돌연변이 후보** — 지도(§2.1)에서 고른 *실행되는데 단언이 약한 줄* 대여섯.
   커버리지가 0인 자리는 적지 않는다.
4. **이미 아는 부채 — 시간 쓰지 마라**(§6). *"내가 틀리게 알고 있으면 그건 새 항목"*
   단서와 함께.
5. 제외: 버전 올리기 제안 · 문구 말투 · 화면 생김새(그 자리는 코드 소유자가 본다) ·
   `npm run lint` · `ruff format`.
6. 규모 — 관문 수와 시간. 지금은 `npm run ci` 3,574개 · 약 100초.

## 5. 순서와 세션

```
준비(코드 소유자) → R35 → 고침 → R36 → 고침 → R37 → 고침 → R38 → 고침 → R39 → 고침 → R40
```

- 감사자 세션은 **코드 소유자가 직접 연다.** 하위 에이전트·클라우드는 안 쓴다.
- 체급은 Opus. 수치·검사기가 대상인 R35만 더 무거운 체급이 값을 했었다 — 예산이
  있으면 거기에 쓴다.
- R35~R39는 소유 경로가 안 겹치므로 **병렬이 가능하다.** 다만 고침은 한 세션이 한다 —
  감사자는 고치지 않는다.

## 6. 이미 아는 부채 — R35~R39는 시간 쓰지 말고, R40이 받는다

R30~R34 보고서의 *"못 한 것"* 절에서 아직 안 닫힌 것. **R40의 입력이다.**

- 브라우저 워커에서 113MB 모델이 죽는 모양(힙 수치는 Node에서 잰 것) — R31·R32
- 사진 경로의 실물 `.mlpx` 왕복 — R33·R34 둘 다 못 했다
- 사진 프로젝트의 sklearn 줄·거절 경로를 화면에서 — R31·R32
- 폴백 경로(원본이 배포판을 내리는 날)의 실물 — R30·R31
- 특성 사다리 여덟·손잡이 사다리 셋의 원본 JSON이 저장소에 없다 — R31
- 다중 SVM 표 동점 규칙이 libsvm과 다르다 · UTF-16 정렬 — R30(결정이 먼저다)
- `r2`의 `total`이 극히 작을 때 `Infinity` · `metrics.ts`의 *"`filled` 가드가 걸러낸다"*는
  전수일 때만 참 · `preprocess.ts`의 `toNumber(...) ?? 0` 원시 연산 · 열이 많으면 실루엣이
  표본값인데 화면이 말하는가 — R34 §7
- `experiment.spec.ts` 720줄 전수 — R26부터 남은 숙제
- 옵셔널 필드 66개 중 콜백·객체·문자열 50개 — R33이 세기만 했다

**그리고 방법의 사각 그대로** — 실기기(아이폰·학교 PC)·실제 스크린 리더·화면 생김새는
어느 라운드도 안 본다. `rule-coverage.md` "검사가 구조적으로 못 잡는 것"이 갖는다.

## 7. 끝내는 기준

**깨끗함이 아니다.** 돌연변이 생존율은 열여덟 라운드 내내 20~35%였고 0에 안 수렴한다.
닫는 근거는 R40이 답하는 둘이다:

1. **A급의 성질이 옮겨갔는가** — 학생이 다치는 것 → 방금 만든 것 → 검사가 없던 자리.
2. **지도가 닫혔는가** — 조회 층(§2.2)의 모집단마다 *"몇 중 몇"*이 적혀 있고, 감사 층의
   지적마다 무는 검사 칸이 채워져 있는가.

둘 다 "예"면 국면을 닫고 결론을 `rule-coverage.md`로 옮긴다. 하나라도 "아니다"면
그 자리가 R41이다.
