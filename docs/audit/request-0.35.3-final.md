## 1. 왜 이 감사인가, 그리고 판정

이 범위는 0.35.2 뒤의 감사 국면이다 — 경계 감사 A·B·C와 고침 라운드가 찾고, **코드를 쓰는 세션(Opus) 하나가** 고쳤다. 고침 라운드 감사는
`a180e38..8762be8`까지만 봤다. **그 뒤의 고침(`827e668`·`da4d099`·`a80d7c0`·`cc7e800`·`d1be26a`·`0b20ee9`)은 어떤 감사자도 안 봤다.**
당신은 **독립된 최종 감사자**다 — 고침이 지적을 실제로 닫았는가, 원칙을 어기지 않았는가, 새 병을 열지 않았는가.

**CLEAN APPROVE** — 이 범위를 그대로 0.35.3으로 태그해도 된다. 조건은 A·B가 0이고 C는 코드를 쓰는 세션이 판단할 수 있는 것뿐인 상태다.
아니면 지적(A/B/C)과 함께 **NOT CLEAN**.

## 3. 볼 것

1. **감사자가 안 본 고침 여섯.** 특히
   - `827e668` — 중복 이동의 `afterEach`에서 지금 주소가 프로젝트 밖이면 `close()`한다. 미저장 편집·결정 74의 확인 창·탭 잠금·자동 저장 타이머와
     겹치는 길에서 `close()`가 학생의 것을 버리는가. 지금 주소가 프로젝트 밖인데 스토어에 지켜야 할 것이 있는 순간이 있는가.
   - `a80d7c0` — 끝나지 못한 이동에서 알림을 안 걷는다. 그 대신 **남지 말아야 할 알림이 남는** 길(리다이렉트로 끝난 이동, 잠긴 단계 알림,
     중복 이동 뒤 수위선)이 있는가.
   - `d1be26a` — 묶음 폴더 이름. 걷은 뒤 겹침·빈 이름·예약 이름·`(2)` 번호와의 상호작용, 경로 구분자 사이의 조각, 한글·NFD 이름이
     바뀌지 않는가. 가능하면 실제로 풀어 보라(`Expand-Archive`·`zipfile`).
   - `0b20ee9` — 학습 화면 머리 범주 수. 군집(라벨 없는 학습)에서 무엇을 보이는가.
   - `cc7e800` — 문구가 `copy.md`·`terms.md` 규칙(한자어 동작명, 닫힌 목록)과 세 언어 계약을 지키는가. `StepHeader`의 `note`가 다른 화면에 영향이 없는가.
