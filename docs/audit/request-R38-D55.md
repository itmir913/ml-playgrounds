## 0. 왜 끊었는가 — 코드 소유자의 이유

코드 소유자(현직 교사)의 말이다(2026-09-23):

> *"만약 어떤 조건이 다른 조건에 영향을 미친다면, 해당 옵션 자체를 on/off로 연쇄교체하는게
> 아니라, 영향을 받는 옵션을 그냥 비활성화만 해야 하거든. 즉, A옵션을 킬 경우 B 옵션이
> 적용되지 않는 함수 관계가 있을 경우, B on 상황에서 학생이 A on 할 경우 B가 단순 disable되어야
> 하는거지, B가 연쇄적으로 off되면 안된다. (추후 의존 사이클이 생길경우 폭주할 수 있기도 하다.)
> 왜냐면 전처리 옵션이 자동으로 체크 해제(비활성화)될 경우 학생이 직접 해당 탭으로 돌아와서
> 다시 켜야 한다."*

이유는 셋이다.

1. **교실의 비용.** 학생이 학습 화면에서 유형을 바꾸면 전처리 화면에서 켜 둔 것이 조용히
   꺼진다. 되돌려도 안 돌아오므로 **학생은 그 탭까지 걸어가 자기가 켜 둔 적 있는 것을 다시
   켜야 한다** — 그런데 꺼졌다는 것부터 모른다.
2. **폭주.** 연쇄는 쓰는 자리가 다른 값을 쓰는 것이다. 옵션이 늘어 **의존에 사이클이 생기면**
   끄고-켜고가 서로를 부른다. 잠그기만 하면 값이 안 움직이므로 사이클이 있어도 멈춰 있다.
3. **선례가 있었다.** 층화에서 이미 한 번 겪고 이렇게 정했다 — 결정됨 *"값을 내리지 않는다.
   학습이 무시하고 화면이 잠근다"*(`open-decisions/02-tabular.md`, 2026-08-31). 그때는 **유형
   사유 하나만** 그렇게 했고, 데이터 사유는 *"끄는 것이 학생의 유일한 탈출구"*라며 학습이
   거부하게 두었다. **그것도 손으로 하는 연쇄다** — 결정문 55가 그 줄을 뒤집었다.

**원칙** (`open-decisions.md` 55): A 때문에 B가 적용될 수 없으면 B의 값은 그대로 두고 —

| 누가 | 무엇을 |
|---|---|
| **학습** | B를 **무시한다.** 거부하지 않는다. 무시하는 자리는 **학습에 넘기는 한 곳**이다 |
| **화면** | B를 **잠그고 이유를 말한다.** 잠금은 이유 목록을 돌려주는 함수 하나가 정한다(architecture.md §10) |
| **파일** | B의 값을 **그대로 든다.** A를 되돌리면 B가 그대로 살아난다 |

**A를 쓰는 문이 B를 고쳐 쓰지 않는다** — 끄지도, 지우지도, 다른 값으로 옮기지도 않는다.

## 2. 적대적 감사 — 불변식을 깨 보라

아래는 **내가 지킨다고 믿는 것**이다. 믿음이지 증거가 아니다. 깨지는 입력을 찾아라.

### I1. 정답은 어떤 길로도 특성이 되지 않는다 — **가장 무겁다**

`withTarget`이 더는 특성에서 타깃을 안 빼므로, 살아 있는 설정의 `features`에 타깃과 같은
이름이 **정상적으로** 있다. 막는 자리는 `plan.ts`의 `featuresInUse` 하나라고 적었다.

- **살아 있는 설정의 `features`를 읽는 자리를 전수로 세어라** — `dataSettings('tabular', …)
  .features`, `tabularDataOf(…).features`, `settings.data.features`, 구조 분해 전부. 각 자리를
  **(학습·예측에 들어간다 / 세기만 한다 / 쓰기 위해 읽는다)**로 갈라라. 첫째 칸에 계획을
  안 지나는 자리가 하나라도 있으면 **A**다.
- **계획을 안 지나는 학습 길**이 있는가 — 재실행 대조(`ml/reproduce.ts` · 점검 화면), 이미지
  경로(`ml/images.ts`가 설정을 따로 짓는다), 예측(`ml/predict.ts`의 `inputVector`), 교정
  (`ml/calibration.ts`), 예상 시간, `provided` 테스트 표.
- **군집**: 타깃 이름이 저장돼 있어도 거르지 않는다(`featuresInUse(…, undefined)`). 유형을
  군집 → 분류로 바꾸는 순간 그 열이 특성에서 빠지는데, **화면과 학습이 같은 순간 같은 말을
  하는가.**
- **실험 기록**(`training-source.ts`의 스냅샷)은 쓴 특성만 든다. 이 기록으로 **다시 돌린
  결과가 원래 학습과 비트 단위로 같은가** — 특성 순서까지.

### I2. 화면이 잠그는 것 ⇔ 학습이 무시하는 것

- **모델**: 줄이 잠기는 조건(`chosenModelBlocks`)과 학습에서 빠지는 조건(`trainableSelections`)이
  모든 입력에서 같은가. 등록부에 없는 알고리즘, 같은 알고리즘이 실행 방법만 달리 여러 줄,
  유형 미정.
- **층화**: 체크박스가 잠기는 조건(`stratifyBlock` / 이미지의 `stratifyBlockFor`)과 계획이
  무시하는 조건이 같은가. **`shareStratifyBlock`은 `split.ts`의 식을 한 벌 더 쓴다** — 나는
  시험 비율 여섯으로만 견줬다. **뽑기를 켠 경우 · `provided` · 이미지 · 뽑은 수가 쓸 수 있는
  행보다 큰 경우**에서 경계가 갈리는가. 갈리면 한쪽은 잠그는데 학습이 층화하거나, 안 잠그는데
  학습이 무시한다 — **A**다.
- **특성**: 특성 칸이 켜진 채 잠기는 조건과 계획이 빼는 조건이 같은가.

### I3. A를 되돌리면 B가 처음 그대로다

왕복 뒤 `settings`가 **바이트 단위로** 처음과 같은가. 내 스펙은 다섯을 왕복으로 쟀지만 **한
경로씩**이다 — A를 두 번 바꾸는 경우, A와 다른 옵션을 섞어 바꾸는 경우, 자동 저장과
되돌리기(undo가 있다면)가 끼는 경우를 봐라.

### I4. 잠긴 줄을 사이에 둔 학습의 자리

학습에는 잠긴 줄을 뺀 목록이 가고, 워커의 자리(index)는 그 목록의 자리다. 화면은
`byChosenRow`로 줄 자리에 옮긴다.

- **진짜 학습으로 재라** — 잠긴 줄이 가운데 끼인 목록으로 학습을 돌려, 줄마다의 상태·경과
  시간·예상 시간이 **자기 줄에** 붙는가.
- **[멈추기]로 끊은 학습**(`open-decisions.md` "멈추기가 끝난 것을 남긴다") — 조립되는 실험의
  `selectedAlgorithms`와 run이 `comparable()`의 **자리 짝짓기**에서 어긋나지 않는가.
- 학습 중에는 목록·유형이 잠긴다(`working`)고 봤다 — **정말 못 바꾸는가.**

### I5. 문구가 참인가

층화 문구 넷(`client.SPLIT_STRATIFY_*`·`SAMPLE_STRATIFY_IMPOSSIBLE`)을 *"적용되지 않습니다 · 무엇을
하면 다시 적용됩니다"*로 바꿨다. **같은 코드를 `split.ts`·`sample.ts`의 마지막 방어선도
던진다** — 거기서는 학습이 **거부**하므로 새 문구가 거짓이다. 계획을 거치면 안 닿는다고 봤다.
**닿는 길을 찾아라**(재실행, 점검, 남의 `.mlpx`). `train.nothingTrainable`이 서는 조건도
맞는지(담은 줄이 있는데 전부 잠김).

### I6. 옛 판과의 호환 — 재라

새 판에서 저장한 `.mlpx`의 `features`에 타깃 이름이 있을 수 있다. **0.26.6 이하는 그것을 빼지

  확인하라. 옛 `withFeatures`는 타깃을 거르는 문이었는데, **파일을 열 때도 걸러지는 길**이

- 돌려서 재고 싶으면 **저장소 밖 임시 디렉터리**에 `git archive 0.26.6`으로 풀어 써라.

### I7. sklearn과 갈린 자리

시험 몫이 범주 수보다 적거나 값이 1개뿐인 범주가 있으면 **sklearn은 던진다.** 우리는 이제
층화를 무시하고 학습한다 — 발판 원칙(`CLAUDE.md` §2)과 갈린다. 결정문 55가 이것을 **충분히
말하는가**, 그리고 실험 기록의 `split.stratify: true`가 **층화를 안 한 실험**에 남는 것이
교사(점검 화면)에게 어떻게 읽히는가.

### 돌연변이

`verify-R38-2.md` §6의 17개를 **네 하니스로 다시 심어라** — 같은 줄을 끊었는지 대조하라.
그리고 내가 안 심은 것을 심어라. 후보:

- `ScatterChart`: 색 열 getter가 후보 밖이면 고른 값을 그대로 돌려줌

안 우는 것은 **안 우는 이유**까지 적어라 — 닿지 않는 줄인가, 검사가 없는가.

## 3. 전수 조사 — **아직 남은 옵션 연쇄**

**정의.** *옵션 연쇄* = 학생이 값 A를 바꾸는 한 번의 조작이 **학생이 따로 고른 값 B를
고쳐 쓰는 것**(끄기 · 지우기 · 다른 값으로 옮기기 · 기본값으로 되돌리기). B가 사는 곳은 셋이다.

- **파일** — `settings`·`manifest`·그 밖에 `.mlpx`에 남는 학생의 선택
- **스토어** — 화면을 떠나도 사는 것(`stores/`)
- **화면** — 그 화면이 열려 있는 동안 학생의 선택을 드는 `ref`(창을 닫으면 잊는 것 포함)

**거꾸로 된 반쪽도 센다.** 원칙은 셋이 한 벌이다 — *학습이 무시하는데 화면이 안 잠그거나*,
*화면이 잠그는데 학습이 그대로 쓰는* 자리도 원칙 위반이다. 따로 표로 적어라.

**어떻게 세는가 — 내가 센 방법과 다르게 세라.** 나는 `with*` 문의 호출처와 화면의 `watch`를
셌다(`verify-R38-2.md` §0-A의 3). 그러면 못 보는 것이 있다.

- **파일을 돌려주는 모든 함수** — `ProjectDocument`·`ProjectFile`을 받아 돌려주는 순수 함수
  전부(`project/`·`ml/`·`data/`). 받은 필드 **밖**을 쓰는가.
- **`project.update`·`project.save`의 레시피 전부** — 레시피 하나가 두 필드 이상을 쓰는가.
- **이벤트 처리기** — `@change`·`@click`·`:action`이 문을 **둘 이상** 부르거나, 한 문을 부른
  뒤 화면 `ref`를 되돌리는가.
- **`watch`·`watchEffect`·계산값의 setter·`onMounted`** 안의 대입 — 학생이 고른 `ref`를
  덮어쓰는가. 화면 전체(`views/`·`components/`·`composables/`)다.
- **스키마 파싱·마이그레이션·열기** — 파일을 열 때 학생의 값을 바꾸는가(연쇄라기보다
  정규화일 수 있다 — 갈라서 적어라).
- **담기 폼 같은 초안 상태** — 학습 화면의 축(유형·모델·실행 방법)을 고르는 동안 한 축이 다른
  축의 초안을 바꾸는가. 이미지 백본 선택, 예측 화면의 필터·입력 방식, 포트폴리오.

**표로 적어라.**

| 자리(`파일:줄`) | A(바꾼 것) | B(고쳐 쓰인 것) | 어디 사는가(파일/스토어/화면) | 판정 | 근거 |
|---|---|---|---|---|---|

판정은 넷 중 하나다 — **연쇄**(원칙 위반) · **한 몸**(A와 B가 사실 한 선택이다 — 왜인지 적어라)
· **데이터가 사라짐**(가리킬 것이 없어졌다) · **정규화**(파일을 열 때 모양을 맞춘다). 내가
남긴 셋(§1 끝)도 이 표에 넣어 **네 판정**을 적어라.

**등급.** 파일에 남는 학생의 값이 조용히 바뀌는 연쇄 · 화면과 학습이 다른 것을 하는 반쪽 →
**A**. 화면 안에서만 사는 선택이 덮어써지는 것 · 판정에 결정이 필요한 것 → **B**. 주석·표기 →
**C**. **연쇄마다 처방을 한 줄 적되 고치지는 마라** — 어디가 무시하고 어디가 잠글지(§0의 표).

## 4. 소유 경로 — 읽기 전용

```
frontend/src/**
frontend/tests/**
docs/**
```

**전부 읽기만 한다.** 이번 라운드에는 고치는 세션이 따로 있다 — 코드 소유자가 회신을 나에게
넘기고, 내가 재현한 뒤 고친다. 임시 스펙은 `frontend/tests/zz-*.spec.ts`로 심고 끝나면 지워라.

## 5. 이미 아는 것 — 시간 쓰지 마라

- **`formatVersion`을 올릴지** — 코드 소유자의 결정을 기다린다(I6은 **닿는지만** 재라).
- **학습 화면의 타깃 문구**(`TrainView.vue`의 `targetIssue`가 파일 전체로 센다) — R39의 몫.
- **일괄 예측 캐시의 두 시점 검사 · 이미지 예측 답 루프** — 남은 일감으로 알고 있다.
- **화면의 생김새·문구의 말투** — 코드 소유자가 브라우저로 본다. 문구가 **참인지**는 본다(I5).
