# #43 계획 재검토 — **APPROVE WITH CHANGES** (변경 5)

> 독립 재검토자의 회신을 오케스트레이터가 옮겨 적었다. 요청서 `request-43-plan.md`. 계획의 규칙을 임시 모듈로 구현해
> `vi.mock`으로 끼우고 진짜 입구(`readImageZip`, `locale:'ko'`, `expect:[]`)로 태웠다(지움). 브라우저의 euc-kr은 파이썬 `cp949`로 대용했다.

**요지.** 틀은 옳다 — 이슈 표본이 돌아오고, 지금 초록인 검사(`zip-names`·`image-format` 132개)를 안 깨고, 대조가 먼저 돈다. 다만
대가 ②의 "(나)가 좁힌다"는 브라우저에서 사실이 아니고, 계획의 돌연변이 하나는 계획의 표본으로 안 운다.

## 잰 것
- 되살아남: `{치킨,치킨}`·`{치킨,pizza}`·`치타`·`화창`·`표`, 같은 압축 파일에 C4 이상이 하나 있으면 `책`도. 그대로: `책`→`å`·`짜짝`→`¥¦`·
  UTF-8 `café`·`Größe`·`Über`·맥 NFD `치킨`. 글자 하나짜리 전수(C2~C8 × A1~BF, 217): C4~C8 155개 전부 되살아나고 C2·C3 62개는 그대로.
- **대가 ②**(ko, 플래그 없는 UTF-8, 언어 소개 낱말 67): 브라우저(cp949 대용) **58/67**(`Łódź`→`흟처d탄`), node(euc-kr) 18/67, ja(cp932) 38/67.
  브라우저는 확장 완성형(뒷바이트 81~A0)을 읽어 라틴 확장-A 거의 모두가 한글이 된다. node는 그 구간을 못 읽어 **vitest가 비용을 작게 보여 준다.**
- ja의 얻는 것: 흔한 낱말 20개 중 UTF-8로 깨지는 것 0개, 무작위 전각 2글자 1.3%, 반각 가나 2글자 22%.

## 바꿀 것 → 처리
1. ko의 (나)를 완성형(ASCII 밖 바이트 전부 `A1` 이상)으로 좁히고 대가 ②를 측정값으로 적는다 → **반영**(`lookalike.minByte`, 결정문 18/67).
2. ja는 예외에서 빼고, `if`가 아니라 표의 필드로 → **반영**(ko만 `lookalike`).
3. "전부→하나" 돌연변이를 무는 섞인 표본 → **반영**(UTF-8 `ġд`, CP949로는 `치畇`).
4. (가)는 되살린 이름만 본다 → **반영**.
5. 비용 표본은 node와 브라우저가 같게 읽는 바이트로 → **반영**, 그리고 브라우저의 확장 완성형을 흉내 낸 디코더로 완성형 하한을 무는 검사.

구현 뒤 돌연변이 5(경계 0x7f·(나) 검사 없음·완성형 하한 없음·예외 끔·(가) 없음) 모두 욺.
