## 0. 먼저 볼 것 — **가장 의심스러운 셋**

1. **쓸 수 있는 행이 0개면 타깃 줄이 거짓 이유를 말한다 — 새로 생겼을 수 있다. 재지 않았다.**
   `detectKind([])`는 `'categorical'`이다(`preprocess.ts:110`). 그래서 `drop`이 모든 행을
   빼면 계획은 `TARGET_NOT_NUMERIC`으로 서고 `targetKind`는 `categorical`이다. **고치기 전에는**
   타깃 줄이 파일 전체의 종류(수치)라 조용했고 요약 카드만 그 문구를 냈다. **이제는 타깃 줄도
   빨강이고 종류 칸이 `범주형`이다** — 숫자뿐인 열에 *"숫자가 아닌 값이 있습니다"*. 계획의
   판정 자체가 원래 이 거짓을 말하던 것을 **내 고침이 한 자리 더 퍼뜨렸다**고 본다. 닿는지,
   그리고 닿으면 등급이 무엇인지 재라. (특성이 전부 빈 행 · 타깃이 전부 빈 열이 입력이다.)
2. **따로 올린 테스트 표의 타깃 판정은 `targetKind`에 안 실린다.** `plan.ts`의 두 번째
   판정(`provided`의 `testLabels`)은 **같은 코드**(`TARGET_NOT_NUMERIC`)로 거부하지만
   `targetKind`는 정본의 판정이라 `numeric`이다. 그러면 **타깃 줄은 조용하고 요약 카드만
   *"타깃 열에는 숫자가 아닌 값이 있습니다"*라고 말한다.** 고치기 전과 같은 모양이라 새 결함은
   아니지만, 한 판에서 두 자리가 다르게 말하는 것은 A-2·V-A1과 같은 병이다. **판정해 달라.**
3. **새 그물의 몇 자리는 여전히 안쪽을 만지거나, 우는 모양이 약하다.**
   - `image-panel-rename-pending.spec.ts`의 **고르기는 여전히 `panel.toggle(…)`이다**(260·261·
     280·286행). 사진 칸의 `@click="emit('toggle', entry.hash, $event.shiftKey)"`
     (`ImageGrid.vue:191`)와 판의 `@toggle`을 끊는 돌연변이는 **안 심었다.** shift를 버리는
     돌연변이가 특히 의심스럽다.
   - `chart-handles.spec.ts`의 산점도 판은 **`chart.colorBy = 'g'`로 쓴다**(276·284행). 색 열
     `<select>`의 `v-model`(네 V6)은 `chart-dialog.spec.ts`가 물지만 **이 파일은 안 문다.**
   - **V9([무작위로 가져오기]의 `@click`)는 시간 초과로 운다**(5015ms) — 단언이 아니다. 칸이
     안 채워져 두 모델이 실패로 답하고, `answered()`가 답 둘을 기다리다 선다. 운다는 사실은
     맞는데 **무엇이 틀렸는지 말하지 않는다.**
   - 이미지 스펙은 굽기가 끝나기를 **`vm.busy`·`vm.pending`을 읽어** 기다린다(쓰지는 않는다).
     **잠긴 확인 단추의 클릭은 조용히 안 먹는다** — 처음에 이것 때문에 다섯 번 중 두 번 빨갰다.
     지금은 누르기 전에 `disabled`를 단언한다. **다른 스펙에 같은 간헐이 숨어 있지 않은가.**

## 1. V-A1 — 타깃 줄이 학습의 판정을 말한다

**넣은 것.** `planRun`이 **`targetKind`**를 내놓는다(`plan.ts`의 `TargetJudgment`). `usableLabels`로
센 종류이고, **계획이 그 뒤에서 거부해도 실린다** — `refuse()`가 `blocked()`에 그것을 붙인다.
**계획의 판정 자체가 그 값을 쓴다**(`judged.targetKind !== required.kind`) — 화면이 읽는 값과
학습이 판정하는 값이 한 식이다. 판(`TabularPrepPanel.vue`의 `plannedColumns`)은 타깃 열의
종류를 그것으로 덮는다. **네 처방의 둘째 모양**(계획이 내놓고 화면이 읽는다)이다.

**검사** `tabular-prep-kind.spec.ts`의 *"타깃 줄이 학습의 판정을 말한다"* 셋 — 네 표의 세 줄
그대로다. 계획의 통과·거부, 타깃 줄의 `targetIssue`·종류, **DOM에 그 문구가 몇 번 서는가**
(0 · 2 · 2)를 본다. **재현이 먼저 됐다**(고치기 전 첫 줄만 빨강, 대조 둘은 초록).

**다시 심은 것.** 판이 `targetKind`를 안 읽음 → 욺. 계획의 `judged`를 파일 전체의 라벨로 셈
→ 욺(계획이 거부해 첫 줄의 전제가 선다).

**의심할 것.**
- 위 §0의 1·2.
- `targetKind`가 실리지 **않는** 거부 — 타깃 판정 **앞**에서 서는 둘(`TARGET_NOT_SELECTED` ·
  유형 미정 `pending`). 그때는 파일 전체의 종류로 남는다. 둘 다 타깃 줄이 빨강일 자리가 아니라고
  봤다.
- **군집**에서는 `targetKind`가 없다. 저장된 타깃이 있어도 역할이 `unused`라 줄이 안 선다고 봤다.
- **학습 화면**(`TrainView.vue:314`)은 안 건드렸다 — 네가 R39 몫으로 셌다. 결정문 53의 문단에
  *"학습 화면의 타깃 문구는 아직 파일 전체로 센다 — R39의 몫이다"*를 적었다.

## 2. V-C1 — 그물을 학생의 손으로 몬다

**넣은 것.** 다섯 스펙이 이제 칸은 `setValue`, 단추는 `trigger('click')`, 카드에는 **놓기
사건**(`dataTransfer`를 직접 심는 `inspect-drop.spec.ts`의 관용구)을 쏜다. 판의 안쪽은 읽기만
한다(§0의 3에 적은 예외 셋을 빼고).

- `chart-handles` — 히스토그램 여섯 판이 로그·자동 체크박스, 구간 수 칸, [적용]을 만진다.
  범위 밖에서 **단추가 잠겼는지**(`disabled`)와 **눌러도 그림이 안 바뀌는지**를 함께 본다(V5).
- `predict-invalidation` — **답을 손으로 안 넣는다.** [무작위로 가져오기] → [예측하기]로 내고
  두 모델 다 **값으로** 답했는지 본다. 그래서 **답 루프(`run()`)가 처음으로 돈다.** 필터가
  서려면 한 축에 선택지가 둘이어야 해서 **알고리즘이 둘**(`decision_tree`·`knn`)이다. 지워졌는지는
  `answers`와 **DOM의 *"값을 입력하고 [예측하기]를…"* 문구 수**로 본다.
- `batch-predict-download` — 바의 [내려받기]를 누른다. 쓰지 않던 `table`을 지웠다(V-C3).
- `tabular-panel-chart` — 검사기의 열 이름 단추를 누른다.
- `image-panel-rename-pending` — 범주 만들기·이름 변경·범주 삭제가 **카드의 단추 → 대화상자의
  칸과 확인 단추**, 사진은 **카드에 놓기**, 굽기는 **바의 [이 사진 사용]**이다.

**다시 심은 것 — 여섯 스펙으로.** 대조 C0(주석만) 조용. **V1~V5 · V7~V14 · V19 전부 욺.**
고침 넷 **V15~V18도 전부 욺**(이미지 스펙을 다시 썼으므로 다시 쟀다). 돌연변이는 네 표의
설명을 보고 **내가 다시 지었다** — 같은 줄을 끊었는지 네 것과 대조해 달라:

| # | 내가 심은 것 |
|---|---|
| V1 · V2 | 로그 · 자동 체크박스 `v-model` → `:checked` |
| V3 | 구간 수 `v-model.number` → `:value` |
| V4 · V5 | [적용]의 `@click` 삭제 · `:disabled` → `false` |
| V7 · V8 | `InputRow`의 `@set` · 필터의 `@toggle` 삭제 |
| V9 · V10 | [가져오기] `@click` → 빈 함수 · [내려받기] `:action` → 빈 함수 |
| V11 | 검사기 열 이름 단추의 `emit('visualize')` → 빈 함수 |
| V12 · V13 | 카드의 `@rename` · `@remove` 삭제 |
| V14 | 카드의 `@drop` → `readPicked($event, IMAGE_UNLABELED)` |
| V19 | `ImageGrid`의 [이름 변경] `emit('rename')` → 빈 함수 |

**밟은 함정 둘 — 스펙에 적었다.**
- **카드는 머리 주석을 앞에 둔 조각이다.** `card.element`는 주석 노드이고, 거기 쏜 놓기는 **판의
  놓기**로 올라가 라벨 없음으로 들어갔다. 그래서 `find('section')`에 쏜다. **다른 스펙이 조각
  루트의 `.element`에 사건을 쏘는 자리가 있는지** 봐 달라 — 그러면 조용히 다른 처리기에 간다.
- 위 §0의 3의 **잠긴 확인 단추**.

## 3. B와 문서

- **V-B1은 아직 안 닫혔다.** B-3에서 내가 적은 일반 규칙(*"열을 바꾼다고 설정을 되돌리지
  않는다"*)과 박스 플롯의 가르기 풀기(`BoxChart.vue:49`)가 반대라는 것 — **코드 소유자의

  모달이라 안 닿는다). **이번 재확인의 범위가 아니다.**
- **V-C2** — 결정문 53의 *"언제나 범주"*를 *"그 실행이 쓰는 행 어디에 있든"*으로, *"아래"*를
  *"위"*로 고쳤다. *"전처리 화면은 학습이 정한 종류를 그대로 말한다"*는 **특성 열(A-2)과 타깃
  열(V-A1)**로 나눠 적었다 — **§0의 1·2가 참이면 이 문장이 또 거짓이다.** `roadmap.md`의
  `0.26.6` 줄 끝에 네가 권한 한 마디를 넣었다.
