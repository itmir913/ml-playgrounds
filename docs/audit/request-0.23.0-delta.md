# `0.22.0`→`0.23.0` 델타 감사 요청서 — **배포를 걸기 전에 본다**

> 앞 라운드: `docs/audit/request-R36.md` · `report-R36.md`
>
> 공통 규칙은 `docs/workflow.md` §3의 **"감사 국면은 어떻게 도는가"**부터 **"감사가
> 되풀이해 잡은 병"**까지다. **먼저 읽어라.** 금지 목록(커밋·`push`·`tag`·`add` ·
> `npm run lint` · `git stash`·`git checkout .`·디렉터리 단위 되돌리기)과 등급(A/B/C),
> 돌연변이 절차, 보고서 서식이 거기 있다.
>
> `git status --short`가 더러운 것은 정상이다 — 병렬 세션이 같이 돈다.

## 0. 왜 이 감사가 있는가 — **한 번 잘못 나갔다**

**2026-09-21에 코드 소유자가 `0.23.0`을 태깅하고 배포했는데, 그 태그가 가리키는 커밋
(`65570e7`)은 CI가 빨갰다.** 배포 워크플로가 관문 셋 중 하나만 돌리고 있어서 초록으로
나갔고, 사용자가 **급히 `0.22.0`으로 롤백했다.** 지금 라이브는 `0.22.0`이다.

두 가지가 겹쳤다.

1. **코드 소유자가 관문을 반만 돌렸다** — `npm run ci`만 돌리고 `cd backend && uv run
   python scripts/ci.py`를 안 돌렸다. 깨진 것은 그쪽이 보는 **로케일 ↔ 백엔드 에러 코드
   계약**이었다(`FEATURE_NOT_NUMBER`가 프런트의 `SHARED_ERROR_CODES`에만 있고 백엔드
   `ErrorCode`에는 없었다).
2. **배포가 CI보다 관대했다** — `ci.yml`은 잡 셋, `deploy.yml`은 `npm run ci` 하나였다.
   결정문(`open-decisions.md` "10. 배포 패키징 — 남은 부분 (2경로는 결정됨)"의 넷째 항목)이 이 갈림을 *"대가는 알고 간다"*로 적어 두었는데,
   **알고 있던 것은 문서였지 워크플로가 아니었다.**

**그래서 이 감사가 답할 것은 하나다 — 이 델타를 배포해도 되는가.** 관문이 초록인 것은
이제 확인됐다(양쪽 다). 물어야 할 것은 **관문이 못 보는 것**이다.

## 2. 이 델타가 위험한 이유 — 되돌리기 어려운 것 셋

**이 셋이 이번 감사의 본체다.** 나머지는 부수적이다.

### 2.1 **전에 통과하던 프로젝트를 거절하게 만들었다**

`planRun`이 `FEATURE_NOT_NUMBER`로 막는다. **거절이 너무 넓으면 멀쩡한 수업이 막힌다.**

물어야 할 것:

- **군집** — `split.testIndices`가 빈 배열이라 안 걸리는가. 확인했나?
- **`recordedSplit`(재실행·점검)** — 이 문이 거기도 걸린다. 결정문은 *"옛 파일의 판정은
  '재현 안 됨'이 아니라 '다시 돌릴 수 없음'이다"*로 받아들였다. **그 결말이 교사 화면에서
  실제로 어떻게 보이는지는 아무도 안 쟀다** — `reproduceExperiment`가 `runExperiment`를
  `try` 없이 부르므로 대조가 통째로 죽는다.
- **뽑기(`nSamples`)가 켜졌을 때** 시험 몫이 무엇인지.
- **`provided`인데 `testDataset`이 `null`인 경로** — `testFromProvided`가 거짓이면
  `dataset`을 `split.testIndices`로 훑는다. 그 인덱스가 어느 표의 번호인가?
  (`mlpx-spec.md` §1.1이 *"서로 다른 정본을 가리키는 유일한 경우"*라고 적은 자리다.)
- **비용** — 이 검사는 `planRun`마다 (수치 열 × 시험 행) 파스를 돈다. 전처리 화면은
  설정이 바뀔 때마다 `planRun`을 부른다. **20,000행에서 재라.** `fitPreprocessor`가
  이미 훈련 행을 훑으므로 비율로는 작아야 하는데, **그건 내 추론이지 잰 값이 아니다.**

### 2.2 **올린 데이터를 묻지 않고 고쳐 쓴다**

`canonicalCell`이 `1,650`을 `1650`으로 바꿔 **정본에 적는다.** 정본은 무결성 해시의
대상이고(`mlpx-spec.md` §7) `.mlpx`에 들어가는 바로 그 바이트다.

```ts
const THOUSANDS_GROUPED = /^[+-]?\d{1,3}(?:,\d{3})+(?:\.\d+)?$/
export function canonicalCell(cell: string): string {
  const trimmed = cell.trim()
  return THOUSANDS_GROUPED.test(trimmed) ? trimmed.replaceAll(',', '') : cell
}
```

**여기가 Fable이 값할 자리다 — 재라.**

- **정규식을 전수로 찔러라.** 통과시키면 안 되는데 통과하는 입력, 통과해야 하는데 막히는
  입력. 전각 숫자·아라비아-인도 숫자·유니코드 공백·` `·부호 둘(`--1,650`)·
  선행 0(`0,123`)·`1,234,56`·소수부 여럿.
- **`trim()`이 정본을 바꾼다** — 통과하는 칸만 `trimmed`를 쓰고 나머지는 원본을 돌려준다.
  `"  1,650  "`는 공백이 사라지고 `"  150  "`는 안 사라진다. **의도인가? 같은 열의 두
  칸이 다른 대접을 받는다.**
- **왕복 무손실이 깨지지 않는가** — `tests/serialize.spec.ts`가 *"정본을 parseCsv에 다시
  넣으면 같은 격자"*를 강제한다. `canonicalGrid`가 그 앞에 끼었는데 **멱등인가?**
  (`canonicalCell(canonicalCell(x)) === canonicalCell(x)`)
- **머리글 줄도 바꾼다.** 열 이름이 `1,650`이면 `1650`이 된다. 세 문(학습 표·테스트
  표·예측 표)이 전부 같은 규칙을 지나므로 이름이 맞는다 — **정말 셋뿐인가?**
  `project/dataset.ts:225`·`:312`가 `toCanonicalCsv`를 다시 부르는데 그것들이 받는
  `imported.grid`가 이미 변환된 것인지 확인하라.
- **한국어 로케일 전제** — 결정문이 *"쉼표가 천 단위이고 소수점은 마침표다"*에 기댄다.
  **그 전제가 이 앱의 어느 코드로도 강제되지 않는다.** 유럽 CSV를 올린 학생이 있으면?
  (닿는 길이 없으면 "없다"고 적어라 — 그것도 답이다.)

### 2.3 **배포 관문을 통째로 갈아 끼웠다**

`gate.yml`(`workflow_call`)을 `ci.yml`과 `deploy.yml`이 부른다.

- **CI 경로는 초록이 확인됐다** (`35603772426`, 잡 셋 전부).
- **배포 경로는 한 번도 안 돌았다.** `pages: true`일 때 `upload-pages-artifact`가
  재사용 워크플로 안에서 실제로 뜨는지, `deploy` 잡이 `needs: gate`로 그 아티팩트를
  받는지 — **소스로만 판단해야 한다.** 권한(재사용 워크플로는 권한을 올릴 수 없다)과
  `inputs.pages` 조건이 맞는지 봐라.
- **닭과 달걀이다** — 배포를 돌려 봐야 확인되는데, 확인 전에는 배포를 안 한다.
  **그래서 이 항목은 "돌려 보라"가 아니라 "정적으로 읽어 틀릴 수 있는 자리를
  대라"다.**

## 3. 반드시 넣을 것 — **네가 만든 것이 아니라 우리가 만든 검사를 찔러라**

이 저장소에서 가장 값했던 요청 항목이다.

> **새로 들어온 검사 둘(`tests/plan-not-number.spec.ts` +220 · `tests/table-thousands.spec.ts`
> +112) 중 망가뜨려도 안 우는 자리를 지목하라.**

코드 소유자가 이미 심어 본 것은 넷이다 — 문을 끄면 아홉 중 다섯이 울고, V-1·V-2 각각의
가드를 끄면 하나씩 운다. **그것 말고.** 특히:

- `table-thousands.spec.ts`의 *"안 푸는 것"* 열하나가 **진짜 잣대인가.** 정규식을 넓히는
  방향(예: `{1,3}`을 `{1,4}`로)으로 바꿔도 통과하는가?
- `plan-not-number.spec.ts`의 픽스처가 **12행짜리 한 벌**이다. R36이 `neural.ts`에서
  *"행이 배치보다 적으면 그 갈래를 원리적으로 못 지나간다"*로 한 번 당했다. **같은
  모양이 여기 있는가?**

그리고 **처방을 실측하라** — 고칠 자리를 찾았으면 그 고침을 임시로 넣고 **원래
돌연변이가 그 상태에서 우는지까지** 보라. 이 저장소에서 말이 되는 처방 둘이 그대로는
안 물었다.

   부딪힌다"*고 적고 등급을 **B**로 두어라.
5. **문서 2,700줄은 대상이 아니다.** 근거로만 읽어라.

## 7. 보고서에 넣을 것

## 8. 규모와 명령

- 관문은 **둘**이다. **둘 다 돌려라** — 이번 사고가 한쪽만 돌려서 났다.
  - `cd frontend && npm run ci` — 176파일 · 3,610 통과 · 3 건너뜀 (약 100초, `build`까지 약 3분)
  - `cd backend && uv run python scripts/ci.py` — 33 통과 (약 2초)
- **출력은 파이프로 자르지 말고 파일로 받아라** — `> ci.log 2>&1` 뒤에 `tail`·`grep`.
- **관문이 빨가면 실패한 스펙만 격리해서 다시 돌려라.** 판정 기준은 *"타임아웃이냐"*가
  아니라 ***"격리하면 통과하냐"***다. 이 기계는 부하에서 가짜 빨강을 낸다.
- **`--testTimeout`이 안 닿는 스펙이 둘 있다**(소스에 30초가 박혀 있다):
  `tests/reopenable.spec.ts:120` · `tests/sklearn-parity.spec.ts:497`.
- 돌연변이 카탈로그는 `cd frontend && npm run mutate`다(90항목 · 약 450초, 관문 밖).
  마지막 실행은 **욺 74 · 조용 16, 기대와 전부 일치**.
- sklearn을 돌리는 문은 `uv run --project backend python -c "..."`다(sklearn 1.9.1 ·
  pandas 3.0.6). **픽스처를 다시 만들지 마라** — `--check` 없는 실행은 `expected.json`을
  바꾼다.
