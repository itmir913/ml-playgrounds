## 0. 이번 방법은 **전수 세기**다

`plan-R35-R40.md` §1이 정한 축이다. **모집단이 닫히는 부류는 세서 0을 확인하고 닫는다.**
그런데 세는 방식에 조건이 하나 붙는다 — **이 저장소가 같은 자리에서 세 번 넘어졌다.**

> **세는 것이 실물이어야 한다. 표기가 아니라.**
> `grep`으로 이름을 세면 `unzipAsync` 안의 `zipAsync`를 못 보고, 스펙이 그 모듈을
> **임포트했다는 사실**은 그 줄을 **실행했다는 뜻이 아니다.** 등록부는 **배열을 읽어**
> 세고, 문은 **불러 보고** 세고, 상한은 **값을 넘겨** 센다.

**R33·R34가 이 방법으로 A를 하나 더 잡았고**(`^export function with\w+\(`를 세던 정규식이
두 표기를 못 봤다), R35가 거기에 절반을 보탰다 — §0.2.

**이 방법이 못 보는 것**은 **화면까지의 이음매**다. 등록부에 항목이 있고 그 항목을 지나가는
스펙이 있어도, **화면이 그 항목을 띄우는지는 다른 라운드(R38·R39)의 몫**이다. 이 슬라이스에서
그 냄새가 나면 지적하지 말고 §6의 "다음 주기"에 한 줄로 적어라.

### 0.1 이 라운드도 **부채 지도 라운드다**

- **네가 고치는 것은 없다** — 감사자는 찾기만 한다. **코드 소유자가 이 라운드에서 닫는 것은
  A뿐이고**, B·C는 `map-2026-09-21.md` §3의 표에 한 줄씩 남는다. **등급이 곧 일정이다.**
- **지적마다 칸을 하나 더 적는다** — `workflow.md` §3의 서식(자리 `경로:줄` · 주장 · 재현 ·
  처방 · 같은 병의 이웃 수)에 이것을 붙여라:

  > **이 자리를 무는 검사가 있는가 / 없으면 세울 수 있는가 / 세울 수 없으면 왜.**

  *"세울 수 없다"*의 이유는 셋 중 하나여야 한다 — **실기기만 답한다** · **비결정적이라
  순서를 강제해야 한다** · **화면 안에 남은 판정이라 밖으로 빼야 한다**(`architecture.md` §8).
  셋 중 아무것도 아니면 *"세울 수 있는데 안 세운 것"*이고, 그렇게 적어라.
- **"나가도 되는가"를 적지 마라.** 이 라운드는 그 물음에 답하지 않는다.

### 0.2 R35가 물려주는 것 — **읽고 시작하라**

`plan-R35-R40.md` §3이 *"R35의 고침은 R36 요청서에 명시적으로 옮겨 적는다"*고 정했다.
**옮길 고침이 없다** — R35는 A급이 0이라 **소스를 한 줄도 안 고쳤다.** 대신 셋이 넘어온다.

1. **카탈로그가 71 → 80이 됐다**(`frontend/tools/mutants.json`). 새 아홉은 전부
   `pyodide-sklearn.ts`다. **이 슬라이스와 안 겹친다** — 네가 심을 자리와 무관하다.
2. **지도 §2.2의 한 줄이 틀려 있었고 고쳤다**(`ml/models/*`가 *"전부 100%"*가 아니라
   `svm.ts`만 33/34였다). **지도의 다른 줄도 같은 폭으로 틀릴 수 있다** — §1.1의 각주가 그
   경고다. **네 슬라이스의 수치를 지도에서 그대로 베끼지 말고 필요하면 다시 재라.**
3. **R35의 교훈이 네 방법을 직접 바꾼다.** 아래가 그것이다.

> **"불린다"는 "재어진다"가 아니다.**
> R35는 커버리지가 **실행된다고 말하는** 배선 둘에 돌연변이를 심어 **둘 다 절반씩만
> 물리는 것**을 봤다(`report-R35.md` §1 B-1의 C1·C3). 나무는 클래스 순서를 잡고 폭을
> 놓치고, 선형은 폭을 잡고 클래스 순서를 놓친다.
>
> **그러므로 네가 세는 칸은 "지나가는 스펙이 있는가"가 아니라 "그 자리를 뭉개면 우는가"다.**
> 커버리지 97.1%인 슬라이스에서 전자는 거의 전부 "예"가 나오고, **그 표는 아무것도 증명하지
> 않는다.**

## 3. 첫 돌연변이 후보 — 지도가 고른 셋

**세기가 본체이고 돌연변이는 그 세기를 검증하는 도구다.** 커버리지 0인 자리에는 심지 마라 —
조용한 것이 자명하다.

### 3.1 `preprocess.ts`의 결측 채우기 둘 — 무실행

**자리** `ml/preprocess.ts:144`(`drop`) · `:154`(`mostFrequent`).

여섯 중 둘이 어느 스펙에서도 실행되지 않는다. **`mostFrequent`의 수치 갈래가 특히
조용히 틀릴 모양이다:**

```ts
mostFrequent: (numbers, strings, kind) =>
  kind === 'numeric'
    ? Number(mostFrequent(numbers.map((value) => String(value))))
    : mostFrequent(strings),
```

**수를 문자열로 바꿔 최빈을 고르고 다시 수로 되돌린다.** 물을 것 셋 — 동점이면 누가
이기는가(그리고 sklearn `SimpleImputer(strategy='most_frequent')`는 누구를 고르는가),
`String(0.1 + 0.2)`처럼 표현이 갈리는 수가 같은 값으로 묶이는가, **`drop`이 `''`를
돌려주는 것이 맞는가**(위 주석은 *"여기까지 왔으면 빈 칸이 없다"*고 단정한다 — **그 단정을
재라**).

### 3.2 워커가 죽는 갈래 — 전부 무실행

**자리** `ml/worker/pool.ts:66`(`onError`)·`:70`(`onMessageError`) ·
`ml/worker/client.ts:166`·`:265–266`.

```ts
const onError = (event: ErrorEvent): void => { cleanup(); reject(new Error(event.message || 'compute worker failed')) }
const onMessageError = (): void => { cleanup(); reject(new Error('compute worker reply could not be cloned')) }
```

**`cleanup()`이 안 불리면 리스너가 샌다.** 셋 다 심어 봐라 — `cleanup()` 제거 · `reject`를
`resolve`로 · 오류 메시지 바꾸기.

> **이 저장소는 여기서 한 번 다쳤다.** *"워커 경계가 프로토타입을 벗긴다"* — 가짜 풀이 진짜
> 경계보다 관대해서 **검사 전부 초록인데 브라우저에서 죽었다.** 그러니 **가짜 워커로만
> 재지 마라.** `tests/compute-pools.spec.ts`가 진짜 경계를 지나간다고 적고 있으니, **그
> 스펙이 정말 진짜 경계인지**부터 확인하라.

### 3.3 `experiment.ts:325` — 학생이 읽는 사유를 고르는 자리

```ts
const relevant = option.runtimes.find(
  (candidate) => candidate.reason && candidate.reason !== 'ALGORITHM_NOT_AVAILABLE_HERE',
)
return relevant?.reason ?? 'ALGORITHM_NOT_AVAILABLE_HERE'
```

**무실행이다.** 화면이 학생에게 *"왜 이 알고리즘을 여기서 못 쓰는지"*를 말하는 문장이 여기서
정해진다. `find`가 **첫 번째**를 고르는데 **그 순서가 `RUNTIMES`의 배열 순서**다 — 순서를
바꾸면 학생이 다른 이유를 듣는다. 그것이 의도인지 재라.

## 4. 이미 아는 부채

**단서 하나**: **내가 틀리게 알고 있으면 그건 새 항목이다.** 아래가 실제와 다르면 지적으로
올려라 — R25에서 이 단서가 하나를 건졌다.

**이 슬라이스에서 아직 안 닫힌 것 넷** (R34 `report-R34.md` §7이 남긴 것이고 **전부 아직
코드에 있다** — 2026-09-21에 확인했다):

- **`ml/metrics.ts:158`** — `r2`의 `total`이 0은 아닌데 **극히 작을 때** `residual / total`이
  `Infinity`가 된다. **CSV 글자로 그 크기를 만들 수 있는지 아무도 안 쟀다.**
- **`ml/metrics.ts:342`** — *"`filled` 가드가 걸러낸다"*는 주석은 **R34가 이미 고쳤다**(전수일
  때만 참이라고 적혀 있다). **주석은 고쳐졌고 코드가 그대로다** — 표본이 켜진 실루엣이
  정말 맞는 값을 내는지는 안 쟀다.
- **`ml/preprocess.ts:477`** — `toNumber(String(filled)) ?? 0`. 예측의 문이 앞에서 막으므로
  오늘은 안 닿지만 **`0`을 고르는 원시 연산 자체는 살아 있다.**
- **`ml/metrics.ts:243`** — `silhouetteSampleSize`가 **열 수로** 표본을 정하므로 열이 많은
  프로젝트에서는 실루엣이 표본값이다. **화면이 그 사실을 말하는지는 R38의 몫이다.**
